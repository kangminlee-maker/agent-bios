# Shared lifecycle hooks: resolution

The seven hook-interoperability findings are addressed in the working tree. Both
session adapters consume the same authored Python hook and event/matcher binding.
Codex support is no longer coupled to Claude native-agent/plugin support.

## Scope and evidence

The starting HEAD has **243 tracked text files with 1,942 hook-related lines**.
The before/after locations are in
`2026-09-11T1204--79b4adb--baseline-inventory.json`. The earlier 11:39 inventory
was captured while edits were in progress, rather than from the starting tree.
The scan includes live code, payload, translations, tests, diagrams/ontology,
historical decisions/design records, and research fixtures. Historical records
keep their original text; Git/shell hooks and transport-header names are not
mistaken for host lifecycle APIs.

Current contracts were checked against [Codex Hooks](https://learn.chatgpt.com/docs/hooks)

The shipped reminder now stays silent if called with an event other than
PreToolUse. Editing an event binding does not translate its Python body into a
new event's output contract. Final paths are supplied to the compiler before
shell/Python quoting, so a dry preview and a persisted snapshot agree even with
spaces, quotes, dollar signs and backticks in the private-store path.

## Runtime proof and retained differences

A real Codex app-server loads the generated snapshot configuration and starts a
turn against a **loopback test transport**, which records a request and returns a
terminal error. No external model or service is used. Before trust, neither the
hook marker nor its injected context appears. After the test fixture records the
host-reported hash of that exact test-owned definition in its scratch native
home, the hook runs and its context appears in the request. Production code does
not write trust or add the hook-trust bypass flag.

This verifies actual SessionStart execution/context delivery, beyond config
parsing. The shared PreToolUse reminder also has matching, nonmatching and
malformed-input subprocess controls on both emitted carriers. The public Codex
launcher dry-run adds one selected hook in Solo and none in Vanilla; native hook
disablement remains unchanged.

The retained differences are specific contracts:

- Event availability and event-specific decision semantics differ by host.
- Codex keeps native enablement and /hooks trust review. Discovery is not execution.
- Claude plugins carry authored native-agent frontmatter. Projecting those agents
  to Codex still requires model/tool-restriction translation; this is independent
  of hook delivery and is not implemented by this change.
- Legacy global registration/removal remains Claude compatibility machinery.
  The default private installer registers no global hooks on either host.
- Reviewer isolation can deliberately withhold ambient hooks. Learning records,
  endpoint transport, Git hooks and zsh interception have different purposes.
