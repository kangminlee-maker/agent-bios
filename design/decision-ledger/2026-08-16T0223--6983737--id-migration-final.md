# Decision ids, second pass — the digest binds every field, and the map is final

The first pass (this morning, PR #32) derived the id from the instant, session and summary. Review of that PR pointed out that a row's `closed`, `why`, `kind`, `reverses_if` or provenance stamps could then be rewritten under an id that still checked out — and the ledger exists to keep exactly those. The digest now covers every field of the record but the id itself, so every id moved once more. The ids of the first pass were never referenced by anything but the superseded map and three active files, all updated here; this table maps the **original positional ids** straight to the **final** ones and is what a pre-2026-08-16 reference resolves through.

The one record made between the two passes (the id decision itself, `D-20260816-a34213` in the first scheme) is `D-20260816-04708b` now.
