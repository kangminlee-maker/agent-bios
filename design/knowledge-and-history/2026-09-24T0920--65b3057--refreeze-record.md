## The drift detector

`gates/workenv/binding-drift.py` compares the bindings a freeze recorded with what
`cases.py --bindings` emits from the tree, and names which part of each moved profile moved:
the case set, the profile itself, the adapter, or the fixtures. It requires the run evidence
as an argument rather than defaulting, because the artifact lives outside the repository and a
tool reporting "no drift" because it found no freeze would be worse than no tool. It exits 0
either way — a drift is either a regression or shared work the freeze has not caught up with,
and this repo blocks only on what is decidable.

Nine controls in `--self-test`, the first of them positive: an unmoved pair must report no
drift, or every other control would pass for the wrong reason. Two reverts of `compare()` were
each caught by it.

**It also found a defect in the packet, which is recorded here because the tooling caused it.**

which does not exist: the dispatcher builds that path from the plan's stamp, and the evaluator
keeps its own because its bytes did not change. The reviewer said so, imported the file the plan

own argument for the subject call, and the packet text still does not; a bundle with mixed stamps
is normal here, so the packet builder should take it too.

Its sixteenth check states its own boundary plainly: the source worktree was not supplied, so
registry emission, subject resolution, source-derived fingerprints, git identity, authorship,
historical environment and the audit's clean-tree provenance were not independently
