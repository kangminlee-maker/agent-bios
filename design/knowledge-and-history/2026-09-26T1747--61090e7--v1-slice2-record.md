# V1, second slice: sources — homes, revisions, reading back, and the person's checkout

V1 is written in five slices. This is the second: the code that registers a source, commits its
revisions, reads them back, binds the person's checkout and observes what they select in it. It is
used here, tested, and run against every scenario. V1 is not complete: four V1 cases now pass, and
the other eighteen block by name at a module not written yet.

## What was written

| Module | Serves | What it keeps |
| --- | --- | --- |
| `workenv/sources/homes.py` | `source.home.register` | each source's scope, role, home and current revision |
| `workenv/sources/revisions.py` | `source.revision.commit` | revisions, and each one's bundle on disk |
| `workenv/sources/reading.py` | `reference.resolve` | nothing; it reads |
| `workenv/sources/checkouts.py` | `repository.bind`, `source.observe` | each bound repository's record and checkout directory |
| `workenv/storage.py` | layout 2; bundle publication | three new tables, brought in by an upgrade in one transaction |
| `workenv/journal.py` | the prepare step; `stale_base` | the head each receipt moved its target to |

**Homes.** The first registration expects no head. Registering again names the head it expects
and may change the home's conditions, the evidence it rests on and the Markdown view it derives.
Where the source is authored (its mode, repository, document root or package), its scope, role and
accepting authority are its identity; changing any of them is `source_home_conflict`
(`D-20260926-a29023`). A repository-authored home must name the binding this installation holds
for its repository, or it is `binding_unverified`. A source's head is the digest of the record its
last commit stored: the home, or the revision's manifest.

**Revisions.** A commit stores the manifest with the `produced_at` the runtime owns. Its bytes are
published first, as the bundle `objects/<revision>/` holding `manifest.json` and each member under
`members/`, in the storage binding's order: stage, sync, read back and hash again, rename, sync the
directory, passing B03's five publication points. The journal runs this as the entry's prepare
step, outside the unit of work, and the entry checks the head again inside the unit
(`D-20260926-df7bc0`). Member bytes come from what the request supplies, and for a
repository-authored source from the bound checkout. Bytes of another size or digest are
`object_digest_mismatch` at that member; a member with no bytes at hand is kept by its hash. A
signature is optional, and each one present must be the actor's own standing key over the
payload, in the `agent-bios/source_manifest` namespace (`D-20260926-b9227e`). A source published
by a package takes no revision here: `publisher_bytes_modified`.

**Reading back.** `reference.resolve` answers the revision's manifest, the source's home at the
head it read, and a named member's bytes as the bundle holds them. A revision not held for that
source, another scope or role, a member the manifest does not list, or bundle bytes that are not
the member's, is `ref_unavailable` with no recovery. It reaches no provider, so its provider effect
is `not_applicable` (`D-20260926-3f6712`).

**The checkout.** `source.observe` reads, under each selected working-tree root, the files git
sees: committed, modified or untracked, never an ignored one. It reads a symbolic link as the
path it holds. The reads are ordered by root, then tracked files before untracked ones, each by
path, as git lists them (`D-20260926-67f38f`). A required root with no file is `ref_unavailable`
at `/roots/<i>`. Observing changes nothing; it keeps the selection it read by digest.
`repository.bind` states the checkout's `origin`, branch and HEAD. As its working bytes it states
the last complete observation of that repository's checkout, while the working tree still reads the
same; otherwise it states none (`D-20260926-bbcc1c`). Every git process runs with the variables
that would point it at another repository removed, so a runtime started from a git hook still
reads the person's checkout.

**Shipping.** The five `workenv/sources` files ship in `package.json` `files[]`. The ontology's
derived count of shipped paths moves from 107 to 112.

## Open — a decision for the owner

**`source.revision.admit` through `author_here` has no manifest.** Its request carries only a
`source_request` (role, destination, route), yet the scenarios expect it to commit a specific
manifest, such as `rules/review.md`. Four V1 cases block on it: CMP-PINS, DEL-PERSONAL,
N09-C07-POS and N15-C11-POS. There are 31 admit steps across 16 scenarios. The options:

- **A:** `author_here_route` gains a required `manifest_digest`, and the request carries the
  manifest. Its bytes come as a commit's do.
- **B:** authoring leaves admit and becomes register then commit, which rewrites the scenarios
  more widely.
- **C:** the contract stays, and those four cases cannot pass in V1.

A and B change a contract, which the P01 re-freeze takes.
