# Product presentation versus authoring criteria

The user's three comprehension questions were being rendered as explanatory
panels, repeated normal-state caveats and a compulsory preparation/review sequence.
The root cause was treating a design criterion as a screen specification.

The successor makes the boundary explicit in the SSOT and development specification:
designers must establish comprehension, while the product names actual objects,
values and actions. The revised [wireframes](2026-09-15T0751--35c75ca--tui-entry-wireframes.md)
and [prototype](2026-09-15T0751--35c75ca--tui-entry-prototype.html) replace the generic
effect panel with environment and execution settings, followed by a concrete start
button. Routine navigation no longer narrates itself.

A normal start performs current owner checks within that explicit action. Conditions
that prevent it disclose a specific reason/remedy. Material permissions and added
model calls remain beside their settings. Removing a compulsory review page does
not remove validation or grant additional authority. A selection change invalidates
internal assessment; an unknown request retains its own original settings and ID.

The prototype indication appears once outside the depicted app. Inside, buttons
use normal product language. This remains a fictional browser projection: its
result states do not establish actual tool execution, delivery or model use.
The existing product TUI was not edited.

The earlier correction remains in force: observed repository/checkpoint information
does not identify the current task. No goal/target form was reintroduced, and task
support remains unassessed until an actual host request exists. That internal state
need not become a permanent first-screen disclaimer.

## Scoped verification

- The browser projection passes 22 named interaction/layout assertions and 256
  scenario/width/layout/appearance combinations without horizontal control clipping.
- Normal start reaches its result through one explicit button. Focus does not start
  or select; changed selection invalidates old assessment and changes consumed inputs.
- Required missing/denied material blocks start, navigation does not repair it,
  explicit recovery can restore readiness, and locked metadata remains hidden.
- Unknown-result inspection preserves the same request and original configuration
  after the current settings change. Offline status retains its observation date.
- The wide initial projection is 508 pixels high and includes the start action.
  These pixel measurements do not establish real terminal cell layout or IME support.
- The unchanged evidence-evaluator control suite is rerun against the successor
  bundle; its results are recorded in the [evidence file](2026-09-15T0751--35c75ca--tui-entry-evidence.json).

N16 now specifies direct startup, owner revalidation and targeted failure behavior,
not panel titles or a fixed number of screens. N26 still requires actual first-user
comprehension and actual Korean terminal observations. The P11 implementation owner
and existing dependency graph remain; no new scheduler, UI state authority or
acceptance milestone was introduced.

Previous snapshots and their test evidence are preserved. This turn changes the
design bundle and its scoped prototype, not the installed product or user state.
It does not claim the full repository parity suite or human usability was validated.
