## The shape every later contract follows

1. **One sealed request, one result** (`D-20260920-ba2e94`). Every protected operation of every
   contract is a C03 `operation_request` answered by a C03 `operation_result`. The payload is a
   separate record named by `payload_kind` and `payload_digest`, and its shape belongs to the
   contract that owns it. A later contract adds payload and stored record kinds; it does not add
   an envelope.
2. **The request's stored digest is its identity.** The runtime adds no field to a request. The
   same `request_id` with other bytes is `request_id_conflict`. A result names the request by id
   and digest, and the examples are held to that: a result example answers a request example
   that exists.
3. **A refusal is a gap code a result states** (`D-20260920-e25200`). A contract module owns its
   codes; the one error table holds them; an accepted result example states each in
   `material_gaps`. A reader's code is still exercised by a refused byte example, and asking the
   reader for a gap code fails.
4. **A record says what it is.** `kind` is a name and `schema` an integer version, both fixed
   constants in the record's schema document, which is how `records.load` finds the schema. The
   document is named `<contract>_<kind>`.
5. **The runtime's writing is marked in the schema.** A property the runtime writes carries
   `x-runtime-owned`; a record the runtime writes whole — a result, a receipt, a state — carries
   it on the document's root. Every marked place needs a submission refused for carrying it.
6. **One name, one meaning** (`D-20260920-fdc411`). `$ref` stays inside one document so that a
   stock validator reads each schema with no setup. Shared definitions (`scope`, `base`, `gap`,
   the ids, `digest`, `instant`) are therefore copies, and two documents that define one name
   differently fail.
7. **What has no field cannot be sent.** A display name or an e-mail address in the place of an
   id, a token in a request, a timestamp the runtime would add to a sealed request: none has a
   property, and the closed schemas refuse each as `unknown_field`. The examples state these
   cases by name.

Spellings (`D-20260920-eb508f`): an id is a three-letter type prefix and 32 lowercase hex digits;
a digest is 64 lowercase hex digits of sha256 over stored bytes; an instant is a UTC second as
text. The modules and schema documents are the owner of every other spelling; this record does
not restate them.

  illustrate the pattern. The closed list of operations is U10's and U11's.
- Whether `action` should carry `local_profile` beside the grant actions, and whether one typed
  `target.resource_id` fits every resource, are open until C07 to C11 are written against them.
