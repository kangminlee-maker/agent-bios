## What the fourth slice has built

- **The owner, which knows no host** (`workenv/delivery.py`, `workenv/roles.py`): links,
  delivery attempts, observation and session activation.
- **One adapter per host, stated as data** (`workenv/hosts/claude_code.py`, `codex.py`): each
  declares the host events that reach the four recipients C11 names (new, current, child,
  rehydrated), where the session id is, and how the host takes context.
- **The support rule.** A route is supported only where the adapter declares it and the latest
  real probe of that recipient's delivery on the host's name and version worked (the owner's
  choice A). A new host version is unsupported until probed; this happened for real when Codex
  updated itself from 0.156.1 to 0.157.1.
- **`capability.probe`** (`workenv/hosts/probes.py`) runs the installed host through its adapter.
  `workenv/hosts/hook.py` is the command the host runs, the same bytes on every run. The hook
  hands the recipient a random code with the instruction to give it when asked, and the probe asks
  for it (`D-20260927-f05a86`: Codex's model will not repeat a developer message).
- **Every run gives the host every declared route's hook**, one group per route in declaration
  order (`Adapter.groups`, `D-20260927-f61065`). Codex trusts a hook by its place, so the places
  must not move.

## How each host is driven (details a new session would otherwise re-learn)

- **Claude Code 2.1.283** (`~/.local/bin/claude`). A probe runs `claude -p --plugin-dir <a
  plugin of the probe's own> --setting-sources "" --output-format json`. New, current and child
  probes add `--no-session-persistence`. A child is asked for through the session's subagent tool.
  A rehydrated session is `--session-id S "Reply OK."` → `--resume S "/compact"` →
  `--resume S <question>`. The person's settings are neither read nor changed. The four probes
  take about 45 s and cost about $1 together.
- **Codex 0.157.1** (`/opt/homebrew/bin/codex`). Every probe goes through the app server
  (`codex app-server --stdio`): `initialize` → `hooks/list` (recorded as the host configuration,
  the person's own hooks included) → `thread/start` (ephemeral, read-only, approval never) →
  `turn/start`. For a rehydrated session the probe first runs one turn, then
  `thread/compact/start`, and waits for `turn/completed`. `codex exec` is not used: it cannot
  compact, and on an ephemeral run it cannot start a child ("collab spawn failed: no thread with
  id").
- **Codex hook trust** is the person's, never ours (`D-20260927-d1cb86`).
  - Codex keeps one trusted hash per place `/<session-flags>/config.toml:<event>:<group>:<handler>`
    in `~/.codex/config.toml` `[hooks.state]`. The four places are trusted now:
    `session_start:0:0` (startup), `session_start:1:0` (compact), `user_prompt_submit:0:0` and
    `subagent_start:0:0`.
  - The hash covers the command line, not the file's bytes. So a later edit to `hook.py` runs
    without review.
  - The command line is `<sys.executable> <worktree>/workenv/hosts/hook.py codex`. Here that is
    `/opt/homebrew/opt/python@3.14/bin/python3.14 …`. **Run the probes with that same
    interpreter**: another interpreter, another checkout path or any change to a hook group
    (matcher, order, an added `additionalContextLimit`) is a new hash, and Codex silently stops
    running the hook until the person reviews it again.
  - `codex-hooks-review-2.sh` opens Codex with exactly the trusted flags.
- The ChatGPT desktop app runs its own `codex app-server`; do not kill it.
