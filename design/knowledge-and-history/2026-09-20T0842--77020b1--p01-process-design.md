## 2. Correction: packaging is not deferred to P18

The 02:10 record said `workenv/` stays out of `package.json` `files[]` under one pending-package
entry until P18. P18 owns no path, its effect is a candidate build, the evaluator refuses a
non-empty `product_changes` for it, and the spec says packaging cannot fix shipped source or
manifest code incidentally. The binding is replaced:

- every implementation node that lands shipped runtime files adds their `files[]` entries in
  the same integrated change;
- `gates/check-package.sh`'s boundary leg asserts that each tracked file under `workenv/` is
  either shipped or declared author-side by name, with a planted-violation control;
- the pending-package state is dropped.

## 4. Correction: how the designs were produced

The 02:10 record says the second designer, a `claude-fable-5-1` subagent, "read only the
packet". That is true of its tool calls and incomplete: the subagent was started inside the
checkout, so the repository's working rules were in its context from the first token. Its
answers on repository fit were therefore not blind and are weighted as the coordinator's own
view, not as a second opinion. No binding rested on that draft alone.

For the successor-bundle design the second designer ran outside the checkout with project
settings only. That excludes the repository's rules by construction. The user-level
instruction file still loads under an OAuth login, and did: the draft followed its language
preference. The coordinator's isolation probe — asking a small model whether it could see
instruction text — had answered "none". A model's self-report is not an instrument.
