# V1, third slice: preparation — the nine positions and a composed environment

V1 is written in five slices. This is the third: the code that keeps each scope's collection for
each role and composes a preparation from them. It is used here, tested, and run against every
scenario. V1 is not complete: nine V1 cases now pass, up from four; twelve block by name at a
module not written yet; one, CMP-QUALIFIED, fails and waits on an owner decision (see Open).

## What was written

| Module | Serves | What it keeps |
| --- | --- | --- |
| `workenv/preparation.py` | `collection.change`, `collection.read`, `preparation.compose` | each collection's position; each preparation, whole, by digest |
| `workenv/storage.py` | layout 4 | `collections` with one collection per position, and `preparations` |
| `workenv/sources/checkouts.py` | what a checkout shows now; the repository last bound from it | nothing new |

**Collections.** Each repository, person and Team keeps one collection per role, and a collection
keeps the position it was created for. The first change expects no head and later ones name it
(`stale_base`). Moving a collection, or a second collection for a held position, is
`request_mismatch` at `/position`; an owner other than the position's scope is `request_mismatch`
at `/owner`. A listed draft must be a carried `source_manifest` of the draft's source; it and its
bytes are staged and nothing accepts them.

**Composition** (`D-20260926-851b43`). Role by role, each scope's position in the applied order:
repository, personal, Team, unless the request states an order naming exactly the basis's scopes.
A switched-off position contributes nothing; an empty one is named `empty`.

- **Units.** An entry's units take the layer of its position's scope, whoever owns the source. An
  entry declaring no unit brings every member as unkeyed prose, and so does a source the basis
  pins. A source, revision or member not held is `selection_unresolved` at its position. A
  source of another role is `role_promotion_refused` in an Instructions position and
  `selection_unresolved` elsewhere.
- **Competition.** Units of one concern in one role compete: the first layer wins and the others
  are `shadowed_by` it. Within that layer only a precedence lower than every other's wins;
  otherwise the concern is `unresolved` and only the first layer's units state
  `same_layer_unordered`. A switched-off entry's units are `disabled` and keep their concern.
- **Other rules.** Only a winning unit's needs name `needed_by`. Memory fixes each source's
  frontier once, at its head. Units are listed role, then layer, then as stated.
- **Storage.** The preparation is stored whole, answers `private_state_written`, names no receipt
  and moves no head.

**Bodies** (`D-20260926-3b2d7d`). A unit's body is its member's bytes in the pinned revision's
bundle, whoever authors the source. A winning or layered unit whose bytes the bundle does not hold
is `role_body_unavailable`, and other bytes are `object_digest_mismatch`. This slice first read a
repository-authored body from the working tree. Direct use and N09-C07-NEG showed that an
uncommitted edit then made the accepted revision undeliverable, and the SSOT's S08 table gives
immutable snapshots as the exact reading representation. The working tree is reported through
`observed` instead.

**The checkout** (`D-20260926-b84190`). Where a repository was bound from the working tree the
process runs in, the preparation records the last such binding's repository as it reads now. That
is its origin (else its directory), branch and HEAD, plus working bytes only where a complete
observation still reads the same. Otherwise it records the directory alone. Working bytes the
binding claimed that moved are `working_bytes_moved`.

**The recipient.** The recipient is the request's work scope, else the first basis scope. A named
link must be held here (`recipient_link_unknown`), and gives the recipient's isolation; without a
link the recipient is `proven_fresh`. A session start on a named link also returns a
`session_routing` that is `selected_only`: the always surface is unchanged and native files are
preserved.

**Shipping.** `workenv/preparation.py` ships in `package.json` `files[]`; the ontology's derived
count of shipped paths moves from 112 to 113.

## Open — a decision for the owner

**CMP-QUALIFIED, a V1 case, cannot pass in V1.**

- **Rights.** It sets a source's rights with `source.rights.set`, which V5 serves.
- **Two codes.** It states the refused unit two ways: `source_not_authorized` in the result and
  `source_right_not_overridable` in the preparation.
- **Bodies.** It expects an unaccepted edit of `rules/deploy.md` to be `object_digest_mismatch` at
  composition, which `D-20260926-3b2d7d` does not give.
- **Order.** Its unit order is not yet aligned.

The options:

- **A (default):** move it to V5, and align it there: one code for the rights refusal, and the
  deploy unit's expectation under the snapshot rule.
- **B:** keep it at V1 and give it a rights double until V5, which puts a stand-in for V5's code
  into V1's acceptance.
- **C:** keep it as stated and return to reading repository-authored bodies from the working
  tree, which contradicts the SSOT's S08 and N09-C07-NEG.
