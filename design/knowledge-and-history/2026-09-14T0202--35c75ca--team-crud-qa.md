## Iteration and measurement limits

The prototype was corrected to distinguish local forgetting from re-enrollment,
to offer completion of a pending existing-Team connection, to bind founding
acceptance to its proposal version, and to display terminal connection state.
Final-source checks covered connection/closed-network/founding failure cases,
governance and role updates, founding re-acceptance, and narrow-screen creation/
update. Earlier CRUD and handoff checks preceded these isolated corrections.

One assertion initially searched for a footer message in the main content. It
was corrected to assert the visible overview's zero-environment state; this was
an assertion target error, not evidence of a failed founding transition.

The fixture has no real provider, cryptographic identity, key custody, immutable
approval store, P2P transfer, filesystem deletion, GitHub connection, invitation
delivery or agent execution. Its in-memory flags and role checks are not a
security boundary. An uncertain operation carries a precomputed fixture effect
revealed by receipt recovery, not an independently running server transaction.

The fixture assumes named actors are distinct verified humans, the nominated
authority device is ready for handoff, and the closure plan's source/custody
dispositions are valid. It cannot prove those assumptions. Displayed peer
counts describe fictional control-data retention. Partial cleanup reports
fixture state, not remote erasure. Local forgetting does not perform deletion
of the prototype's in-memory fixture database.

The creation wizard uses a fixture-only numeric planning range and a small
repository picker; those are not universal runtime policy limits or an actual
account repository inventory. Individual grant expiry, all source-specific
conditions, unavailable external dependencies and two-client races require
real provider tests.

## Design coverage versus executable coverage

The [main design](2026-09-14T0132--35c75ca--team-crud-and-creation-design.md)
and [scenario matrix](2026-09-14T0135--35c75ca--team-lifecycle-scenarios.md)

Team copying, repository provisioning, all purge outcomes and the first
environment's creation/adoption are not implemented in this fragment. Their
fields, authority boundaries and success/failure contracts are specified; they
are not deferred from design scope.

All production mutation routes require authority-side checks, request-bound
receipts, durable recovery and supported retention/identity evidence. Native
controls and preserved focus help keyboard use but do not constitute a complete
screen-reader/accessibility certification. Optional host design controls were
not exercised by the standalone run.

No shipped runtime source changed for this Team CRUD design. No actual Team,
repository or message was created or deleted. The full product parity suite
was not rerun for design/prototype artifacts.
