# V1, fourth slice, second increment: every route qualified on both hosts

[The 15:36 record](2026-09-27T1536--c0f0291--v1-slice4-codex-qualified-record.md) left two
Codex routes unsupported: a child, because what Codex's `SubagentStart` output takes had not been
shown, and a rehydrated session, because `codex exec` does not compact. The owner asked for both
to be checked against Codex's documentation and its binary. Both work. Everything else in the
14:08 and 15:36 records stands.

## What the documentation, the binary and the runs showed

| Question | Where it was answered | Answer |
| --- | --- | --- |
| What does a `SubagentStart` hook's output take? | Codex's source (`hooks/src/events/session_start.rs`: "`SubagentStart` stays context-injection-only") and the `subagent-start.command.output` schema embedded in the 0.157.1 binary | `hookSpecificOutput.additionalContext` with `hookEventName` `SubagentStart`, the output the adapter already writes |
| Does Codex start a child without a person? | A run through the app server | Yes: `subAgentActivity` started, the child answered. `codex exec --ephemeral` cannot: "collab spawn failed: no thread with id" |
| Can a conversation be compacted without a person? | The app-server protocol generated by the 0.157.1 binary, and a run | Yes: `thread/compact/start` compacts an ephemeral conversation. On the next turn `SessionStart` runs again |
| Does the compacted session read what the hook hands it? | A run with the hooks trusted | Yes: it gave the code, and NONE when the hook handed nothing |

The first try of the child route answered NONE although Codex ran the `SubagentStart` hook. The
hook answers only a route its host's adapter declares, and the Codex adapter declared no child
route. Declaring it (`D-20260927-b27667`) made the child give the code.

## What changed

- **The Codex adapter** declares `child` (`SubagentStart`) and drives every probe through the
  app server. For each probe it lists the hooks, starts an ephemeral conversation in a read-only
  sandbox and asks. For a rehydrated session it first runs one turn and compacts. `codex exec` is
  no longer used.
- **Every run gives the host every declared route's hook**, one group per route in the order the
  routes are declared (`Adapter.groups`, `D-20260927-f61065`). Codex trusts a hook by its place,
  and the startup and compact hooks would otherwise take the same place, so trusting one would
  replace the other. The startup hook stays at `session_start:0:0`, and the compact hook takes
  `session_start:1:0`. The two hooks the person had trusted stayed trusted; the person reviewed
  and trusted the two new places. Claude Code takes the same set, so a probe runs the
  configuration a delivery will.
- A route counts as trusted on Codex only by its own place. A trusted startup hook does not make
  the compact route runnable.

## Used on this machine

On a fresh state root, through the journal:

| Host | new | current | child | rehydrated |
| --- | --- | --- | --- | --- |
| Claude Code 2.1.283 | worked | worked | worked | worked |
| Codex 0.157.1 | worked | worked | worked | worked |

Each Claude Code probe recorded three hooks (one per event), all enabled; each Codex probe
recorded nine, the person's six and the adapter's three, all enabled. Deliveries to the current
and child recipients were then received on both hosts. The whole run took 87 seconds, and 96
seconds when run again after the last change below, with the same results. The attempts were
still submitted by the script, standing in for the hook.

## How it was checked

- **Units.** The fake Codex is now its app server. New tests check that:
  - a rehydrated Codex session is compacted before it is asked;
  - a child is asked for through the session on both hosts;
  - a session that could not be compacted is not asked;
  - Codex conversations are ephemeral and read-only;
  - every run carries every route's hook in its place;
  - a route whose own place is untrusted is refused even when its event's other place is trusted.

  The delivery tests that needed a route an adapter does not declare now remove one for the
  length of the test. 262 V1 unit tests pass.
- **Reverts.** The sweep tool, lost with the session's scratchpad, was rebuilt beside this
  slice's evidence (`v1-slice4-use/revert4c.py` in the workbench) with the new rules. Its first
  runs left five reverts alive, and each was fixed:
  - Two were the probe's branch for an outcome an adapter already knows. Driven through the app
    server, Codex no longer knows one, so the branch and `Run.outcome` were removed.
  - One was a test whose expected hooks were built by the function under test, so reverting the
    function moved both sides. The test now states the values.
  - Two were cases no test brought about: Codex refusing to start a conversation, and a turn that
    answers and closes before it ends. The fake Codex now does both, and each is no response. In
    its error case it leaves a plan and no message, which holds a reply to the agent's messages.

  A sixth revert (skipping the compaction request) was caught only by waiting out the probe's
  five minutes, once for every compacting test, so the sweep ran out of time. The probe tests now
  give a probe twenty seconds, and a refused compaction must end within ten. After these changes
  all 69 reverts are caught.
- **The V1 cases on the real driver.** 13 pass, 7 fail and 2 block, as before.
