# Independent GPT design draft — 2026-09-07

Dispatch: native FRONTIER task `/root/session_scope_design_gpt`, fresh context,
using the same blind packet as the Claude draft. This is the substantive draft
returned by that task, retained for comparison; it is not an implementation verdict.

The recommended boundary is explicit launch: installation stores agent-bios in
its own directory; agent-launch activates it for a selected session. Plain codex,
plain claude, and Software Engineer/Vanilla retain normal native discovery and
receive no agent-bios additions.

This can deliver zero automatic exposure without changing global files during
ordinary launches. Existing installations first require explicit cleanup. A project
or personal file deliberately importing corpus is a separate conflict: preserving
that import and guaranteeing zero corpus are incompatible. Resuming a Builder
transcript cannot become Vanilla just by omitting new arguments.

Compare a portable startup corpus with private procedure paths against the same
mechanism plus session-only native registrations. The first has the lowest cost
but does not promise native skill menus or event hooks; the second is recommended
because it preserves useful existing behavior through two bounded host adapters.
A redirected host home couples filtering to auth, preferences, history, databases,
and host writes. No safe selective overlay contract was established, so it should
not be the default.

Reuse corpus, package, domain, consumption surface, preset, and launch plan. Extend
the launch plan with resolved selection and immutable content references; retain
the domain manifest as membership authority. Presets choose behavior, not duplicate
instruction bodies. Installation places versioned assets under app-owned state,
without seeding globals, registering global hooks/agents/skills, or replacing shell
functions. Vanilla directly dispatches the native backend without corpus settings
or permissions changes.

An active launch materializes selected content, resolved guide paths, agent
definitions, hooks, and a personal-learning snapshot into immutable files. Code
owns paths, hashes, serialization, and registration projections. Resolve all
references there, including wrappers and nested processes; leaving host-home guide
paths would retain the old dependency. User customizations remain separately owned.

For Codex, retain the real CODEX_HOME. Per-call agent config is a candidate that
must be verified against child execution. developer_instructions is a replaced
scalar, not an append: it can erase user instructions and raise corpus above project
instructions. Probe effective configuration and hierarchy before choosing it. If
no supported additive route preserves existing instructions, use startup content
in the initial user input and disclose its priority. Do not approximate native
configuration resolution. Until session-only native skill discovery is proven,
expose selected procedures with private paths without claiming native registration.

For Claude, append startup guidance and use the existing agents JSON route. A
session-only plugin is the candidate for skills and the advisory hook. Probe
schema, discovery, collisions, and coexistence. A settings file is an alternative
only after hook-array merge behavior is known. Keep normal settings sources.
The current hook supplies reminders; do not invent a permission guarantee from it.
Any delivery limitation must be visible before launch.

Neither adapter should infer sandbox bypass from corpus activation. Apply only
selected launch settings and preserve managed policy. Instruction priority,
scalar replacement, collection merging, and permission enforcement are separate.

Retain snapshots for active/resumable sessions; updates affect future selections.
Map native identity to the launch plan through verified host evidence. Resume
reuses recorded content; missing content produces a recovery choice rather than
silently selecting latest. Mode changes start fresh. Credentials and native
history stay in their normal homes. Garbage collection removes only unreferenced
snapshots.

Migration is separate from install and launch: inventory owned markers, imports,
config, hooks, skills, agents, and interception; produce a backed-up exact removal
diff; preserve unrelated content. Modified or ambiguous material needs a specific
decision. Preserve dependencies of existing sessions. Repeated migration must be
harmless.

Cleanup alone is insufficient: learning capture recreates global imports/regions,
and corpus-state publication and rollback write global content. Change those
writers alongside the installer so later actions cannot reactivate Vanilla.

Implementation sequence: native loading/merge/child/resume probes; immutable
assembly and launch projection behind explicit opt-in; both adapters and all
writers; reviewed migration and current-state docs; real fresh/migrated install
tests, simultaneous sessions, crash/update/resume, unchanged global files, and
preserved user instructions/config/auth. Positive and negative controls must
observe real prompt, hook, and child behavior, not just argv.

User decisions: architecture approval before implementation, and approval of the
concrete legacy removal diff. Other choices should arise from actual conflicts or
failed probes rather than routine adapter details.
