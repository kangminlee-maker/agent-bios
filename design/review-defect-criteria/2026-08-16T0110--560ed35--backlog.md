# Backlog — a catalog of review defect criteria, and where it lives

**Status: not started. Needs its own design session** (blind packet, dual-provider drafts per
the corpus's design rule), because it changes the deployed corpus — the review guides every
session loads — and the corpus author has to approve what ships. This record is the packet
seed; it decides nothing.

## Where it came from

A peer session on `~/Documents/cli-api-adaptor/local-OAuth-CLI-API-adapter` handed over
`docs/review-defect-criteria.md` (commit `b9eea7e` there, branch
`feat/model-selection-2026-08-13`) on 2026-08-15 with the user's request that this repo judge
it. Read that file first; it is the source and this record only frames the decision.

## The claim, in one paragraph

"Defect" is not a universal bar. It is a function of **system type × the goal of this piece
of work**: an API surface's defect is a client receiving a response other than the contract's;
a library's is a contract violated *or unprotected*; an AI harness's is **a signal that is
false but looks true** (a wrong PASS, a vacuous test, a silent fallback, a packet missing its
call site, a wrong denominator); a decision ontology's is a model reaching a wrong judgement.
Measured over 39 review rounds on that repo: reviewing an API surface against a "material"
bar (contract violation OR unprotected promise) plateaued at 17→23 findings — each fix added a
contract row that became the next round's finding — and splitting into
behavioral_defect / coverage_gap / doc_gap with the stop condition "behavioral = 0" resumed
the decline (10→5). The bar was not wrong; it was a library's bar applied to an API.

Three consequences it argues for: (1) choose and **declare** the criterion from a catalog
before a review starts, not improvise it; (2) every criterion carries **goldens** — 2+
positive, 2+ negative, 1+ boundary, each with its why — because a definition alone does not
make an LLM reviewer classify consistently at the edge (measured: the same item classed
doc_gap by one lens and behavioral_defect by another, both defensible); (3) the classification
is a **required enum field in the output schema**, audited every round, not a prompt
instruction — the corpus's own LLM/capability-boundary rule.

The catalog schema it proposes per criterion: name · observer · definition of defect ·
evidence required · explicit non-defects · stop condition (what "0" means and whether it is
reachable, i.e. not self-replenishing) · misclassification cost (which error is expensive) ·
goldens. Four draft entries: 4-A web service/API, 4-B library/SDK, 4-C AI harness, 4-D
decision ontology. Its own open problems: where the catalog lives and who maintains it;
validating the goldens themselves; the cost of switching criteria mid-loop; 4-C's stop unit
being "a run" rather than "a surface", so harness review may need its own track.

## Why this repo, and the recommendation carried into the packet

This repo's PR #29 loop is an instance of the claim: its stop condition "no product
malfunction or crash findings" is a 4-C criterion chosen implicitly, and it converged where an
earlier "material" bar would not have. The deployed corpus's `review-request.md` explicitly
does not own "what counts as material" — it points at `coding-staged-workflow.md`'s severity
ladder — so the catalog has two candidate homes.

Recommendation carried into the design (not decided): **a new guide,
`review-defect-criteria.md`, linked from both** — `coding-staged-workflow.md` is 112 lines of
workflow and a catalog with goldens is a different altitude; a `defect criterion` term goes
into `LEXICON.md`; goldens ship with a dated "why" and a rule for how one is overturned.
Alternatives the design must weigh: fold a section into `coding-staged-workflow.md`; keep the
catalog in the origin repo and ship only the principle ("declare the criterion, attach
goldens, force the enum"). Constraints: concept economy (one new term at most), the
LLM/capability boundary (the enum is enforced by the reviewer's output channel, not prose),
the global-bullet budget (nothing new in `claude/CLAUDE.md` unless it displaces a bullet), and
the mirror rule (ko tree + `emit-mirrors.py`).

## Done-when for the design session

A design record under this directory that names the home, the term, the golden-validation
rule, and the migration for existing review packets (this repo's own rounds declare their
criterion by name), with a build order and its negative controls; then the user's approval
before any corpus file changes.
