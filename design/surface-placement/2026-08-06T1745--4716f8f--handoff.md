six rounds. Eleven were fixed, three went to backlog, one was left as pre-existing in main.

## The open work, in the order it was left

### 1. Concept Economy guide — started, nothing written

The blocking piece of the relocation design. Four of the five builder-base sections can be
compressed to a pointer because their guide already exists; Concept Economy has none, and it is
the largest block at 16 bullets. The bullets were extracted and the guide conventions read; no
prose exists yet.

**Know the real cost before starting.** A guide is not one file: `claude/guides/<n>.md` and
`ko/claude/guides/<n>.md` are both hand-written (the codex pair is generated by
`gates/emit-mirrors.py`), plus a `compose/domains.json` entry and one global pointer.
`gates/check-parity.sh` fails when the EN and KO guide sets differ, when `guide_id` does not
match the filename, and when `language` does not match the tree. Comparable guides run ~285
lines in each language.

### 2. Enforcement candidates — measured, unverified

Three of the seven hook traps dissolve into a default that reaches both agents because both run
the same shell and the same git: `pull.ff = only`, `set -o pipefail`, and a `grep` that passes
`-a`. **None is deployed** — `launch/agent-launch.zsh` is 38 lines whose only behaviour is two
`unalias` calls.

`set -o pipefail` changes the exit status of existing pipelines and can turn working scripts
red. It is a behaviour change to a shared environment: default-off opt-in, proven over this
repo's own scripts first. The other two are narrower but still ambient and need the same
treatment.

## Outside the repo

`~/.zshrc` no longer exports the gh keyring token into every process environment. That export
was how a token reached a transcript this session — it was rotated (scopes narrowed at the same
time), and the line is now commented out with the reason and the restore path beside it. The one

`${GITHUB_PERSONAL_ACCESS_TOKEN}` as a bearer header, and it is not enabled, so nothing broke.

call `gh auth token` itself. Backup at `~/.zshrc.bak-20260806-174644`; takes effect in shells

## What this session got wrong, so it is not repeated

The two-dot range trap, caught by a hook: `git diff 80b5c97..HEAD` was used to compute "files
this session touched" and would have included everything the trunk brought in. The correct range
excluded the merge's other parent.

Assuming a green command answered the question asked. `install.sh install` would have narrowed

Claiming a fix without re-measuring. The ownership regex was narrowed once and still claimed
`notes.bak-20260101-000000`; the self-test had only rejected malformed timestamps, testing the
shape and never the ownership.
