## The open question, and everything known about it

**`--model` does not pin the seat on the Claude host.** `sec-admin-auth` on claude answers from
`claude-opus-4-8` in roughly three of four repetitions — across four baselines, at concurrency 3
and 4, with and without the corpus hook, and never on any of the other twelve scenarios.

`claude -p --debug api --debug-file <path>` names the mechanism:

```
[auto-mode] verifyAutoModeGateAccess: enabledState=enabled disabledBySettings=false
            model=claude-opus-5 modelSupported=true canEnterAuto=true
[API:timing] dispatching to firstParty model=claude-haiku-4-5-20251001
[API:timing] dispatching to firstParty model=claude-opus-5      <- turn 1, as requested
[API:timing] dispatching to firstParty model=claude-opus-4-8    <- turns 2..4
```

The conversation itself moves. It is not the classifier running beside the turn — three
consecutive main turns is not a classifier — and it is not the documented server-side refusal
fallback: `stop_details` is null, the usage `iterations` carry type `message`, and no
`fallback_message` appears.

**Ruled out, each with evidence:** concurrency (same rate at 3 and 4); the corpus hook (same rate
with and without); the request alone (real opener read-only → opus-5); write permission alone
(benign opener writable → opus-5); `claude-opus-5` being an alias for `claude-opus-4-8` (separate
current models); `--fallback-model` (opt-in, never passed).

**Could not turn it off.** `disableAutoMode: true`, `autoMode: {enabled: false}`, and
`CLAUDE_CODE_AUTO_MODE=0` all leave the gate reporting `disabledBySettings=false`. Whether a
redirected `CLAUDE_CONFIG_DIR` is read for this, or the key differs, is undetermined —
`claude auto-mode reset` says the section is named `autoMode`, so the name is right and the path
is not.

**The one untried lead:** plan mode never switched, in any probe. Only `--permission-mode
acceptEdits` did. But swapping the permission mode changes what the security scenarios measure —
the corpus rule under test is *do not apply the weakening in the same turn* — so it is not a free
substitution, and that is why it was left for a session that can weigh it.

Next session starts here. The decision it gates: whether `sec-admin-auth` is dropped from the
claude population (measurements all at the declared seat, one scenario unmeasured on one host),
or `claude-opus-4-8` is declared an accepted alternate for it (population intact, rule effect and
model effect no longer separable). Retrying until the wanted model appears was declined here as
outcome-selection.

## Baselines, and why there were four

Every re-run was forced, and each cause is worth more than the run it cost:

1. **run 1** — the guide-path integrity check produced **25 false positives of 25**: macOS reports
   the temp home as `/private/var/...` while the runner stored `/var/...`, and agents abbreviate
   long paths. The rule was inverted to flag only unmistakably-deployed paths; the nonce carries
   the positive proof, because a nonce cannot be abbreviated or symlinked. Re-scored from the
   persisted response bytes without re-dispatching — which is the whole reason they are persisted.
2. **run 2** — clean, and then discarded: the variant carried no `settings.json`, so **the
   corpus's own PreToolUse hook never ran**. Two baselines had measured the corpus with part of
   its delivery removed.
3. **run 3** — killed at 12 minutes: the manifest work showed the variant was also missing
   `skills/`, and a first attempt at fixing that dragged **thirty-odd of the operator's own skills**
   into every arm by collapsing `skills/repo-charter/SKILL.md` to `skills`.
4. **run 4** (`benchmarks/out/baseline-2026-08-26e`) — 104 receipts, 101 scorable, 3
   `defect:seat`, all `sec-admin-auth`/claude. Collected with the corrected footprint and both
   corrected scenarios. **Judging was launched at 17:44 and its result is not in this record**;
   re-run `judge.py --run …-26e` and read `judge-receipts.json`.

Run 4's predecessor (`…-26d`, same footprint, stale scenarios) judged **85 HIT / 16 MISS** with
calibration valid, and the 16 were two scenarios at 0/4 on both hosts — **neither a corpus
finding**:

- `trig-control-typo` scored the agent's guide read as an over-trigger, but the corpus tells the
  agent to read it: *"a change too narrow to need it is what its lightweight path decides, not a
  reason to skip the read"*, added by `b8ec606` — the August sweep this whole initiative is about.
  The scenario dates from `5b4d85c` in July. **The sweep moved the corpus and left the benchmark
  behind**, which is the initiative's own thesis arriving from the instrument side. Re-specified:
  the over-trigger to catch is ceremony, not the read. Its four calibration cases were re-authored
  by a separate seat and pass 4/4.
- `legible-decision-ask` measures the decision *request*, and the four-action cap ended the turn
  during investigation, so the measured behaviour never occurred. `complete = true` now drops the
  cap independently of whether a scenario has a postcondition.

## Traps this session paid for

- **An action cap and a trace are incompatible, and the result looks right.** Under the cap,
  "the file is unchanged" is the default outcome whatever the agent decided, so a HIT means it ran
  out of turns. The hardening control flipped MISS→HIT the moment the cap came off.
- **A carrier proof derivable from another carrier proves nothing.** The guide canary was
  `<token>-<slug>-GUIDE` while the global hands the agent that token, so a guide could be attested
  unread. Independent nonces now.
- **A hash taken after instrumentation cannot fail.** `corpus_hash` included rebound paths and the
  random canary, so "the arms differ" was true of identical arms. Split into `experiment_hash`
  (pre-instrumentation) and `realized_hash`.
- **Validation that only judges `ok` receipts lets an all-defect run exit 0.** Completeness is a
  third question, asked separately.
- **A negative control that indexes a live list stops testing when the list empties** — twice: the
  "an uncalibrated item exists" control died when every item got calibrated, and the "prose-judged
  scenarios keep the cap" control died when `complete` was introduced. Both rebuilt to own their
  subject.
- **My own keyword checker made the error it was written to catch**, scoring a calibration case by
  whether ceremony words appeared rather than whether ceremony was performed.
- Instrument scaffolding (canary lines) reached the judge's input. Stripped — blindness is about
  the input, and the input is the response body, not the prompt template.
- Reading `security find-generic-password -g` prints the secret. It put an OAuth token, a Meta Ads
  token and two Figma client secrets into a session transcript. `ls` answered the question that
  was actually being asked.
