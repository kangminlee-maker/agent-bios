# Stage 0 live: what the instrument found when it met the hosts

Closes the build plan `2026-09-04T1420--e7b6151--stage0-build-plan.md` (S5) against real
seats, and is what design revision 9 reports back. Instrument: `benchmarks/tier/` —
`usage.py`, `pin.py`, `fixture_gen.py`, `level.py`, `protocol.py`, `probes.py`, and the
live path `live.py` (`probe`, `run`, `plants`); negative controls in `selftest.py`
(72 checks across seven slices, every blocking control shown failing on a
planted violation). Run records under `benchmarks/out/tier/` (gitignored — regenerable by
re-running, and the seat costs are the reason not to commit them).

## Three things the design named that the hosts do not have

1. **Haiku 4.5 has no effort lever.** `claude -p --effort max` on haiku records no
   `effort` field in the transcript; the same flag on opus-5 records `xhigh`; the vendor
   reference lists no effort levels for Haiku 4.5 (Opus 4.5 gained `effort`, Haiku 4.5
   did not). "haiku at max" was a seat that cannot be run. The Claude sweep row now pins
   `effort: None`, and the seat receipt demands an *absent* effort there
   (`D-20260904-090eb5`).
2. **Codex encrypts what a parent tells its child.** The child rollout stores the spawn
   message as `encrypted_content`; the parent rollout's `spawn_agent` arguments carry the
   same ciphertext; `codex exec --json` emits no spawn text. The brief half of control 4
   has no artifact on Codex and is a disclosure there; `agent_type` and `fork_turns` are
   plaintext and still block (`D-20260904-d42861`). The body half survives: the child's
   first `developer` message is the template's `developer_instructions` verbatim.
3. **The Claude "standing prefix" settles on the third identical run.** Three
   byte-identical fresh processes in one directory: haiku read 14,952 → 40,314 → 40,314
   (the whole prefix, nothing written on the third); opus-5 at xhigh 11,815 → 15,091 →
   15,091 with 35,211 still written on the third (cause not established). Runs that
   differ in flags or directory do not share the suffix — three haiku runs with
   differing flags read 17,877 / 17,887 / 17,887 and wrote 14,126 each time — and the
   first run in a new directory reads less than the settled value: the live run below
   read 11,815 against a 15,027 reference and was flagged cold, as designed. The probe
   now primes twice and measures the third; Stage 1 must prime in the run's own
   working directory, per block, with the run's own flags.

## Instrument facts learned on the way

- A `-p` parent that spawns a subagent emits **two** `result` events; the last carries the
  spawn-inclusive `total_cost_usd`, which reconciled with parent + child from their own
  transcripts at relative error ≤ 1.2% on every run.
- Some Claude messages leave **only streaming snapshots** in the transcript (three
  records, `output_tokens: 1`, no `output_tokens_details`, no `stop_reason`, then the
  tool's result). The request ran; its final usage was never written. `usage.py` bills it
  from the last snapshot and discloses the under-read; a final record without the field
  is still refused. The reconciliation control is what sizes the gap (0.8–1.1% on the
  runs above).
- The Codex body receipt is a placement, not a message: the template body sits inside
  the child's first `developer` message, at char 0 in one run of the same seats and at
  char 17,885 in the next — after a `<model_switch>…</model_switch>` preamble carrying
  the child model's base instructions — and the host appends ~13–14K chars of
  `<skills_instructions>`, permissions, and plugins blocks after it. Two false refusals
  taught the rule; the s6 golden now carries the preamble, and a body preceded by any
  other text is refused by name.
- A fresh `CODEX_HOME` bootstraps ~28 MB of curated plugins and system skills on first
  start (network), and every child's prompt carries the resulting skills list. Identical
  across arms, but Stage 1 should reuse one home per host rather than pay it per run.
- `codex exec resume` keeps the thread's cwd and sandbox but **not** its model or effort
  (a `low` thread resumed bare ran at `xhigh`), so every resumed pass re-pins both.
- `spawn_agent` is not on luna's tool surface ("spawn_agent unavailable" from inside the
  model's exec script); terra and sol have it. Luna is only ever a child, so no arm is
  affected.
- The Agent tool hands a subagent its prompt without the trailing newline; the brief
  receipt compares stripped text.
- The keychain item `Claude Code-credentials` no longer exists on this machine
  (`security … rc=44`); credentials live in `~/.claude/.credentials.json`. `live.py`
  lets the parent authenticate itself from the deployed home when no token channel can be
  opened. `benchmarks/corpus.auth_channel` still reads the keychain first — the
  instruction benchmark's live path is affected; not changed here.
- `benchmarks/run.py` and a tier `run.py` shadowed each other on a `sys.path` that
  `usage.py` extends; the live path is `live.py`, named for its realization.

## What Stage 0 leaves for Stage 1

- Cost basis: the Claude reference cannot be cheaper than the host's own list-rate
  arithmetic; the two estimators agree by construction there.
- The Claude cache band's reference is directory-sensitive (probe-cwd vs a fixture
  workdir differ in path length and git state); a run whose first request falls outside
  ±10% is flagged, not excluded — Stage 1 will show how often.
- The delegated-workhorse arm on Claude coincides with P (design); nothing here ran it.
