# Session distill implementation plan: addendum for WP-02

This record settles one reading of `2026-10-20T2119--cc0498f--implementation-plan.md`, work package
WP-02 (the model-call gate and the dispatch supervisor), raised by the review of its supervisor.
The plan and design §3.2 stand otherwise.

## The dispatcher writes the call's receipt, after the runner exits

WP-02's interface says the dispatcher "writes `calls/<call_id>/` and the receipt through the
runner". The receipt's required evidence keys include the usage state and totals and the capture
hash (design §3.2), and those are final only after the runner's process tree has exited and its
capture has been copied out before any temporary home is deleted (§13.3). The reading this record
takes:

- `runlib/dispatch.py` writes each call's `ReviewReceipt/v1` once, after the runner exits and the
  capture is copied, through the launcher's own receipt writer (`launch/agent-launch.py`
  `--emit-receipt`), so the receipt format keeps one owner.
- A receipt a runner may write for itself is kept inside the call's capture as evidence; it is
  never the call's receipt.
- The gate recomputes every receipt value from the call directory (WP-02), so who writes the
  receipt does not make any value trusted.
