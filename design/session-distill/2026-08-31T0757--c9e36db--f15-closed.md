# F-15 named its own cause within the hour of being made able to

F-15 sat in `FINDINGS.md` from 2026-08-03: a launcher parity check failed once, never
reproduced in three consecutive runs, and its message could not say which of its four
conditions had been true. The entry's own reading of it was a race — `argv_log` is written by
a spawned process, and a read landing before the child flushes fails exactly that way — but it
said so as a hypothesis, because the one occurrence had destroyed the evidence that would
decide it.

## What happened

The first alternative the entry named was taken: split the assertion so each condition names
itself (`conditions_that_held`), verified by planting each condition and reading the message
back. That change was staged, and **the very commit carrying it was blocked by the flake
recurring** — inside `gates/test-install-guides.sh`, whose I15 scenarios run a nested umbrella
while the outer one is still running:

```
FAIL: agent-launch Custom Start was not the final launch confirmation:
      ['picker_exited_nonzero', 'argv_log_absent'] (picker exit -9)
```

`-9` is SIGKILL, and the killer is this harness: `run_picker_scenario` waits `timeout` seconds
for the picker to exit and kills it on the deadline. `argv_log_absent` is downstream of that —
a killed picker never wrote the log.

So the hypothesis was wrong, and wrong in the direction that matters: nothing was racing. The
picker was fine and the deadline was short.

## Why 3 seconds was not enough, measured

Instrumented on an idle machine, every picker scenario in the fixture finishes in **0.03–0.35 s**
against the 3 s deadline — a 9–100× margin, which is why this looked safe and why it fired once
in two years. It fired under nesting: the install scenarios run a full umbrella inside the
umbrella, and the second copy of this fixture competes with the first.

## The fix, both halves

1. **A deadline kill is reported as one.** The `finally` branch that kills now calls `mark_fail`
   naming the scenario and the timeout, and says every assertion below it is about a killed
   process. Before, `-9` flowed into the semantic assertions and the suite blamed the launcher
   for the harness's own deadline — a false signal by this repo's defect criterion, and the
   reason F-15 was unreadable for as long as it was. Controlled by forcing the deadline to
   0.01 s: 17 scenarios report the timeout by name; restored, the leg passes.
2. **The deadline gets real headroom**: 3 s → 15 s, still ~40× the measured worst case. It costs
   time only when something genuinely hangs.

## What this closes, and what it does not

F-15 is deleted from `FINDINGS.md`, which is now empty. The flake had a cause, the cause is
named, and the condition that produced it is both survivable and reported honestly if it
recurs.

It does not prove the picker can never hang for a product reason. If it does, the message now
distinguishes that case from this one — which is the whole difference F-15 existed to record.

The generalisable half is not about pickers: **a failure message that folds several conditions
into one sentence destroys the evidence its own recurrence needs.** The split cost four lines
and the answer arrived within the hour.
