## Goal and completion boundary

Mine every retained, discoverable Claude Code and Codex session that had a directly handled interactive main-context event in the rolling 21-day window. Exclude dispatched subagents, automated/headless subprocesses, and ambiguous provenance. Screen every eligible user-goal episode, deeply analyze evidence-backed high-value candidates, compare every candidate with the current canonical AGENTS/CLAUDE/guides, add historical instruction lineage only when the delivered state is provable, generalize approved lessons, and produce a human-reviewable promotion bundle. Repository edits and deployment are later, separately approved work.

The honest scope is “all human-history session ids plus all retained records in enumerated authoritative roots.” A history-only id remains an observed session with `goal_only` evidence rather than being silently removed: its surviving user goal may support task/topic recurrence, but not outcome, rollback, causal, impact, or solution-learning claims. Sessions absent from both history and every known store remain unknowable.

## Definitions and default scope

- Window: runtime captures `T_end` once and uses `[T_end - 21*24h, T_end)`; UTC is comparison authority and Asia/Seoul is recorded for display.
- Inclusion event: at least one human user message or main assistant/tool event belonging to an interactive user turn is in the window. Background bookkeeping alone does not include a session.
- Direct main: user-operated interactive TUI/Desktop/CLI context with compatible non-dispatch provenance and at least one admitted human-input episode. Human history membership and transcript-side explicit human provenance are separate evidence sources when the provider exposes both; the absence of an automation marker is never promoted into positive human evidence.
- Headless/dispatched: `codex exec`, `claude -p`/`sdk-cli`, automation, and review subprocesses are excluded even when they run many turns. Historical metadata cannot distinguish a manually invoked headless command from a dispatched one; `thread_source=user` on Codex exec is not proof. The retrospective run therefore has no safe “include manual headless” option. A future launcher could stamp explicit human-launch provenance.
- Logical session: provider + stable provider session/thread id, not a filename. Resumes and relocated files with the same id remain one lineage.
- Episode: one user goal and its resulting main-context decision/action/outcome. Token and error value is measured at episode level, not whole-session level.
- Evidence completeness is orthogonal to provenance: `full_episode` has goal plus decision/action/outcome evidence; `partial_episode` has a bounded missing segment; `goal_only` has only an admitted human goal. A weaker grade can support only claims whose required evidence fields it actually contains, and no aggregation upgrades the grade.
- Instruction segment: the maximal interval in one logical session governed by the same exact delivered instruction payload. A new injection, reset, or instruction-affecting compaction opens a new segment; an event that cannot be assigned to one exact segment has `historical_unknown` reach even when another segment in the same session is exact.
- Dispatched content quoted into a main transcript is `dispatched_input`, not an independent occurrence. Known machine provenance such as Claude `origin.senderTaskId` marks it deterministically; semantic judgment is limited to whether the main context adopts, rejects, changes, verifies, or acts on it.

## Architecture

### 1. Freeze and snapshot

Preservation precedes readiness: a deterministic, readiness-independent archive step copies every in-window session JSONL from both provider stores plus both `history.jsonl` files into a launcher-owned local archive outside the repository, provider homes, cloud-synced folders, and every run root, recording per-file size, mtime, and SHA-256 of the original bytes (per-file compression is allowed; manifest hashes always refer to the original bytes). The census enumerates and freezes byte prefixes against the archive, so later provider-store GC, rotation, or mutation cannot shrink the corpus. The archive is append-only across censuses, exempt from run-root retention and hard expiry, and kept indefinitely; deletion is an explicit user decision (decided 2026-07-16). The first archive for this corpus was executed 2026-07-16 into `~/.local/share/session-distill-archive/census-2026-07-16`.

Runtime creates a private run root under a short launcher-owned 0700 base whose exact realpath is outside the repository, provider state/instruction homes, and default/system temp roots. The P0 path-length and ancestry gate blocks if no such base satisfies the pinned providers' temp constraints. It pins `T_start/T_end`, source roots, source byte limits, parser/classifier/redactor/prompt/schema versions, current repo commit/hash, provider route, model/effort, budgets, and approval state.

Active JSONL files are read only through the captured complete-line byte prefix. Appends after `T_end` belong to a later run. Malformed lines, divergent duplicate session ids, missing timestamps, and source mutation are visible dispositions, never silently skipped.

Discover default and configured Claude/Codex roots, archives, restore locations, provider SQLite indexes, and both `history.jsonl` files. Deduplicate by stable session/event identity. A strict-prefix duplicate may use the complete superset; divergent variants quarantine. Path dates and mtimes are discovery hints only. The analysis/review jobs created by this pipeline are explicitly self-marked and excluded; their normal `codex_exec`/`sdk-cli` provenance is also a negative signal.

### 2. Deterministic census and normalization

Every physical source and logical session receives one source disposition: `eligible_main`, `excluded_dispatched`, `outside_window`, `proven_duplicate`, `known_absent_source`, or `unknown_quarantine`, with a required reason code. Evidence completeness is a separate axis: a history-only session can simultaneously have `source_disposition=known_absent_source` and one `evidence_grade=goal_only` card. Reconcile the retained-store partition, human-history partition, and semantic-card partition independently. A retained broad-main signature without history is never folded into `excluded_dispatched`: explicit human provenance may admit it; otherwise it is `unknown_quarantine(reason=history_missing_or_provenance_ambiguous)` and remains visible.

Initial versioned classifiers:

- Codex candidate signature: scalar `source=cli|vscode`; `thread_source=user`; observed direct-interactive originator allowlist; no object `source.subagent`; no `originator=codex_exec`/`source=exec`; and no dispatch provenance. Because the observed rollout schema has no positive transcript-side human marker equivalent to Claude `promptSource+origin`, admission additionally requires a matching Codex history event. A retained complete direct signature absent from history is `unknown_quarantine(reason=history_missing_no_positive_human_marker)`, not eligible. `thread_source=automation`, object subagent sources, and exec records are negative controls. `thread_source=user` alone is not sufficient because exec records also carry it.
- Claude candidate signature: retained top-level session identity; `entrypoint=cli`; compatible non-sidechain/null-agent sanity fields; and no known dispatch provenance. Episode admission then requires a history event matched to the visible user turn, or transcript-side explicit human provenance such as `promptSource=typed|queued|suggestion_accepted` with `origin.kind=human`. `promptSource=sdk|system`, `origin.senderTaskId`, `entrypoint=sdk-cli|review|reconstruct`, `subagents/`, sidechain, and agent markers are deterministic machine/dispatched evidence. `sessionKind=bg`, contradictory origins, missing new-schema provenance, and unknown enum values quarantine for local adjudication even when history contains the id; `bg` is not assumed dispatched because observed `bg` rows can also say `typed`/`human`.

Human histories are a second observation channel, not the classifier's oracle. Build a disagreement matrix for `history + explicit-human`, `history only`, `explicit-human only`, `history only with contradictory/ambiguous transcript provenance`, and `neither`. Every in-window human-history event—not merely each session id—must reconcile exactly once to an admitted source anchor, a proven duplicate, a `known_absent_source` goal-only anchor, or a blocking `unknown_quarantine` reason; being inside an otherwise retained session cannot hide an unmatched history event. Only manually labeled real controls can be used to report classifier precision/recall; population coverage is reported as source/event reconciliation, disagreement, and quarantine counts instead.

Quarantine is a visible decision queue, not an exclusion sink. P0 reports its cardinality by provider, reason, history membership, and explicit-human evidence, then freezes a count/time adjudication budget before semantic dispatch. Every `unknown_quarantine` item is blocking regardless of whether it already carries positive-human evidence: before P3.5 it must be deterministically reclassified from admissible evidence, human-adjudicated, or explicitly excluded by the user with its exact id/count/reason stratum recorded. Retained-only ambiguity may be sampled by reason only to prioritize work and discover classifier misses; a zero-positive sample never disposes or excludes the unsampled remainder, while one confirmed direct-main miss expands adjudication to the full reason stratum. At P0 the user may pre-sign a standing exclusion policy naming reason strata and per-stratum maximum counts; a still-unresolved item matching that policy at P3.5 automatically takes the signed-exclusion path with its exact id/count/reason recorded, yielding `bounded_exclusion_coverage` without a synchronous per-item signature, while items outside the standing policy still block. A confirmed direct-main miss inside a reason stratum voids the standing policy for that stratum and returns its items to the blocking queue, mirroring the sampling-expansion rule (design review S18, 2026-07-17). If the frozen budget is exceeded, the run stops at the user gate to expand the budget or accept a named bounded exclusion; `full_coverage` requires an empty unresolved quarantine queue, and disclosure alone cannot satisfy it.

Unknown producer/schema combinations quarantine until locally adjudicated and added as versioned fixtures.

Normalize only visible interaction/tool records into a provider-neutral event ledger with opaque evidence refs and local source mappings. Preserve Codex rollback/abort events and Claude parent-UUID/fork/rewind evidence as a lineage DAG. A lineage whose branch semantics cannot be proven may still be screened outside branch-sensitive categories, but rollback claims remain unavailable.

Before any user-data semantic dispatch, deterministic code freezes an immutable current-epoch **source-anchor inventory** for every admitted human-input/user-goal event plus a provisional episode mapping and an explicit ambiguous-boundary queue. A bounded provider-affine P1.5 linker receives only locally redacted adjacent anchor heads/tails and may propose only split/merge membership for anchors already named in that queue; it cannot create, delete, duplicate, retext, exclude, or semantically classify an anchor, and its attempts use the same exposure/write-ahead/capability contracts as later semantics. Low-confidence, conflicting, or unavailable results require local human adjudication; a human may sign a conservative split into separate `partial_episode` cards with `boundary_unknown`, which preserves anchor coverage but removes cross-boundary claim authority. After every queued boundary has a validated or human-signed disposition, deterministic code freezes the final anchor/card manifest: each anchor maps exactly once to a `full_episode` or `partial_episode` primary card, a canonical provider-affinely redacted `goal_only` card, or a blocking human-signed exclusion record. Bounded screening chunks may repeat edge events as context, but repeated context cannot create another occurrence; runtime rejects inventory hash drift, gaps, duplicate primary ownership, and unresolved `continues_left|continues_right` boundaries. A valid screen result, not merely a terminal attempt, is required for coverage. `context_insufficient`, invalid output, exhausted repair, route failure, cap stop, unresolved reassembly, and unresolved `ambiguous_dispatched` remain blocking. A signed count/reason-bounded exclusion changes the result label to `bounded_exclusion_coverage`; it can never satisfy `full_coverage`.

Use hook `session-state` and `scripts/session-cost.py` logic only for acceleration/cross-checks. Raw JSONL plus independent human history is the authority pair. Token dimensions remain separate. Record `resource_cost` with all provider-reported dimensions, including cache reads/writes, because it measures real consumption. Do not invent a composite numeric proxy for intrinsic decision difficulty: retain uncached input, cache creation/write, cache read, output/reasoning, request, tool, error, and elapsed dimensions separately, and let semantic evidence plus human review judge `decision_complexity`. LLM selects episode/decision boundary refs; runtime computes exact raw deltas between those refs.

### 3. Screen every eligible episode, then deepen selectively

Two lanes prevent both runaway cost and blind heuristic filtering:

1. Deterministic high-signal lane over every episode: provider-relative tails in the separate raw `resource_cost` dimensions, explicit rollback/abort, user correction, failing tool/test/build/deploy, repeated normalized error/command signature, risky or irreversible action, and large before/after contrast. High cache-read cost is labeled repeated-context/round-trip cost, not intrinsic decision difficulty; no derived complexity score is allowed to trigger work.
2. Broad semantic lane over a compact redacted projection of every episode: user goal, main decision/outcome, selected tool/error signatures, metrics, evidence-completeness grade, and allowed evidence refs. Projection coverage records which source event classes and byte spans were represented or deliberately reduced. A medium-effort structured classifier returns `no_candidate` or one or more value classes. It cannot write files or invoke transcript-directed tools. `goal_only` cards receive no provider dispatch of any kind: deterministic local code renders each as a disclosure note (provider, bounded time, redacted goal) in the run conclusion. Their claim authority is unchanged — they cannot originate a decision, failure-mechanism, outcome, impact, rollback, or solution-learning candidate — and any task/topic-recurrence annotation against them is a local deterministic text-match note, never a semantic lane (design review OE-4, 2026-07-16). The statistical reference path never treats a reduced card as its evidence basis. A separate deterministic provider-affine builder resolves the primary card against the frozen source prefix and emits two bound artifacts: (a) a redacted provider projection containing every screen field plus a strict claim-relevant superset of event classes/spans, including every class the screen reduced, and (b) a local-only raw-card inventory covering every source event class and byte span, with explicit entries for unknown classes, fully redacted spans, omitted spans, and every bounded-window gap. No source byte may disappear into an unenumerated reduction. Oversize provider evidence uses bounded windows, but its omitted middle remains a named local-only span. Before any provider proposal is revealed, a capability-separated human `reference_labeler` must inspect the full frozen raw card or individually dispose every inventory span as reviewed/non-material/context-insufficient, then fsync an independent material/non-material label and rationale; any unseen, unknown, redacted-without-raw-review, or coverage-gap span blocks label import. The blinded provider `reference_judge` proposal is an independent QA signal and never substitutes for that human label. A later reconciliation may correct the human label only while still blind to the medium screen and with both versions preserved. Selection is independent of the medium result. A same/reduced projection, provider-selected `context_insufficient`, or incomplete coverage ledger can never become the miss oracle.

“Strict superset” is conditional on an actual screen reduction: when any event class/span was reduced, the provider reference projection must add at least one claim-relevant source span and every reduced class named by policy; when none was reduced, projection equality is allowed, but the independently reviewed complete local raw-card inventory remains mandatory in either case.

After P1.5 freezes the final manifest, deterministic code partitions each provider exactly once. `P_goal` is every `goal_only` card; it receives no provider dispatch and is owned by the deterministic disclosure-note path. `P_screen` is every non-excluded `full_episode|partial_episode` primary card requiring the broad screen. The versioned deterministic trigger rules and provider-relative thresholds classify `H = {c ∈ P_screen | at least one deterministic high-signal trigger holds}`; the probability-audit population is defined only as the exact complement `L = P_screen \ H`, regardless of resource percentile or medium-screen result. Thus “ordinary/low-signal” is a name for `L`, not a discretionary implementation bucket. Runtime fsyncs the IDs/cardinalities and asserts `P_screen = H ⊎ L` plus `final_primary = P_goal ⊎ P_screen`; no card may sit outside or in both. If `L` is empty, no hypergeometric miss-rate claim is emitted: a non-vacuous receipt must instead prove `P_screen=H` and that every member has a validated deterministic trigger/deep path. If `L` is non-empty, the provider probability sample and bound use exactly `L`.

High-effort extraction runs only for deterministic triggers or semantic candidates. A provider-level pre-committed probability audit of ordinary/low-signal primary cards receives independent reference judgments regardless of screen output; it estimates the material miss rate, while packet-size × signal minima are descriptive contrast probes. Misses beyond the frozen acceptance rule invalidate the current audit receipt and may trigger a redesign/recalibration; the first redesign allowance is included and each further one requires a fresh explicit user gate (renewable), never silent iteration. Deterministic provenance code computes the transitive card closure of everything exposed to the redesign authority—raw examples, outputs, labels, judgments, summaries, aggregates, histograms, and every upstream artifact—and freezes that closure as `influence_set`; an artifact with incomplete contributing-card lineage conservatively adds its entire possible source population. Every target-population card in that set must traverse the revised screen and an independent reference judgment as a regression control, while none contributes probability confidence. The revised contract/influence hashes must be sealed before a fresh, pre-output, disjoint probability holdout is drawn. The capability surface has distinct principals: `redesign_authority` can inspect the influence set and edit only before seal but can never enumerate/read the holdout; `reference_labeler` can receive one runtime-selected raw card/inventory at a time but cannot read medium-screen output, edit the screen contract, choose items, or reveal the manifest; screen/reference workers cannot edit either authority. When one natural person fills both human roles — the expected case here — procedural choreography cannot manufacture true independence; the run instead enforces time-separated precommitment (seal the revised contract, then label) and the audit receipt discloses the single-operator-independence limitation as a named residual instead of claiming adversarial separation (design review C04, 2026-07-16). Reopening the sealed contract still invalidates the epoch, puts every exposed card into the influence closure, and returns to the user rather than drawing adaptively. Holdout identity/content/results remain capability-hidden from prompt/schema designers and every still-enabled redesign principal until its terminal audit receipt. Misses beyond the frozen acceptance rule in the regression or holdout set, a regression failure, lineage gap, role/permission drift, premature holdout exposure, or contract/influence drift returns to the user rather than recycling either sample.

### 4. Candidate evidence and rubric

Every proposed candidate has separate refs for premise/decision, action, observed outcome, diagnosis or counterevidence, correction/rollback, and post-correction outcome when present. Chronology alone is `correlation_only`; runtime validates refs/order while LLM/human owns causal judgment.

Hard eligibility before priority:

- grounded in an admitted main episode with resolvable evidence;
- actionably preventable or repeatably improvable;
- absent or only partially covered in the current canonical instruction baseline, or demonstrably an enforcement/recognition issue;
- generalizable beyond the incident, or an exceptional high-impact singleton with confirmed impact and counterfactual;
- stable enough for an active rule/guide rather than volatile environment trivia.

Use an evidence-backed vector, not one opaque score. Each 0–3 facet carries evidence, counterevidence, dissent, and unknowns:

- `resource_cost` (actual provider-relative token dimensions, requests, active time) and `decision_complexity` (semantic evidence about the difficulty of reaching the decision), kept distinct; the latter is never computed from a token formula;
- `wrong_or_rollback`;
- `rediscovery`;
- `recurrent_error`;
- `impact` (including irreversibility/blast radius);
- `expected_gain` split into cost, time, design quality, and safety;
- `generality_and_stability`;
- `evidence_and_causal_strength`.

Runtime enforces a versioned claim-authority matrix before human ranking. `goal_only` may establish only direct history submission, bounded provider/time identity, a redacted user goal, and task/topic similarity. It cannot establish a decision, action, outcome, rollback, diagnosis, cause, counterfactual, impact, solution, failure mechanism, or learned-rule premise. `partial_episode` may support only claim types whose required refs survive; no aggregate upgrades missing fields. Topic recurrence involving `goal_only` is labeled `topic_only` and cannot increase causal, behavioral, impact, novelty, or admission strength.

Runtime orders only human-confirmed facets. Behavioral or mechanism recurrence requires at least two independent direct-main lineages, each claim-sufficient for that exact behavior/mechanism; repeats/resumes in one incident count once and dispatched quotation counts zero. Semantic similarity and causality remain LLM proposals and human judgments, while runtime owns evidence grade, required-ref presence, ordering, and lineage independence. Two singleton routes exist (design review OE-8, 2026-07-16): the high route requires human-confirmed high/blocker impact plus observed impact or rollback contrast and a written singleton rationale; the medium route requires human-confirmed generalizability, a novelty check against the current baseline, an explicit counterexample search, an over-trigger control, a token-budget delta, and explicit user sign-off, with the bundle entry labeled `singleton_medium` and dissent recorded.

### 5. Compare with instruction truth

Current baseline is a deterministic index of (a) the shared English canonical units in `claude/CLAUDE.md` and `claude/guides/` and (b) every declared provider-scoped exception identified by the pinned parity authority `scripts/check-parity.sh`, including the current Codex-only dispatch exception. Each unit carries `applies_to=common|codex|claude`; an undeclared mirror difference is a parity failure, not an implicit exception. Stable current rule-unit ids come from authority path, heading, applicability, and content hash. They are not hash-joined to historical prompt text. The comparator selects common units plus the candidate provider's applicable units; a cross-provider cluster reports each provider projection before a combined disposition. Semantic comparison proposes `covered`, `partial`, `absent`, or `conflict`; human adjudicates it.

Current-gap comparison is the sole instruction authority for admission. It is neutral to historical reach but respects declared provider applicability. A current `covered` result routes to recognition/enforcement/capability/benchmark work rather than a duplicate rule; `partial`, `absent`, and `conflict` remain human-adjudicated promotion candidates. A provider-scoped rule cannot falsely cover another provider, while a cluster covered for one provider and absent for another receives a scoped disposition rather than one lossy label. Whether the lesson was also absent when the incident occurred is useful lineage, but is not required by the user's goal and cannot block, boost, or numerically rank the current-gap decision.

Historical reach is a separate audit axis. Codex rollouts preserve exact injected payloads, but each eligible event must first map to an instruction segment; a session-level payload elsewhere is not automatically event-time authority. Claude's 240-file structural audit found no delivery receipt, so `historical_unknown` is the default unless an exact provider artifact appears. Git timestamps, filesystem mtimes, and possible deployed-version intervals may narrow a search but never prove delivery. Historical states are `delivered_known_present`, `delivered_known_absent`, or `historical_unknown`.

Historical prompt units receive content-addressed ids. Historical-to-current mapping and semantic coverage are LLM proposals with human adjudication, never hash equality. The separate provenance question “was the delivered payload identical to a canonical/mirror snapshot?” remains unknown unless an event-time snapshot proves it; exact delivered content still proves what it contains without proving repository parity.

- delivered present + behavior failed -> recognition/enforcement/capability/benchmark lineage;
- delivered absent then + present now -> already-incorporated calibration lineage;
- current absent + delivered known absent -> `proposed_current_gap` with a proven historical-absence annotation;
- current absent + historical unknown -> the same `proposed_current_gap`, with no claim about when it became new.

The admission bundle reports provider × historical-reach counts as an audit table only. It produces no historical novelty score and never pools `delivered_known_absent` with `historical_unknown` into a stronger claim. Cross-provider recurrence, impact, and current-gap clusters remain allowed when their direct-main and evidence-completeness requirements are independently satisfied.

### 6. Cluster, generalize, and place

Workers submit allowlisted bounded fingerprints: controlled facet/category fields, opaque evidence refs, and overlap-guarded `abstract_text` for trigger, undesired behavior, consequence, desired behavior, counterfactual, and scope. Unknown/free-form fields or source-overlap failures are not canonical. Similarity edges are proposals. Runtime projects candidate clusters; human confirms membership/independence, shared cause, counterexamples, dissent, and singleton status.

Draft a principle only from an adjudicated recurrent cluster or approved singleton. Drafts must state invariant trigger, desired behavior, applicability boundary, exception, prevented failure, and negative control without transcript ids, names, dates, session or user-machine paths, or provider anecdotes; the draft's consumer-target path and section id are required metadata drawn from the canonical-baseline allowlist, not forbidden repo-specific paths (design review S02, 2026-07-17). Each draft is an implementer-ready patch proposal: it names the exact consumer target (file and section), carries the exact proposed wording as a prospective diff, its measured token delta, and an aggregate gate — the sum of accepted global-text deltas must stay within the user-frozen corpus token budget before P7 can accept the set. Operational vocabulary (exact CLI flags, environment names, documented commands and config keys) is first-class draft content under the local overlap tier. Before P7, every admission-recommended candidate receives one fresh-context validity probe that attempts to refute the draft against its resolved evidence refs; the probe runs through the admission-judge provider lane's hardened route with its own packet class, schema, receipt, and forecast/budget dimensions, and that packet class is a distinct `validity_probe` workload lane with its own P2 N=1 calibration receipt in the required matrix `R` (design review S16/V06/V14, 2026-07-17), and its outcome (`supports|refutes|needs_human`) is recorded in the bundle, with a `refutes` outcome blocking admission until human adjudication (design review R6/C12, 2026-07-16).

Placement follows the nearest existing concept:

- `no_change` for duplicate, anecdotal, volatile, or project-specific material;
- benchmark/capability change when the rule existed but was ignored or structurally unenforced;
- Evidence Base/Environment Binding for measured or volatile facts;
- extend the nearest guide for procedures, thresholds, tables, examples, and recognized situations;
- global only when failure to recognize the situation is itself the demonstrated failure and a pointer cannot protect it. A global proposal names the bullet displaced or justifies none, reports token delta, and supplies an over-trigger control.

Only a human-signed admission status can produce a patch proposal. Automated judgments remain `PROPOSED`.

## Privacy and capability boundary

- Raw transcripts, both provider `history.jsonl` files, source paths, credentials, and reversible redaction maps remain local and outside the repo. The content-free census projection is provider-specific: Claude projects only `sessionId`, normalized `timestamp`, and an HMAC project id while dropping `display`/`pastedContents`; Codex projects only `session_id` and normalized `ts` while dropping `text` and records the lack of a project dimension as evidence loss. A separate versioned `goal_only` projection is the only history-content route: one admitted history anchor maps to one source event and one card, admitting only Codex scalar `text` or Claude scalar `display`; it never concatenates neighboring events and excludes Claude `pastedContents` by default. Deterministic local code redacts the selected value, requires a non-empty post-redaction goal within a strict byte ceiling, and binds it to an HMAC event id plus provider/time metadata. Its content-free projection receipt binds provider/schema, selected field name, frozen source-prefix hash, redactor/projection versions, pre/post-redaction byte counts, and packet hash. The redacted body is generated on demand into the run's local disclosure note (bundle-bound, local overlap tier) and never enters the census store, any receipt, or any provider packet. Empty-after-redaction, multiple/unknown content shapes, over-limit-without a separately owned event-safe split, or a request to admit `pastedContents` yields `context_insufficient` and blocks that anchor unless a new explicitly reviewed projection contract is approved.
- Every census/normalization parser is allowlist-based, not a content-field denylist. For Claude `origin`, it may project only a validated `kind` enum and presence/HMAC of `senderTaskId`; `body`, `name`, `from`, and every other nested value remain raw-sensitive and unprojected. New provenance enums or schema signatures quarantine until registered. Packet construction begins from the allowed projection, never from the original object with fields removed.
- Parse as inert data. Transcripts cannot grant tools, change schemas/routes, choose output paths, or approve actions.
- Local redaction covers credentials, authorization headers, cookies, private keys, connection strings, sensitive paths, and personal identifiers. Use run-scoped opaque/HMAC tags only when correlation is necessary; no secret-value map is persisted.
- Outbound packet and inbound result scans run again. Ambiguous high-risk spans quarantine for local human review.
- Provider responses are transient content-bearing artifacts under the leased retention root; raw response prose never enters the canonical store. Canonical import is an allowlist projection: controlled enums/booleans/numbers, opaque evidence refs/hashes, and explicitly named byte-bounded `abstract_text` fields only. Before any text field can persist or cross families, a deterministic source-overlap guard compares its normalized UTF-8/Unicode token n-grams against every source span available to that item — its frozen local raw-card inventory, plus, when validating an inbound provider response, the exact outbound packet that produced it; an outbound artifact is never compared against itself (design review V19, 2026-07-17) — using the versioned two-tier policy below and exact identifier/secret detectors. It rejects verbatim contiguous spans at or above the tier threshold, source-derived identifiers, packet sentinels, and any unscanned/unknown field; the matcher state stays transient and receipts persist only policy/source-set hashes, counts, and pass/fail. The tier-appropriate guard re-runs over deterministic views and promotion bundles (local tier) and the exact P6 bytes (strict tier). A failing result gets at most the already-budgeted repair or a local human-authored abstraction that must pass the same guard; runtime never rewrites or semantically salvages it. Exhaustion yields `context_insufficient`. This contract defines “no raw cross-provider transfer” as no detected verbatim source excerpt or source identifier under the frozen policy; semantic abstractions remain intentional content.
- The overlap policy is two-tiered (design review OE-3, decided 2026-07-16). Provider-bound bytes — outbound packets, cross-family projections, and P6 bytes — keep the strict tier: NFKC/casefold plus whitespace/punctuation-run normalization, rejection of any verbatim match of four lexical tokens or 24 Unicode scalar values (whichever identifies the shorter source span), and rejection of any source-derived path/URL/email/UUID/hash or number-bearing opaque identifier of eight or more scalars. Local-only artifacts — canonical-store `abstract_text`, deterministic views, and the promotion bundle — use the local tier: exact secret/credential detectors (keys, tokens, authorization material, e-mail addresses, private path prefixes) plus a sixteen-lexical-token verbatim ceiling against raw transcripts, so bulk quotation still fails while exact operational vocabulary (CLI flags, environment names, documented commands and config keys) is admissible lesson content. Three carve-outs apply on every tier (explicitly accepted 2026-07-17): current canonical baseline corpus text (already delivered to both providers in routine operation) is exempt from verbatim rejection; single tokens on the frozen operational-vocabulary allowlist — CLI flags, environment names, and command/config-key tokens whose exact spelling appears in the current canonical baseline index or the pinned binaries' registered-flag/variable probes (Appendix A), never accepted on shape alone — pass both verbatim rejection and the identifier detector; a token that matches an operational shape (`^--?[A-Za-z0-9-]+$` or `^[A-Z][A-Z0-9_]*$`) but is absent from that allowlist is treated as an unknown identifier and additionally routed through an entropy/length/digit-density test, so a high-entropy uppercase token (base32 seed, uppercase-hex, or key-id shape) is rejected rather than exempted (design review T21, 2026-07-17); and a deterministic allowlist of canonical-baseline repo-relative paths and section ids, derived from the current-baseline index and never from transcripts, passes both the identifier detector and verbatim rejection so a draft diff can name its exact consumer target (design review S02/T11, 2026-07-17). Secret/credential/private-path detectors and the entropy backstop still apply to all three; the carve-out exempts single tokens only, subtracted from a span before its four-token/24-scalar count only when every token of that span is either (i) on the frozen operational-vocabulary allowlist or (ii) the value-half of an allowlisted `flag=value`/`flag:value` split whose value is **itself a registered value on the frozen allowlist** (a documented enum such as `stream-json` for `--input-format`, never an arbitrary free-form value) and additionally clears every secret/credential/identifier detector and the entropy/length/digit-density backstop. Both the entropy backstop and the detectors apply to every subtracted value-half regardless of its shape, and neither ever by itself grants subtraction; so a free-form flag value (`--message=<arbitrary prose or secret>`) and ordinary prose are never subtracted and remain fully subject to verbatim rejection on both tiers (design review V08/T02/R6-01/T01/T04/T06/T07, 2026-07-18). `--input-format=stream-json` is split on `=`/`:`, and its value is subtracted only because `stream-json` is a registered allowlist enum that also clears the detectors and backstop. The carve-out lists and the entropy-test parameters are bound into the overlap-policy hash. Common-phrase false positives fail closed and may be locally rewritten. A looser strict-tier threshold is a new privacy contract requiring design review and user approval, not an implementation tuning knob.

Per-PID signaling of a non-direct descendant is unavailable on every path: start-time revalidation cannot close the exit-recycle window between check and signal, so event-confirmed exits plus the pinned-group path own descendant cleanup. - Process completion closes child registrations but does not override retention authority. Cleanup is a fsynced state machine `active → terminating|termination_blocked → expired|expired_incomplete → deleting → deleted` (a no-live-child run may skip `terminating`): it validates the policy hash, hard expiry, exact realpaths, artifact-class disposition, and death proofs before each transition, records `deleting` before exact-path removal, then records the content-free `deleted` tombstone outside the run root. Arbitrary per-PID signaling of non-direct descendants is unavailable on every path because start-time revalidation cannot close the exit-recycle window; the zombie-pinned PID and PGID paths carry no such window. Crash GC terminates only through the fsynced attempt registrations and those same two authorities: with the supervisor alive it reaches them through the authenticated endpoint; with the supervisor dead no pin survives (an orphaned zombie is reaped by the system, releasing the PID and PGID), so GC proves death via start-time mismatch or enters `termination_blocked`, and never signals. If any registered member's liveness or identity is ambiguous, state becomes `termination_blocked`; content is preserved, the incident is alerted, and `cleanup_complete=false`. A name match, a bare PID/PGID/SID revalidated only by number, an unpinned process-group signal, or a process-table snapshot is never signal authority; the sole authorities are a direct leader's zombie-pinned PID and `killpg` on the group PGID that that unreaped leader pins against reuse (design review V10, 2026-07-17). Resolution must revalidate the same lease and handles before continuing, so a retention violation is disclosed rather than silently extended. Candidate decisions may cause earlier policy-authorized expiry but cannot extend hard expiry silently. If analysis work is incomplete at hard expiry, a previously signed extension creates a new policy hash/deadline; otherwise runtime records `expired_incomplete` after handle termination/death proof, deletes content, and keeps `extraction_complete=false`; an already completed extraction is not semantically revoked by a later visible cleanup incident, but its retention conformance remains false until resolution. The mandatory operational tombstone duration is fixed and disclosed by implementation; the user may approve longer content-free audit retention but not shorten that floor. Before deletion, GC acquires the released cleanup lock, validates the exact leased run root, proves the supervisor plus every registered handle/member and every recorded or still-open/cwd descendant dead without identity ambiguity, and observes crash grace plus `gc_not_before`; it never uses a name glob or adopts an unleased path. A child created before adapter registration remains owned by leased `TMPDIR` ancestry and the pre-created attempt handle. A name-matching directory outside a valid lease is never adopted or auto-deleted, and a live/open, symlinked, cross-run, or identity-ambiguous path is never deletion-eligible. Packet bodies are generated on demand per bounded chunk, not materialized for the full corpus. The SQLite store retains hashes, opaque refs, decisions, and audit receipts—not transcript excerpts.

## Compact canonical artifact model

To limit concept sprawl, one private SQLite run store is canonical, with atomic transactions and schema versioning. It owns run/analysis-epoch metadata, source dispositions and evidence grades, the unique anchor/episode manifest, lineage and instruction segments, packet/exposure registries, write-ahead attempt states, budget reservations/receipts, run-root leases and per-attempt identity-safe handle/session registrations, per-item results, candidate/cluster/admission states, risk states, and approvals. Every screening/candidate/admission row carries its analysis-epoch id. It stores no transcript excerpts. Bounded redacted packets and provider/orchestrator prompt-result journals are transient content-bearing artifacts inside the same run-root retention boundary. Human JSON/Markdown views and the final promotion bundle are deterministic projections, not competing truth locations.

Ultracode retains its own per-run journals. The parent pipeline store owns cross-job item completion and maps each item to Ultracode `jobId/runId/call key`.

## Ultracode execution plan

Do not create one enormous workflow. The main context owns decisions; deterministic local code owns census, packets, validation, merge, and persistence. Each semantic phase uses bounded chunk workflows so a breaker can stop later dispatches.

### Measured budget contract

Budget authority is a vector, not a combined score. Runtime tracks and hard-caps, separately by provider and phase: request count, constructed packet bytes/tokens, provider-reported uncached input, cache creation/write, cache read, output/reasoning, elapsed time, retry count, cross-family projection bytes, and human adjudication count/time. Historical session usage is only a stratification signal. It neither forecasts this run nor authorizes spend.

P0 computes the exact source-anchor inventory, provisional boundary queue, and a conservative upper-bound card/shard/budget plan before any user-data semantic call. P1.5 then resolves only that bounded queue through its separately capped real route; deterministic code freezes the exact final episode/card/shard manifest before P2. Each route uses a live-verified context limit and tokenizer when available; otherwise a conservative UTF-8 byte ceiling plus pilot-observed usage and at least 40% context/output headroom. No card is silently truncated. Oversized cards split into evidence windows with one primary event owner and explicit continuation refs; unresolved joins fail closed.

After P1.5 freezes the final manifest and probability sample, deterministic code computes the exact base-call requirement from P2 lanes, screen shards, independent reference-judgment shards, deepening, admission, and review calibration; P0 owns only the conservative upper plan and user-approved cap policy. The whole P2/P3 route stops before dispatch at the first of the approved call cap, 4 million constructed input tokens (or verified byte equivalent), 400,000 provider output/reasoning tokens, 90 minutes wall time, any provider-dimension cap, or the frozen human-adjudication cap. Initial attempt plus one repair remains the per-item ceiling, but repairs also consume the global pool and vector caps; the three-consecutive cross-item breaker still applies. Reaching a cap, missing a lane receipt, or failing the confidence criterion makes P3 incomplete rather than silently shrinking the denominator.

The 90-minute P2/P3 limit is cumulative active scheduler/provider elapsed time, measured monotonically around preparation, dispatch, wait, validation, and repair; it excludes an explicitly entered human/user-gate wait state. While a human reference-label reserve is pending, label-independent lanes and deterministic work continue unattended within their pre-approved caps; only label-dependent stages enter the wait state (decided 2026-07-16). Human review has its separately reserved per-item/total time and absolute reservation expiry. Neither pause extends the run-root hard expiry: if human work or a user gate remains open at hard expiry without a signed extension, the run follows `expired_incomplete`.

P4 is never implied by P3 approval. For each provider × workload-lane × packet-size × signal stratum, deterministic code computes exact remaining shard counts, uses the one-sided candidate-rate bound, and bootstraps whole successful shards plus the approved bounded retry process to obtain p50/p90 totals for every resource dimension and human review. The forecast explicitly projects downstream admission, `validity_probe`, and `cross_family_review` calls, sanitized projection bytes, and output/reasoning from the candidate-rate bound and the P2 lane receipt — one `validity_probe` call per admission-recommended candidate, scaling with candidates like admission calls (design review T03, 2026-07-18). Historical provider totals and composite scores are excluded. Each proposed full-coverage cap must be at least `F90[d] + O[d]`, where `O[d]` is zero for atomically pre-reservable dimensions and otherwise the explicitly approved maximum in-flight exposure; a user-selected reserve such as 1.20× may be higher but not lower. A lower cap authorizes only a named bounded partial run. Before every dispatch runtime atomically reserves every pre-bounded dimension and proves capacity. Post-receipt-only dimensions default to concurrency one unless the user approves a finite in-flight bound. Forecast drift can trigger one recalibration proposal, never an automatic cap increase.

The review forecast reserves at least one non-empty final P6 conclusion shard/call and its byte/output/human dimensions for every run seeking reviewed status or `extraction_complete` (the `cross_family_review` lane in `R`), even when the candidate-rate bound or final candidate count is zero; a P0-no-route `complete_unreviewed` run reserves no P6 dimension because it will spend none (design review T01/V05, 2026-07-18). Candidate-bearing shards add to that floor.

It seals `pilot_dispatch_ready=true` to those hashes without depending on any P1.5/P2/P3 result, so the gate is cycle-free. Implementation changes are classed (design review R4, 2026-07-16): class A (containment-, privacy-, route-, or egress-touching) requires fresh hash-bound conformance plus a fresh independent cross-family implementation review; class B (semantic contracts: prompts, schemas, screen/judge logic) requires the hash-bound conformance suite, a ledger entry, and a fresh N=1 calibration for affected lanes; class C (mechanical, no contract surface) requires the conformance suite and a ledger entry. The class label is itself an auditable ledger field, defaults to the stricter class, and any dispute escalates to class A. Both readiness receipts (`pilot_dispatch_ready`, `production_dispatch_ready`) bind per-class implementation component hashes over a deterministic component-dependency manifest that maps every source unit to exactly one class and records its dependents; a change's effective class is the strictest class among the changed unit and every unit that transitively depends on it, a unit shared across classes is class A, and any unit with unknown or incomplete dependency lineage defaults to class A (design review V22, 2026-07-17). A class B/C change refreshes its component through its class-scoped re-validation and re-seals the receipt without repeating **unaffected** P1.5/P3 work or the cross-family implementation review; a class-B change to a semantic lane reruns that lane's P2 N=1 calibration and rebinds and re-approves the affected P3.5 lane receipt and forecast (a scoped P3.5 refresh, not a full re-run), while a class A change revokes and requires the full path (design review V08/R6-04, 2026-07-17). Readiness re-seal is orthogonal to result validity: a class-B change to semantic logic (a prompt, schema, or screen/judge contract) alters the bound effective-input hash of every item it governs, so those results do not carry — they open epoch N+1 and replay — even though the readiness receipt re-seals cheaply; a class-B/C re-seal never certifies coverage over results produced by the superseded logic (design review V08/R4-F01, 2026-07-17). Design, route, policy, or cap drift still revokes readiness outright.

P0 content-free helpers/canaries and local P1 work do not require it, and no “calibration” label can bypass it. One exception is narrower, not weaker: before the full independent implementation review closes, the user may sign a `single_item_pilot_authorization` — a distinct receipt the dispatch gate accepts in place of `pilot_dispatch_ready` for exactly one designated P2 N=1 calibration attempt (design review C09/V17, 2026-07-17). The user personally inspects the exact outbound packet bytes; runtime binds the inspected byte hash into the receipt and the write-ahead record and refuses dispatch unless the dispatched bytes hash-match the inspected bytes (design review S10). An fsynced run-level `single_item_pilot_authorization_consumed` invariant is checked atomically before dispatch so at most one such attempt can ever leave in a run — a second attempt under any distinct otherwise-valid authorization emits zero bytes (design review V07, 2026-07-18); every later send still requires the full receipt, and the authorization is a named row in the residual-risk register and an explicit alternative inside the P0.5 predicate (design review S14).

Bounded dynamic chunks use per-item keys binding packet+schema+prompt+model hashes. Medium screen; high deep extraction; atomic pre-dispatch reservations and vector-budget enforcement on every request. An unaffected lane may continue only when its reservation ledger and caps are disjoint and doing so cannot invalidate the shared forecast; otherwise P4 pauses globally. First use a content-free provider status/recovery route keyed by the persisted receipt to recover, validate, and import the original exactly once without resend. A P3.5-approved standing runtime-exception policy may pre-authorize, per provider lane, recovery-first plus at most one exact-effective-input linked resend within a pre-reserved duplicate-exposure ceiling; a qualifying failure takes that path automatically with per-item records, and only failures outside the standing policy require a fresh signed disposition (design review OE-7, 2026-07-16). P4Q first classifies the miss (below); only a diagnosed systematic defect invalidates the screen-quality/P3.5 receipt, the affected provider × stratum screen results implicated by the confirmed miss class in that epoch (whole-provider invalidation only when the miss class cannot be bounded to strata), and every downstream coverage/admission projection that consumed them, and cannot be converted into a P4R transport exclusion or an identical-hash epoch carry; a within-tolerance classification un-pauses the halted lanes and leaves all receipts valid. On a systematic-defect classification, deterministic code freezes the miss and the transitive provenance of every artifact that exposed it into the redesign influence closure. Before any new-epoch semantic dispatch, every prior-epoch affected/dependent attempt and P4R ledger must reach a permitted terminal/reconciled state; an unresolved/cancelled `ambiguous_dispatched` attempt keeps P4Q blocked, while every preserved exposure/reservation and possible late duplicate is carried into the new forecast/caps. The quality miss itself is never a transport exclusion. P4Q classifies the confirmed miss by a defined test (design review S03/T22, 2026-07-17): the within-tolerance branch applies when human diagnosis finds no systematic defect and the exact one-sided bound, recomputed over the probability-audit sample's confirmed misses only (incidental P4-and-later discoveries are repaired, disclosed, and added as regression controls but do not enter that bound), stays at or below `epsilon`; its disposition is repair, disclosure, and a new regression control without invalidating any receipt. The mandatory corrective-delta path applies only to a diagnosed systematic defect; and, as with P6 findings, the user may close a disputed P4Q classification by explicitly accepting the named residual risk. If a redesign allowance is available (the first is included; each further one requires a fresh explicit user gate), a documented corrective prompt/schema/model/validator/analysis-contract delta is mandatory; runtime opens a new analysis epoch and seals that revised contract/influence set. Once the new P2/P3 call/reference manifests are exact, **before any content-bearing revised call** the user must approve their vector caps plus exact local-human count/time reserve, unless an already signed redesign-contingency reserve covers those same hashes and worst-case dimensions. Runtime then repeats the affected `screen`/`reference_judge` P2 lanes, complete influence regression, fresh blinded holdout, and P3; only afterward does a new P3.5 forecast/user approval authorize downstream P4/P6 replay. Every screen item in the invalidated scope is replayed. Downstream items may carry only after the new upstream result validates and its bound effective-input/result hashes are byte-identical; the invalidated screen result itself never carries. If prior attempts cannot reconcile, no corrective delta exists, a redesign was already consumed, a regression/holdout miss beyond the frozen `(n, c)` rule occurs, or the user declines either approval, the run remains `incomplete` and returns to the user. No P5/P6/P7 decision may rely on the invalidated epoch.

After P5 fixes the actual bundle/shard count, deterministic code recomputes review calls/projection bytes/output ceilings against the P3.5 forecast and reservations. Main context cannot downgrade, omit, or close a reviewer-material finding: it remains gating until corrected inputs receive a fresh P6 that no longer finds it material or the user explicitly accepts the named residual risk. 10. `P7 user decision gate` — inspect the complete current-epoch run-conclusion/admission bundle and full review-finding ledger, record one explicit terminal run-level decision on the reviewed conclusion, decide every candidate, and decide every reviewer-material, main-material, or disputed finding with approve/reject/defer/route-to-enforcement or named risk acceptance plus residual dissent per provider × historical-reach audit stratum. A deferred/unresolved reviewer-material finding or run conclusion keeps extraction incomplete. 11. `P8 later implementation` — only on a new approval: edit English canonical, regenerate mirrors/Korean, update relevant benchmarks/implementation map, run parity and behavioral gates, then separately approve deployment.

Every provider attempt uses one write-ahead state machine. Before packet bytes can leave the process, the parent atomically persists and fsyncs a unique dispatch identity, item/effective-input hash, route, packet/exposure hash, declared resource maxima/reservations, and `prepared` state. It then records the observable transitions `dispatching`, provider `accepted` when provable, `result_received`, `validated`, and `committed`; canonical import is a separate atomic transaction. On restart, a provably pre-send attempt may retry, and an accepted attempt with a recoverable validated result imports exactly once without redispatch. If provider acceptance cannot be proved absent and no valid result can be recovered, the attempt becomes `ambiguous_dispatched`: it cannot retry automatically or satisfy canonical completion. A call key is not provider idempotency unless the live route proves that contract. One recovery-first dispatch-exception protocol owns dynamic transitions, but phase authority is explicit: P1.5 may use a signed human boundary judgment; P2 live-route receipts permit only recovery or one exact-effective-input linked resend; a P3 selected card may likewise recover or use one exact-effective-input linked resend, but card/label substitution, adjudication-as-result, exclusion, or absence fails the probability gate; optional deep/admission items and post-snapshot P4R failures may use the P3.5-approved standing recovery-first/linked-resend policy within its reserved ceiling, and beyond it only their separately authorized signed adjudication/exclusion, which remains visible in the candidate/coverage ledger and cannot manufacture a required receipt (design review S09, 2026-07-17). Every signed linked resend atomically moves the original from `ambiguous_dispatched` to `superseded_ambiguous`, preserves its reservation and ambiguous exposure, reserves the worst-case additional duplicate exposure/cost, and creates one linked attempt without rewriting history; cap insufficiency blocks. When phase authority permits a non-recovery human disposition instead, the same transaction moves the original to `superseded_by_human` (P1.5) or the named `adjudicated_ambiguous|excluded_ambiguous` terminal state (optional deep/admission or P4R), binds the signed disposition, and preserves all exposure/reservation history; P4R cancel/leave-unresolved deliberately retains `ambiguous_dispatched` and completion false. A later result from any superseded/adjudicated/excluded original is validated only into `late_duplicate_result` quarantine and can never become canonical or override the signed disposition. Every exclusion preserves attempt/exposure/reservation ledgers and applies the appropriate incomplete/bounded label. Unresolved work stays incomplete. One canonical machine-readable state/transition table is the implementation authority for every attempt, receipt, exception, reviewer-ledger, and cleanup transition named in this document (P1.5, P2, P3, P4R, P4Q, the P6 finding ledger, and cleanup-registry/run-store reconciliation — the two durable stores cross-reference by run id and reconcile at every transition); prose here defers to that artifact, and it ships as code plus fixtures (design review R8, 2026-07-16).

A `late_duplicate_result` remains preserved and non-canonical. It clears its completion blocker only through a signed `noncanonical_duplicate_disposed` transition that validates its linkage/content hash, proves canonical and every downstream effective/result hash stayed unchanged, and retains the duplicate/exposure/reservation audit row; otherwise it remains quarantine.

Each workflow call has strict schema, evidence-bound key, explicit effort, and no `ultra` inside workflow agents. The parent scheduler persists per-item status, limits a poison item to initial attempt + one repair, and trips after three consecutive cross-item auth/limit/transport failures after bounded backoff. Within an unchanged epoch, terminal valid items are never rerun. Every item has an effective input hash binding source/packet, upstream result hashes, schema, prompt, model/route, analysis contract, and the per-item class-B implementation-component hash from the component-dependency manifest, so a screen/judge **logic** change with unchanged prompt/schema/analysis-contract still breaks the carry identity and forces replay (design review V01/T01, 2026-07-17). Source-prefix mutation fails visibly and requires an explicit new census.
