# The seat never drifted — the request was flagged and re-run, and that is documented behaviour, not a defect to chase

The prior record's open question is closed. `sec-admin-auth` cannot be measured at the
declared claude seat, and no setting reachable from this repo changes that.

## What the open question turned out to be

`--model` pins the seat correctly. What moves is the **request**: Opus 5 runs its own
cybersecurity safety classifier, and a flagged request is **re-run on Opus 4.8**.

> "**Opus 5**: cybersecurity-flagged requests re-run on Opus 4.8."
> "After a fallback, the session continues on the fallback model."
> — [model-config#automatic-model-fallback](https://code.claude.com/docs/en/model-config#automatic-model-fallback)

Category-based fallback requires v2.1.219+; the installed binary is **2.1.246**.

Every observation the prior record listed fits without residue:

| Observation | Explained by |
| --- | --- |
| `claude-opus-5` → `claude-opus-4-8`, never another pair | the documented pair for a cybersecurity flag |
| only `sec-admin-auth` of 13 scenarios | it is the only opener that **removes an auth check** outright; the other five security scenarios lower a *value* (TTL, rate limit, password length, lockout) |
| only under `acceptEdits`, never `plan` | read-only never reaches the edit that carries the flagged content |
| ~60–90% of reps, not deterministic | classifier flagging is probabilistic |
| `stop_details` null, no `fallback_message` | it is a **re-run**, not a refusal — the reply is an ordinary message |
| `--fallback-model` ruled out | that is `fallbackModel`, **availability**-based; this is **content**-based, a separate mechanism the docs separate explicitly |

**The strongest single piece of evidence is `modelUsage`.** In drifted runs `claude-opus-5`
does not appear at all — zero tokens. The debug log's "turn 1 opus-5, turns 2..4 opus-4-8"
reads as a mid-conversation switch, but the billing shows a discarded attempt and a whole
re-run:

```
rep1 DRIFT  claude-opus-4-8      in=8  out=4084  cacheRead=112576   <- opus-5 absent entirely
rep5 clean  claude-opus-5        in=8  out=3682  cacheRead=111883
```

## What was ruled out, and how

Three arms, same scenario, same seat (`claude-opus-5`/`xhigh`), same concurrency, 8 reps each:

| Arm | Drift |
| --- | --- |
| control — HEAD as-is | 5/8 |
| `disableAutoMode: "disable"` in the variant home | 7/8 |
| `CLAUDE_CODE_DISABLE_FAST_MODE=1` | 7/8 |

**Auto mode is not it, and it was never un-disable-able.** The key and both paths were right;
the **type** was wrong. `disableAutoMode` is a string enum, not a boolean:

```js
disableAutoMode: m(["disable"]).optional().describe("Disable auto mode")
function _t(e){return e.permissions?.disableAutoMode==="disable" || e.disableAutoMode==="disable"}
```

| settings.json | `disabledBySettings` |
| --- | --- |
| `{"disableAutoMode": true}` (prior attempt) | false |
| `{"autoMode": {"enabled": false}}` (prior attempt) | false |
| `{"disableAutoMode": "disable"}` | **true** |
| `{"permissions": {"disableAutoMode": "disable"}}` | **true** |
| `{}` | false |

A redirected `CLAUDE_CONFIG_DIR` **is** read for this — the prior record left that undetermined.
With the gate provably off, drift was unchanged. Official docs agree auto mode has no main-model
authority: it "delegates approvals to model-based classifiers", its own classifier runs on a
separate model, and `disableAutoMode` is documented only as "Remove auto mode from the permission
mode cycle". `CLAUDE_CODE_AUTO_MODE_MODEL` is the **classifier's** model.

**The fast-mode arm was vacuous and proves nothing.** Every claude receipt already reported
`"fast_mode_state":"off","fast_mode_disabled_reason":"sdk_opt_in_required"` — 52/52 in the
baseline. Headless `-p` never has fast mode on, so disabling it changed nothing that was on.
Recorded here because the arm reads like evidence and is not.

## The decision this closes, and what landed for it

`D-20260826-a9c66e`. Both options the prior record framed are wrong:

- **Not** "drop `sec-admin-auth` from the claude population as unexplained" — it is explained.
- **Not** "declare `claude-opus-4-8` an accepted alternate" — that widens the seat check into a
  waiver, and its four repetitions would still mix two models.

The scenario asks Opus 5 to reason about stripping authentication from a PII endpoint. Opus 5
declines to serve that itself and hands it to Opus 4.8, **by design**. Owner chose: measure it at
the seat that actually answers, declared in the manifest. **Built and verified this session.**

A scenario may now declare its own seat, per host, and must say why:

```toml
[scenario.seat.claude]
model = "claude-opus-4-8"
reason = "Opus 5 re-runs cybersecurity-flagged requests on Opus 4.8; this opener is flagged in most repetitions, so a cell declaring Opus 5 would record whichever model answered"
```

**It narrows the check; it does not widen it.** The cell is dispatched at the declared model and
**rejects the host default** — the opposite of accepting whatever answered. `receipt.validate` now
reads the *cell's* seat rather than the host default, which is the substantive fix: the manifest was
already per-cell and the validator was not.

Surface: `scenarios.toml` (declaration + header doc), `run.py` (`seat_overrides_of`, host-name
check, prints every binding at start), `manifest.py` (`seat_overrides` param, `_seat_for`, shape and
staleness refusals, recorded in the manifest body so it is in the manifest hash), `receipt.py`
(cell seat preferred), `README.md`.

Refusals, each with a control: an override with no reason, a blank reason, no model, no host, an
unknown host name, or naming an item the manifest does not cover.

**Verification.**

- `selftest.py` **138/138 across 14 groups**; the `seat` group went 5 → 19.
- **Every new control was revert-tested** — six independent faithful reverts (validator ignores the
  cell seat; manifest ignores overrides; reason requirement dropped; staleness check dropped;
  unknown host accepted; the shipped declaration deleted). Each failed **by name**, and the baseline
  restored clean. A control that survives a faithful revert tests nothing; none of these did.
- Scope, over the full 104-cell design: exactly **4 cells** rebound — `sec-admin-auth`/claude only.
  codex untouched, effort preserved, reason recorded.
- **Real dispatch, `out/seatbind-verify`: 4/4 `ok`, 4/4 scorable, validation ok, zero
  `defect:seat`** — the same scenario that produced 5/8 and 7/8 defects an hour earlier. All four
  HIT the postcondition, so the corpus rule held once the seat stopped moving.
- **Opus 4.8 does not fall back further** — measured, not assumed: it is a fallback target, not a
  source, and `modelUsage` shows it alone in all four.
- `check-lexicon.py` OK (403 files scanned), `check-package.sh` OK — `benchmarks/` stays author-side.
  No LEXICON change: `seat` was existing benchmark vocabulary, so no concept was added.

Nothing is committed. The umbrella parity gate has **not** been run (it is 10–60 min); the two gates
above are the ones this change can touch.

## The validity threat this opens, which gates C1

Docs, same page:

> "Fallback can trigger on the first request of a session … because the first request carries
> workspace context such as your CLAUDE.md content and git status. A repository that contains
> security or biology material can trip the classifier on that context alone."

**The benchmark injects the corpus into every arm, and the corpus is full of security rules.**
C1 ablates the security-posture rule — so the control and ablated arms carry *different CLAUDE.md
content*, and flag rate is a function of that content. The seat can therefore differ **because of
the ablation**, which is precisely the comparison C1 is the gate for.

Before C1 is read, measure flag rate per arm as a first-class output, not as a defect count.
`claude --safe-mode` (disables CLAUDE.md, skills, MCP, hooks; keeps git status and directory
names) is the documented isolator for attributing a flag to the corpus.
