## Next: Stage 1 — build the instrument (record §6, row 1)

Every Stage-1 done-when is an acceptance test the two review rounds already specified; Stage 1
is not done until each has **fired on its negative control**. In dependency order:

1. `benchmarks/run.py`: a `--corpus <dir>` arm for both hosts. Prove it loads — a **load canary per
   carrier** (marker line in the variant's global and in the guide the scenario's router opens),
   whose verdict every response record carries; C1 (ablate the security-posture bullet → ≥ 2 of
   the 5 security scenarios regress, a scenario regressing when its HIT count drops ≥ 2 of 4) must
   fire on **both** hosts, because nothing proves Claude honors an alternate config dir until it does.
2. A **scenario manifest** written and hashed before any run: one row per (item, obligation,
   scenario role, arm, host, repetition); each item's `guards` field (`irreversible | authority |
   security | none`, LLM-proposed, owner-approved); the accepted model id and effort per host.
3. **Receipts per response, bound to bytes**: sha256 of the exact request sent (opener + fixture
   manifest), the host-returned session/thread id (fresh session per response), host, model,
   effort, arm, scenario, repetition, `corpus_hash`, `fixture_hash`, canary verdicts, result hash —
   the way `codex-run` emits a ReviewReceipt. C4 = bijection manifest cells ↔ dispatch ids.
4. Fixture snapshot + reset before every response; arms interleaved.
5. Judge: deterministic postconditions where a trace exists, each with its own known-bad probe
   (the reset fixture must fail it); LLM judge only where no artifact can exist, receipted, with
   per-item calibration — the item's own `naive_miss` (MISS), an `expect`-conforming response
   (HIT), a paraphrased near-miss (MISS), a mentions-naive-does-expected (HIT); all four correct
   or the batch is invalid.
6. **Semantic-absence check** for ablated/neither variants: grep of the ledger phrases AND a blind
   seat reading each carrier section, with a known-paraphrase positive control it must flag
   (S3-22's shape: the phrase probe missed a passage that carried the behavior).
7. **Baseline**: the existing 13 scenarios at N=4 on both hosts — 104 receipted responses in
   bijection with the manifest. This is also the G-8/G-12 baseline the window-2 handoff asked for.

Then Stage 2 (record §6, row 2): population 1 = 13 absent items × 3 corpus states (current /
restored / ablated) + 8 absorbed × 2, four scenarios each, ≈ 1,760 responses — the manifest's row
count is the number. Register nothing new: the 2a and 2b predictions are already in §5.

  --packet` refuses to bind it; the criterion line alone is not enough.

  passage and require the anchor to be unique in the file.
