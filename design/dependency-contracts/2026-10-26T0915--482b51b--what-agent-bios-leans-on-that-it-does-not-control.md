# What agent-bios leans on that it does not control, judged by the contract it relied on

## Why this exists

AGENTS.md §12 (decision D-20261026-56c103) classifies every failure by the contract the failing
code relied on. The contract sources are fixed in advance: POSIX and the macOS headers and man
pages, the Python standard library documentation, a host CLI's official documentation and its
`--help`, and this repo's design records. The rule only helps if the dependencies are known
before a failure, so the owner asked for an inventory of every place the repository depends on
something it does not control. This record is that inventory at one point in time. It is the
input to the contract-fix work package that follows WP-07 package A (decision D-20261026-7fce2a).

A row is **inside** when the relied-on behaviour is stated by its contract, **outside** when it is
not stated or the contract states the opposite (ours to fix), **none** when no contract exists for
the thing at all (then validating the input and refusing a drift by name is ours), and
**unknown** when the pass could not establish it.

## Scope and method

Three independent read-only passes over `feat/distill-redesign` at `856d6bb`, one per kind of
dependency: A, external programs (the `claude` and `codex` CLIs, the desktop apps, git, npm,
Python, bash, zsh, zstd, PowerShell); B, host-owned data formats (transcripts, host
configuration, host caches and indexes); C, operating-system mechanics (pipes and child I/O,
processes and signals, files, locks, temp directories, environment, platform splits). Each pass
enumerated its sites by grep first, judged each helper once, and quoted its contract with the
location. Coverage was complete for the shipped code (`package.json` `files[]`) and for
`session-distill/runlib`; `gates/`, `decisions/` and `.githooks/` were sampled. Every statement
in the appendices carries its provenance mark. No host data, credential or transcript was
opened; formats came from the repository's fixtures, code and design records and from published
documentation.

## Lead rulings on the passes

- **C-1 is inside, not outside.** `wrappers/codex-helm.sh:388` pipes the prompt into
  `codex-run.sh` and then `codex exec`, whose `--help` states that the instructions are read
  from stdin when no prompt is given (or `-`), and that a piped stdin is appended to a given
  prompt. A reader that reads makes the writer wait when the pipe is small, never fail; only a
  reader that exits 0 unread produces the SIGPIPE, and that reader breaks the CLI's own
  contract. The 2026-10-25 failures were the gate's fake doing exactly that (fixed in
  `4e3659b`). The wrapper is not changed.
- **C-2's environment claim is corrected.** This author's session runs with
  `LANG=en_US.UTF-8`, so the five-token assumption holds here today. Under `ko_KR.UTF-8`,
  `ps -o lstart=` prints seven tokens; the lead reproduced it on this machine. The defect stands
  for any operator whose shell has a Korean (or other non-C) locale.
- **Checked against the artifact by the lead:** A-1 (the versions directory holds 2.1.306,
  2.1.307, 2.1.309 and 2.1.310; `session-distill/seats.json` pins 2.1.304), C-2 (`stop.py`
  `ps_table` sets no locale), C-3 (`mktemp -t <word>` at `install.sh` 910, 1179, 1499 and
  `gates/check-parity.sh` 227; GNU behaviour from the GNU manual, not run on Linux), C-4
  (`codex_frame_filter.py` `select()` on a `text=True` stream, then `readline()`), and the vendor
  sentence on transcript records (quoted independently by passes A and B). The other rows are as
  each pass reported them.
- `install.sh`'s `mktemp -t` form is on `main` and on this branch, not in the published 0.19.3
  (no occurrence in that tag), so no released user reaches C-3 yet.

## Patterns across the passes

1. **The fakes answer for the hosts, and nothing compares them.** The gates' host doubles
   (A-37, B-16) restate a host version's behaviour; a green umbrella after a host release proves
   only that the wrappers handle the old shape. The 2026-10-25 helm failures were this pattern.
2. **Version drift is recorded and never judged.** `DEPENDENCIES.md` records Claude 2.1.304 and
   Codex 0.153/0.154 as verified; 2.1.310 and 0.163.0 are installed, and nothing warns.
3. **The fix often exists in another copy.** C-2 (`LC_ALL=C`), C-3 (the portable `mktemp` form
   used by the hook and the wrappers) and C-4 (reader thread and queue in
   `instructions_session.AppServer`) each have their correct shape elsewhere in the tree.
4. **"None" rows fail in three ways.** By name (A-1, A-6, A-23, ZSTD, B-7, B-9): correct.
   Misnamed (B-4, B-10, C-4): the operator looks in the wrong place. Silent (B-2, A-10, A-11,
   A-5's missing directive): the criterion's one forbidden outcome.

### The five rows I consider most consequential

1. **A-2 — Codex `app-server` is the load-bearing surface for private Codex activation and for codex-run's context evidence, and the vendor labels it "experimental … not supported for production workloads" / "may change without notice".** Six names the code depends on (`developerInstructions`, `experimentalRawEvents`, `thread.path`, `config/read` `includeLayers`/`layers`, `hooks/list` `cwds`, the `sessionFlags` label) are not in the documentation read. The failures are loud when a method disappears, but a field that merely goes empty (`developer_instructions`) silently drops the user's own instructions from the composed session. This is the clearest case of "relying on the thing is itself outside contract": the right move is either a version pin + refusal-by-name (as codex-run already does for its capture) on this path too, or a design decision to accept the surface explicitly.

2. **A-1 — `seats.json` pins a Claude binary path the vendor never promised and that is already gone on this machine.** `~/.local/share/claude/versions/2.1.304` no longer exists (only 2.1.306–2.1.310 do); the next distill dispatch on the Claude side will refuse with `HOST_BINARY_UNPINNED`. The refusal is correctly loud and named, so the code is on the right side of the owner's criterion — but every re-pin re-measures a flag-set hash and a host allowance, and nothing warns before a run starts. This also means the hermetic flag set's "measured on 2.1.304" evidence can no longer be re-run on the binary it was measured on.

3. **A-3 — Claude transcript parsing is explicitly disclaimed by the vendor ("changes between versions … can break on any release"), and four shipped readers plus the hermetic evidence helper depend on it.** The hermetic review's proof of cleanliness (`host.json`: which instruction files loaded, which system prompts were appended) is reconstructed from `api-request*` records that the vendor does not document. The reader fails loudly on a missing field (status 70) but not on a field that keeps its name and changes meaning. B owns the shapes; the decision here is whether a disclaimed format may carry evidence at all.

4. **A-5 — The only evidence naming the model that actually answered a Codex call comes from `RUST_LOG=tungstenite::protocol=trace` stderr lines that the code itself calls "unsupported and version-bound".** The mechanism (`RUST_LOG` honoured) is documented; the target names and line grammar are internal. The adapter only warns when the directive is missing, so an upstream rename yields a capture with no frames and a receipt that adjudicates UNKNOWN without naming the cause as a drift.

5. **A-8 + A-9 — Two holes in what "hermetic" promises for Claude.** `--setting-sources ""` has no documented meaning (A-8), and `--safe-mode` is documented to keep "managed settings policy … including policy-configured hooks" (A-9), which the P5 ancestry check cannot see because managed settings live in a system directory. On the owner's machine both are dormant; as a property of the claim the receipt makes, they are the gap between "measured clean on 2.1.304" and "guaranteed clean".

Runner-up: **A-11** — the zsh wrapper's six-verb exception list is a frozen measurement of 2.1.280; a new background-session verb typed bare would start a permission-bypassing session with the verb as its prompt, silently.

### The five most consequential rows

1. **B-4 `wrappers/claude_hermetic_evidence.py` (shipped).** It reconstructs sent requests from `api-request`/`api-request-shape`/`api-request-blob` records and the loaded context from `attachment` records — none of which appear in any published page, while the sessions doc states the transcript format "is internal to Claude Code and changes between versions, so scripts that parse these files directly can break on any release." `DEPENDENCIES.md` already pins this reliance to 2.1.304. When a record kind is renamed the helper returns empty context and the gate refuses every dispatch for a context mismatch: fail-closed, but the failure names the call rather than the drift, so an operator will look for a packet error first. This is the clearest case of relying on something no contract promises; by the owner's criterion the missing piece is ours — validate the record kinds seen and refuse by name ("transcript carries no `api-request` records on <version>") instead of returning empty lists.

2. **B-5 stream-json fields beyond the SDK schema.** `result.api_error`, `result.safety_stops`, `system/status requesting`, `rate_limit_event`, and the exact cap-overrun sentence drive the breaker (usage-limit and output-cap recognition) and `seats.json`'s cap evidence. The SDK reference lists `is_error`, `api_error_status`, `terminal_reason`, `stop_reason`, `structured_output`, `modelUsage.contextWindow` — a solid base — but not those. The breaker reports unknown signals as `unrecognised` (good), while `cap_overrun` silently stops recognising a cap (bad). Moving the cap recogniser onto documented fields (`api_error_status`, `terminal_reason`, `stop_reason`) or naming its own drift would bring it inside.

3. **B-6 Codex rollout records.** `session_meta.payload.source/originator`, `response_item`, `event_msg.token_count`, the `.jsonl.zst` convention and the `_`-in-stem continuation rule have no published description at all; the shapes come from the host's Rust source and the 2026-10-20 probes. A renamed field moves every Codex session to `unknown_provenance` (visible) or silently drops human turns (lineage links vanish). The per-source counts in every run record are the only alarm; a one-line "shape check" on the first record (`session_meta` with `id`, `source`, `originator`) refusing by name would separate drift from genuinely unknown provenance.

4. **B-11 Codex trace frames under `RUST_LOG=tungstenite::protocol=trace`.** The wrapper's own docstring calls the channel "unsupported and version-bound", yet it is the only source of which model answered and per-request usage for Codex, and the receipt gate refuses without it. The handling is already fail-closed and named (`frames_blind`, `unresolved`), so the exposure is availability, not correctness: any Codex release that changes its logging halts Codex dispatch until the reducer is re-derived. The decision to make is whether Codex accounting may depend on a debug log at all, and if so, to pin the exact `codex` version in the run declaration (it is: `seats.json`/`hosts.codex`) and treat a version bump as a re-measurement obligation, which `declare.py` already enforces for S1.

5. **B-10 model-catalogue caches gate publishing.** `~/.claude/cache/model-catalog/*.json` and `~/.codex/models_cache.json` are undocumented, per-account caches, and `--publish-guard` refuses a release when a catalogue reads as absent. A shape change therefore blocks `npm prepack` with the message "no catalogue on this machine", the wrong cause. The structure half is sound; the currency half should either name "catalogue present but unreadable in the shape this gate expects" separately from "no file", or be excluded from the publish guard. Honourable mentions: **B-2** `session-cost.py` is shipped and user-facing and prints `$0.00` silently when a usage key moves; **B-7/B-9** the host indexes are called undocumented by the repo's own design and are handled by name already.

### The five most consequential rows

1. **C-2 — `stop.py` cannot verify any stop under a non-C locale.** The owner's machine is the case (Korean locale → 7-token `lstart`). Every listing becomes "no evidence", so the freeze/kill verification that design §13.2 rests on reports unverified on every call, members outside the root's group are never signalled, and the message blames the listing. The one-line fix is already in the repository's other copy of the probe (`instructions_setup_cli.py:124-126`: `LC_ALL=C`). Ours.
2. **C-3 — `mktemp -t name` breaks `install.sh` on the Linux the package declares.** It aborts `cmd_install` after the files are deployed and before the status projection, and the EXIT trap then restores the previous manifest over the new install — the exact "destructive command reporting success" the trap was written to prevent. No Linux run of `install.sh` exists in CI. Ours; the portable form is already the house style in the hook and the wrappers.
3. **C-1 — `codex-helm.sh` still writes the prompt into a pipe whose capacity POSIX does not promise.** The 2026-10-25 fix changed the gate's fake, not the wrapper; under pipe-memory exhaustion (environment) the helm exits 141 with no message (ours: the failure neither names its cause nor avoids the reliance). `codex-run.sh`'s capture path already shows the shape that does not rely on capacity (packet to a file, C-30).
4. **C-4 — `select()` over a buffered stream in the Codex capture path.** No contract covers a line already in Python's buffer; the symptom is a 60 s stall ending in `effective-context evidence failed; refusing to dispatch`, attributed to codex. The thread-and-queue shape that is immune is in `instructions_session.AppServer`. Ours.
5. **C-6 — the stop boundary is judged on `time.time()`**, whose documentation states it can go backwards. A clock step during a call silently misjudges `STOP_BOUNDARY_*`. Deadlines already use `monotonic`; the record needs both stamps or a step flag. Ours (silent misjudgement is the one failure mode the criterion forbids).

Close behind: C-5 (an inherited idle stdin hangs `codex-helm --dry-run`; fixed in two callers, asserted for none) and C-16 (every blocking `flock` writer has no deadline, so a wedged holder hangs the installer, launcher and decision recorder without a message — inside contract, but it fails the "neither hangs" half of the criterion).
