## Where the fix departs from the reviewer's proposal, and why

- **#9.** Of the two offered remedies the entry is REFUSED at save rather than
  carried, against the carry-through precedent (`D-20260816-77afa8`,
  `D-20260817-105da4`) — because here there is no home to carry it to, measured
  rather than assumed. `tier_overrides` host keys are closed to the launchable set
  by `build_plan`, so normalizing it there makes the saved preset unloadable; and
  a `frontier_effort` map that omits the launching host resolves that host's
  frontier effort to None, so re-emitting only the residual keys makes the preset
  unloadable on *both* hosts (`{'future':'high'}` and `{'codex':'ultra'}` each
  raise `unsupported effort for balanced.frontier: None` from claude). Re-emitting
  the whole map puts every launchable host's value in two homes, which is what
  `D-20260817-76ecd1` closed. That leaves the one case `D-20260817-105da4` keeps a
  named refusal for. Recorded as `D-20260817-53c588`.
- **#8.** Of the two offered remedies the value is preserved to the renderer's
  `_table` door rather than refused inside the normalizer. The host-block branch
  three lines above already states that rule in the same words, and the renderer
  produces the identical sentence its workhorse twin arrives through; raising in
  the normalizer would give one rule two owners and two spellings. Recorded as
  `D-20260817-89fc58`.
- **#4.** One PREDICATE is shared by the three result-hash sites; the per-site
  diagnoses are not merged. Round 23 deliberately separated "records an empty
  result, so nothing was actually reviewed" from "is not a SHA-256 hash", because
  one is a claim about what the reviewer produced and the other about the field
  being a digest at all. Recorded as `D-20260817-16602f`, together with the
  consequence that the fold's use of the shared predicate is single-sourcing with
  no independently observable behaviour.
- **#1, beyond the proposal.** The snapshot lives on the ROW, beside `controls`,
  and is required rather than optional — including its complement, that a DROPPED
  row reports no evidence. `check_adapter_command` authors `"evidence": []`
  explicitly for the same reason it authors its controls: the bar a record is
  adjudicated against is stated in the record, never defaulted.
- **#6, beyond the proposal.** The SELECTED host's model resolution was routed
  through the same helper too. That call is single-sourcing rather than a door —
  reverting it alone changes nothing observable, which was checked rather than
  assumed — and it is what makes "the same override rule" true of the code rather
  than of a comment.

## What the reverts taught

- **A control that never reaches the code is green about nothing.** #8's case was
  written with the inactive host's frontier effort equal to that host's default,
  so the normalizer returned before it ever touched the malformed block: the case
  passed with the fix reverted. It only became a control once the effort was
  DERIVED as "any effort this host supports that is not its default" — which also
  keeps it from going quiet the day the shipped default moves.
- **Reverting one door can leave the case failing by a NEIGHBOUR's message.**
  With #2's door alone reverted, the wrong offer is selected and #1's drift
  comparison then refuses the disagreement it produced — a true verdict reached
  through a false step, with the operator sent to the registry instead of to the
  provider their plan names. The assertion now separates "adjudicated anyway" from
  "refused by the wrong door", and the paired revert (#2 with #1c) shows the
  defect itself: the row is adjudicated, `complete`, exit 0. The same shape
  appears inside one reader for #3a and #3b, where each case is graded on its own
  needle and is separable for exactly that reason.
- **A probe stops discriminating the moment the shape it was written against
  moves.** The reviewer's #1 and #2 probes build a plan row directly, so after the
  fix both arms — mutation and control — hit the new "the record predates the
  declaration" door, and the pair said nothing. Re-running them required a
  launch-faithful row carrying the snapshot; with that, the mutation is refused by
  name and the control is byte-for-byte what the reviewer recorded. A probe
  written for the old shape is not a control for the new one, and reading its
  refusal as agreement would have been the easiest mistake available here.
- **A mutation can fail to reproduce because the ENVIRONMENT differs, not because
  the finding is wrong.** #5's mutation forges `best_grade=provider_difference`
  over the shipped `balanced` preset — which in this checkout already derives
  `provider_difference`, so mutation and control printed the same line. The defect
  is real and was reproduced on a report whose rows genuinely reach the floor,
  giving exactly the reviewer's output. The reviewer ran read-only, where the
  codex seat degrades; nothing about the finding depended on that.
- **Not every hunk of a fix is a door, and saying so is part of the record.**
  #6's selected-host call and #4's fold-side use of the shared predicate both
  change nothing observable when reverted alone, because a neighbouring guard
  precedes them. They are single-sourcing — the thing that stops the two branches
  from drifting apart later — and claiming a control for them would be the "guard
  whose only proof is another guard" trap wearing the opposite costume.
