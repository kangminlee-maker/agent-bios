# Task-based visual decisions belong in a scoped UI guide

Operational interfaces need to keep a worker's task, evidence, authority and
continuation context understandable. The UI design guide combines those needs
with an explicit visual decision procedure. It preserves the product purpose:
workers can use team standards and continue shared work without conflating source
ownership, selection, approval, execution or actual recipient use.

## Adopted scope

`@agent-bios/core:guide-ui-design` is one `builder-base` relevant item. Its primary
body is `claude/guides/ui-design.md`; `ui-design/visual-direction.md` is a member
of the same guide. The primary is independently usable and consults the companion
when a new visual direction or material arrangement decision remains unresolved.
The existing staged development guide supplies a conditional entry point. The
canonical always surface is unchanged.

The guide asks typography, alignment, spacing, color and boundaries to express
task-relevant relationships. It does not impose a product palette, fixed pixel
scale, panel count or blanket card prohibition. Reading/review, repeated record
comparison, selection-driven editing, and input/result confirmation select their
own patterns. Small corrections retain a proportionate completion path.

English is the catalog source. Korean explains the same criteria. Host mirrors
are generated by the existing projector. Selection includes both guide members;
it does not imply a session was activated or a model followed the guidance.

## Reference basis and evidence limits

The reference study used official product and design-system material, including
[Linear's 2026 refresh](https://linear.app/now/behind-the-latest-design-refresh),
[Primer layout](https://primer.style/product/getting-started/foundations/layout/),
[Carbon tables](https://carbondesignsystem.com/components/data-table/usage/),
[Atlassian elevation](https://atlassian.design/foundations/elevation), and
[Pajamas tokens](https://design.gitlab.com/product-foundations/design-tokens/).
These support reusable design hypotheses, not a claim that a style identifies
AI authorship or that a particular palette improves every task.

The user reviewed an author-composed rendering with constant content and actions
under token and region-arrangement variants, then approved creating Instructions.
The rendering was an exploratory visual-factor study, not an independently
generated instruction-treatment experiment. Visual preference and observed task
performance remain separate evidence. Customer inputs, raw model runs, personal
paths and preview assets are not part of this publication.

## Supporting verification corrections

The legacy assembler's guide-count checks now count top-level primary files.
Same-stem companion directories are members of a guide, not extra guide items.

Checker reachability distinguishes one exact historical checker from current
automatic gates. A tracked historical subject must have its original plan's
content binding, regular files, a reason for retention, and a different current
checker selected by active prose. Changed bytes, missing/duplicate bindings,
symlinks, current/live reuse and neighboring orphan gates remain failures.
Comments and code examples cannot establish the current selector.

This classification is intersected with the index's checker subjects before
loading historical records. A clean publication without those author-side
records therefore needs no unpublished archive. If that checker is later
included, all provenance guards apply. Independent synthetic controls always
run, including when no historical subject is selected.

## Validation contract

Verify the selected item's two members, authored router description, private
member paths and snapshot integrity for both supported hosts. Exercise selection
and deselection and require a modified companion to fail verification.
Run the existing catalog/store/session tests, assembler scenarios, package and
mirror checks, and the required commit hook against the staged tree.

This record states the design and validation contract. Completed command results
