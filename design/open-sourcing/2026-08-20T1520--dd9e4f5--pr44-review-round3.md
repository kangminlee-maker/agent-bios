# Round 3: the same seam leaked a third shape, and the fix for round 2 killed records

Round 2 reviewed the first fix delta and found it had introduced two regressions.
This round reviewed the second fix delta (`fd2e8b1..dd9e4f5`) on the same two
lenses. Both found real harm again, and the pattern is now the finding: **a fix
delta is where defects come from**, and one seam in particular kept leaking.

| Lens | Reviewer | Findings |
| --- | --- | --- |
| Regression | fresh-context frontier agent | 1 regression + 2 latent |
| Contract-first | gpt-5.6-sol @ max, schema route | 12 (2 already closed mid-round, 10 live) |

## The seam that leaked three times

Every round, the slot claim was expressed as *"does this look like a usable
file?"*, and every round a state answered False that was not "absent":

| Round | Test | What answered False that should not have |
| --- | --- | --- |
| 1 | `is_file()` | an EACCES at or above the slot → silent legacy fallback |
| 2 | `{"token","ingest-url"} & names` | uppercase names on a case-insensitive filesystem |
| 3 | `is_file()` again | a dangling symlink, a directory, a readable-but-untraversable dir |

The third round stopped patching shapes and split the question, which is what the
first two should have done:

- **Existence** is `os.lstat` — no symlink following, no type judgement. Something
  is there, or `ENOENT` says it is not.
- **Shape** is `is_file()`, asked only after the slot is already claimed, and a
  failure is loud with the file named.

Absent → legacy. Anything else present → claimed, and any non-file among them is a
named failure. All four shapes now go through their own door, and the gate holds
the promise too (`leg_default` grew a dangling-symlink probe).

## The fix for round 2 was killing records

`UNSENDABLE` was introduced in round 2 so a record that can never be serialized
settles instead of wedging the queue. It lumped two different causes together, and
the contract lens found the cost: a **base** urllib cannot use — a 64-character DNS
label, an unparseable port — also returned `UNSENDABLE`, so every queued record
died permanently. Fixing the URL afterwards could not recover them.

The model is now explicit about whose fault it is:

- **The record** cannot be serialized → `UNSENDABLE` → settles like a `400`, the
  queue keeps moving.
- **The configuration** cannot be used → transient, records survive the fix — and
  it is refused up front anyway: `invalid_base` now rejects an unencodable host and
  a port urllib will not parse, and `transport_config` rejects a token that cannot
  be a header value, each naming its file.

`http.client.InvalidURL` inherits from both `HTTPException` and `ValueError`, which
is why the base case was reaching the wrong clause at all; the body is now encoded
before the request is built, so the two causes are separated by construction rather
than by exception taxonomy.

## The rest, by class

**Reasons that did not name what failed** — both slot files were read in one `try`,
so a decode error could only say "something in the slot". One read per file now.

**Controls that could not fire** — the hostname requirement (no fixture had a netloc
without a host), the `ValueError` catches on config reads (no fixture was invalid
UTF-8), the budget boundary (only the far side was tested, so a deadline widened to
"will probably overrun" passed), `browser` and array-`bin` force-includes (this
package declares neither), and the structural status-literal scan (its only
mutation was independently caught by the wire probe). Each has its own control now,
and three were revert-proven.

**Instruments that died with their subject** — the UTF-8 controls crashed alongside
the crash they were testing for, so the self-test reported a traceback rather than a
named failure. They catch the exception and turn it into a reason string.

**Gate hygiene** — the structural scan's region ran past `classify_status` into the
next class (a `3xx` in an unrelated docstring would have failed the gate) and is now
bounded to its own body with docstrings stripped; the self-test's scratch tree is
removed on every exit path, including the `SystemExit` a stale mutation source
raises; the fixture recognizer accepts a port after a `.test` host while still
refusing `evil.example.com:1234.test`; a dead parameter is gone.

## Judgement on continuing

Three rounds, three deltas, three findings-of-substance. The rate is not falling
because the reviews are weak — it is falling because each round's fix is the next
round's subject, and this seam was structurally miscast until this round. The
existence/shape split is a change in kind rather than another patch, and the
record/config split does the same for the settle model. That is the point at which
the staged-workflow guide says to stop patching instances: both root causes are now
addressed at their authority, so the next round would be reviewing a delta of
controls rather than a delta of behavior.
