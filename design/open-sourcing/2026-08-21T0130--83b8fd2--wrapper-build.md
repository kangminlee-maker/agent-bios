# Step 3 built — the organization provider left the core, and the shape it left in is repeatable

Roadmap step 3 (`2026-08-19T1713--7d37b87--frame-critique-roadmap.md`): the
`day1-agent-bios` wrapper, this machine's migration, and — decided in the same
session — removing the legacy provider from the core immediately after, rather
than as a follow-up.

The user reframed the opening question before it was answered. Not "how does the
wrapper carry day1's transport" but **"what is best if other organizations take
the open source and set it up themselves"** — which changes the answer, because
the day1-shaped options stop being admissible.

## The split that decides everything

Two values, two natures:

| Value | Nature | Home |
| --- | --- | --- |
| ingest URL | organization CONSTANT — not secret, reviewable, versioned | the wrapper's `org.json`, travelling with a wrapper release |
| token | per-user SECRET, issued differently by every organization | resolved at run time, never committed |

Every rejected option collapsed one of those two into the other. Copying the
dashboard's hook-dir layout into the wrapper hard-codes day1's token *mechanism*
as if it were the contract. Symlinking the slot at the dashboard's files makes
the core's slot a pointer into another product's state and blurs who owns it.
Both work for day1 and neither survives a second organization.

So the adoption surface is one file:

```json
{ "org": "your-org",
  "ingest_url": "https://ingest.your-org.example",
  "token_files": ["~/.config/your-org/token"] }
```

## What exists now

**`day1-agent-bios`** (`~/Documents/day1-agent-bios`, committed locally at
`202756c`; the GitHub repo is NOT yet created — see Open below).

- `bin/day1-agent-bios` — claims BOTH bin names (`day1-agent-bios` and
  `agent-bios`), refreshes the slot, then `exec`s the pinned core's
  `install.sh` with the arguments untouched. `setup` and `update` are
  intercepted; everything else forwards.
- `lib/provision_slot.py` — token resolution (`$AGENT_BIOS_TOKEN` → the
  organization's `token_files` → a terminal prompt under `setup` only), slot
  writing at 0600 under a 0700 directory, and **validation by asking the pinned
  core's own `transport_config` to accept a staged copy** rather than restating
  its acceptance rules. 17 self-test checks, 4 of them negative controls.
- `test/e2e.sh` — the real path end to end: wrapper writes the slot, the core
  resolves it, a real capture POSTs to a loopback ingest. Asserts the request
  path, token header, content type, record body, and record count.
- `package.json` is `"private": true`, so npm refuses to publish it. That is the
  D-20260819-949d79 "never on any registry" decision made structural instead of
  remembered.

**The core** now resolves the slot and nothing else. `transport_config` lost its
`home` parameter along with the fallback — a parameter no branch reads is worse
than the branch. `ENDPOINTS.md` §Transport configuration states the adopter's
obligation as the contract; `gates/check-endpoints.py` grew two legs (a
dashboard-shaped decoy hook dir must still resolve nothing; the resolver's own
source must name no hook directory) with two new planted controls, 68 total.

## The measurement that overturned a recorded decision

D-20260819-949d79 says the wrapper "is installed as a git dependency". Probed
before building on it:

```
npm error code EALLOWGIT
npm error Fetching packages of type "git" have been disabled
```

**npm 12 ships `allow-git = "none"`.** Valid values are `all | none | root`;
`--allow-git=root` covers a top-level git spec, `--allow-git=all` also covers a
git dependency of one. With the flag, the private repo installs in ~8 s and the
nested core arrives intact (verified in a throwaway prefix, both shapes). The
decision survives; its install line does not, and now carries the flag.

Also learned in the same probe: npm 12 blocks lifecycle scripts by default
(`allow-scripts`), which the core's postinstall message hits harmlessly.

## Traps this session paid for

- **A wrapper checkout beside an agent-bios checkout resolved the neighbour as
  its pinned core.** The hoisted-dependency fallback (`../agent-bios`) is only a
  hoist when the parent is a `node_modules`; without that condition the wrapper
  validates against a version it does not ship. Caught by its own self-test
  crashing on a signature that only the clone had.
- **`case` inside `$( )` closes the substitution at its first pattern `)`.** Five
  end-to-end assertions reported FAIL for a syntax error, not a defect.
- **A positional argument silently changed meaning.** Dropping `home` from
  `transport_config(home, slot_root)` turned every `transport_config(x, slot_root=y)`
  call site into a `TypeError` — loud, and that was luck. `gates/test-install-guides.sh`
  passed the host home positionally *while relying on `$HOME`*; had the signature
  kept two parameters, that probe would have quietly measured the wrong tree.
- **A check that cannot fail.** The first version of the core's "no organization
  provider" self-test asked the resolver about a hook dir it no longer receives
  — structurally unable to fail. It was moved to the drain, where a re-added
  fallback really would resolve and send, and then proven by re-planting the
  fallback.

## Open

1. **The GitHub repo does not exist yet.** `day1co/day1-agent-bios`, private.
   Creating it is an outward action and waits on the user.
2. **The core pin is `github:day1co/agent-bios#83b8fd2`** — one commit behind the
   change it needs. Bump it to the merge commit of this branch, then to an exact
   npm version once the core publishes (which drops the install flag to
   `--allow-git=root`).
3. **This machine keeps the core's npm global install**, so `agent-bios` on PATH
   is still the published 0.13.0, not the wrapper. The slot is written and inert
   until a slot-aware core is deployed; switching the bin means removing the
   global core first. A developer machine may deliberately not want that.
4. **Name defence** (frame-critique item 7) is unresolved: git-ref installs never
   touch a registry, but `npm i day1-agent-bios` typed by hand reaches an
   unclaimed public name. Reserve it or scope it.
5. `learn/collect-learning.py` no longer reads the dashboard hook dir, but the
   dashboard still writes it — the session collector needs it. Nothing to do;
   noted so it is not read as leftovers.
