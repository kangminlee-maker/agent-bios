## What the two defects were

**T5.1** — `httpGetConditional` resolved for any 2xx, and its caller installs the
returned body over the poller's own `__filename`. A 206 from a range-serving
proxy delivers a prefix; cut after a complete statement it carries no placeholder
sentinel and passes `node --check`, so it cleared every guard `selfUpdate` has.
The installed body has no `main()`, so that machine collects nothing and can
never update again — the code that would fetch the next version is what the
prefix truncated away. 203 is RFC 9110's "transformed by an intermediary": the
same hazard, declared.

**T5.2** — Node's `timeout` request option is an inactivity timer, not a
deadline. A response sending one chunk every four seconds resets it forever, and
the only remaining bound is the 12s `HARD_TIMEOUT` that kills the process.
`main()` awaits `selfUpdate` before any session POST, so one trickling response
ends every scan before a single session is sent.

## The one the repair itself created

Round 5's runtime packet found it, and it was reproduced here before being
fixed rather than taken on the reviewer's word. The T5.2 fix added
`req.on("close", clearDeadline)`. On a peer that sends headers and then drops the
connection, neither `end` on the response nor `error` on the **request** fires —
the ECONNRESET arrives on the response object, *after* the request's `close`. So
the handler cleared the timer and nothing settled. Measured on node 26.0.0:

```
response 200 -> data:abc -> res-aborted -> req-close -> res-error:ECONNRESET
settlement: pending
```

The success ordering was measured too, because the fix depends on it — `RES-END`
precedes `REQ-CLOSE` for both GET and POST — so promoting `close` to a settle
path cannot turn a good exchange into a rejection.

## Round 6 said the same thing three times, so the answer was not another control

Its three findings were one shape: the guarantee lived in two copies (`postJson`
and `httpGetConditional`), so every promise needed two controls and one was
always missing. 201 survived P1. The POST premature-close survived P7. The POST
size cap survived P3.

Patching each would have refilled. The exchange is now single-sourced as
`performRequest`, with only the status policy left per caller — the one thing the
two genuinely disagree about. Those policies are named
(`classifyScriptResponse`, `classifyIngestResponse`) so a test can sweep their
whole domain instead of sampling it. **Enumerating statuses in a control is a
refilling queue: 203 survived one round, 201 survived the next.** The sweep runs
100–999, which is what `res.writeHead` accepts.

## Controls: eleven planted, eleven dead

The battery now emits a receipt, because round 6's first finding was that the
previous one had none for the tree it claimed to describe — it had been run
against the pre-single-sourcing tree. Baseline template `56a971a639079905`, plant
count asserted at 1, mutated hash, restored hash, and the exact command, per
mutation.

Killed: 700 and 203 into the self-update policy · a not-ok verdict resolving
`undefined` · the two policies swapped between callers · the cap enforced for GET
only · the deadline drifting to 6.4s · `const files = []` · `close` back to
cleanup-only · the deadline neutered · the parser dropping the user message · the
single-sourcing reverted faithfully.

Four things the controls learned to read, each because a review showed the old
observable was weaker than the claim:

- **The lock file is the receipt that `main()` returned.** `finally` releases it;
  `process.exit(0)` from `HARD_TIMEOUT` runs no `finally`. A health POST arriving
  proves only that execution passed the awaited call.
- **The session fixture runs the fleet-default path.** It had used
  `CODEX_SESSION_SYNC_INCLUDE_HISTORICAL=1`, which also switches off the file
  mtime guard and the parsed-last-active guard — so it proved a path no machine
  takes. Preseeding an older `installedAtMs` is what makes a fresh session
  eligible the way a real rollout is.
- **The payload is asserted, not just the request.** The stub discarded request
  bytes, so a parser mutation dropping the message still produced a POST.
- **Injected hazards are recorded and asserted.** One line in the harness
  (`const isIngest = false`) turned two hazard controls into ordinary 200
  responses, both green.

## The instrument that measured the wrong thing

The early-refusal receipt ("the cap stopped the read *during* the body, not
after it") was first built at the socket level: the stub recorded whether the
peer went away before the server finished writing. It read false on correct code.

An independent probe found why. In-process it discriminates — `cutOff:true`,
2.42 MB written of 3.14 MB. Across processes it does not: the poller is a child,
so the stub's event loop pushes the whole body before the peer's destroy is ever
processed. **It was measuring kernel buffer size, not the client.** Replaced with
an in-process control that counts the chunks the exchange consumed before it
settled, run for both request shapes — `body === null` restores a GET-only cap
while every socket-level control stays green.

## Traps this round paid for

- **A review dispatched at the live working tree while that tree is being
  edited.** The round-6 harness reviewer detected it, polled both files' hashes
  until they stopped moving, and pinned its final read to them — so the verdict
  survived. It survived because the reviewer handled it, not because the dispatch
  was sound. Point `--cd` at a frozen copy.
- **`--cd <repo>` gives the reviewer read access to everything under it,
  including `.env.local`.** Four ultra dispatches this session had that. Nothing
  indicates any of them read it, and the sandbox was read-only, but the capability
  was there and choosing the path is where it gets decided.
- **A mutation can plant syntactically and change nothing.**
  `performRequest(...) || copy()` short-circuits because a promise is truthy, so
  it reported SURVIVED and looked like a control hole. The assert that the
  pattern matched once does not prove the mutation *does* anything.
- **`execFileSync` in the same process as a stub server blocks the event loop
  that would accept the connections.** Three controls failed with "0 requests"
  and the poller was not at fault.
- **`execFileSync(..., stdio:[..,"pipe"])` discards stderr on success.**
  Diagnosis needs `spawnSync`.
- **A surviving mutation is not automatically a hole.** `return;` in place of the
  refusal rejection survives because the `close` settle path now supplies the
  same rejection. Two reviewers agreed it is equivalent. The criterion's own
  golden warns about the harness that reads "survived = gap" as a rule.

## Where the loop stopped, and why

Material findings ran 7 → 11 → 8. The runtime converged: round 6 found zero
runtime defects and its reviewer enumerated the settlement graph and called it
correct. What did not converge is harness fidelity — every round produced fresh
instances of one root cause, *the control's observable is weaker than the claim
it makes*. That is the self-refilling criterion the defect-criteria guide warns
about for the contract-first observer, and stopping is a decision rather than an
arrival. The user made it after round 6, with eleven planted mutations dead and
no survivors as the evidence for the current bar.
