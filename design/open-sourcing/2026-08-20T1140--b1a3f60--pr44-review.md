# PR #44 reviewed on two lenses the nine build rounds did not carry

The build loop ran nine rounds on ONE criterion (`AI harness` / `false_signal`)
and converged. This record is what a different question found in the same
change: two lenses, 27 findings, **two more shipped-client defects**.

Why a second pass at all: nine rounds of one criterion is nine rounds of one
question. `false_signal` asks "does this instrument lie?" — it never asks "is
the promise true?" or "does this crash?". The two defects below sat inside a
change that had already survived 86 findings.

## Shipped-client defects (both reproduced before fixing)

1. **A hand-typed slot URL crashed `learn!`.** `dashboard.example.com` (no
   scheme) in `~/.config/agent-bios/ingest-url` raised
   `ValueError: unknown url type` out of the drain, after the local writes had
   already happened. Same class as round 8's `BadStatusLine` fix, on the request
   side instead of the response side — and the new slot is the surface most
   likely to carry a typo. Fixed at the authority: `invalid_base()` refuses a
   base with no http(s) scheme or no host **where the value is produced**, with
   the file named; `http_post` catches `ValueError`/`UnicodeError` as the belt.
2. **`CLAUDE_CONFIG_DIR` stopped isolating the transport.** Before this branch
   the transport came from `<home>/hooks/`, so redirecting the config home
   disabled upload; the new slot resolves from `$HOME`, so a harness that
   redirects only the config home would POST to the operator's live endpoint.
   Reproduced directly. The tell was in the diff: the self-test had to override
   `os.environ["HOME"]` — patching the caller instead of the seam. Fixed by
   making the slot root an explicit `slot_root` argument (no test mutates the
   environment now), documenting that `--config-dir` moves local writes and not
   the transport, and giving `gates/check_parity.py::capture_works_anywhere` a
   redirected `HOME`.

A third, adjacent: an EACCES anywhere at or above the slot made every path
predicate answer "absent", so a complete-but-unreadable slot **silently selected
the legacy endpoint**. The claim is now made by listing the directory —
`FileNotFoundError` means absent, every other `OSError` means a claim we cannot
read — and the loud-failure promise holds for the case that motivated it.

## What else changed, by class

**False PASSes in the gate** — `shipped_files()` silently dropped any `files[]`
entry absent from the worktree (`provenance.json`) or written as a glob, so
"119 shipped files url-scanned" was a narrowed denominator claiming full
coverage. `check-hygiene.derive_subjects` had already closed both holes, so the
gate now **imports it** instead of carrying a third model of npm packing (npm's
array-form `bin` was probed and added to that one owner: npm 12.0.2 packs every
entry). The subject set went 79 → 119 the moment it was single-sourced.

**Unfalsifiable numbers** — `leg_default` and `leg_wire` returned literal
subject counts (3, 15) while the module docstring promised "each reports its
subject count". Both now derive: 8 probes, 48 observed requests.

**Unprotected promises** — the settle mapping was sampled at three statuses, so
`if status == 503: return "ok"` was invisible; the wire matrix now walks a
representative of every class (2xx incl. 200/201/204/299, 400/413 permanent,
3xx incl. 301, 4xx, 5xx) and 301 as well as 302 for the no-redirect promise.
The env-var promise was checked by one literal prefix; it now compares the whole
set of environment names the client reads against a declared allowlist.

**Lifecycle** — the gate leaked ~11 temp directories per run and the client
self-test 17; **43,001** had accumulated on this machine. Both now use one
scratch tree per run, removed at the end. `leg_wire` also closes its listener
(`server_close`) and joins its helper thread.

**Silent-skip holes in the umbrella guard** — `[ -f "$REPO/x" ]`, `[ ! -f x ]`
and `[[ -f x ]]` matched neither the PARSE nor the COUNT regex, so a leg written
any of those ways left both scans at once. The COUNT now accepts every
plausible spelling while the PARSE stays strict, so an unparseable form
diverges the two and fails loudly; all three were probed.

**A control that could not fail** — the untraversable-slot check used
`os.access`, which uid 0 ignores. It is skipped under root now rather than
quietly testing nothing.

**Doc claims that were false** — `ENDPOINTS.md` said corpus operations are
"realized by npm alone" while its own table named `git pull`; said the server
stores the payload verbatim when the dashboard calls `stripNullChars`; and
promised a wall-budget overrun of "at most one socket timeout" when urllib's
timeout bounds each blocking socket operation, not the request (a drip-feeding
server extends a POST past both numbers, and DNS is outside it entirely). All
three now say what is true. `SURFACES.md` named `compose/register-hooks.py` as
the install-time merger; the live path is `assemble.py`, and the stale line was
a false authority for anyone who found it first.

**Scenario probe robustness** — the installed-hooks assertion rebuilt the
expected command as `python3 <abs>`, which would fail on a template that ever
carries an interpreter flag or script argument. It now applies the installer's
own substitution rule.

## Not fixed, and why

- **Deliberate in-repo evasion** stays out of scope (D-20260819-67c00a): an
  author who can commit can disable the gate.
- **The hook-source egress scan is a tripwire** — `os.system("ping …")` evades
  any denylist. The structural weight is the canonical-shape refusal; the
  banner no longer claims "egress-free", it says "sources tripwire-scanned".
- **Prose negation next to an anchored token** ("`2xx` does NOT settle") is
  review's territory: a naive detector false-fires on the Response field's own
  "Redirects are not followed".
- **Self-test wall time** (~2 min, full `run()` per mutation) is disclosed, not
  optimized — inside a 10–15 minute umbrella, and the per-leg selector it would
  need is more machinery than the minute buys.
