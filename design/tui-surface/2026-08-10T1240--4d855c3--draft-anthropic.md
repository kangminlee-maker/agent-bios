# Independent design draft — TUI corpus checklist, chrome i18n, reviewer-registration wizard
(Claude-side, packet-only)

## 1. Architecture decisions
F1: launcher = pure front-end to installer; NO durable pending state. Checklist pre-checked from corpus-status.json; core+infra checked-and-disabled; domain list via NEW `agent-bios domains --json`; on confirm suspend TUI and run `agent-bios install --domains <set>` synchronously, then re-read status. Failure surfacing: installer extends corpus-status.json with last_apply {requested_domains, outcome: applied|canary_failed|install_failed, at, error_tail}; panel renders applied / failed-loud / unknown-loud. REJECTED: durable pending-selection file (second authority, stale-apply shim); launcher importing install logic (breaks launcher-never-deploys).
F2: symbolic-key catalogs launch/i18n/{en,ko,ja}.toml; en = reference key-set; t(key) accessor; precedence AGENT_BIOS_LANG env > user-owned launcher.local.toml [ui].language > en. Menu shows each language in itself. Missing key: gate-enforced completeness (set equality + both directions vs source); runtime fallback to English + ONE persistent loud banner (no crash, no silent fallback, no per-string markers). TOML data descriptions render verbatim in all chrome languages (content, not chrome). REJECTED: English-literal-as-key gettext style (copy edits silently invalidate catalogs).
F3: wizard with ZERO validation logic; validity oracle = the real reader run in-process on candidate merged in-memory; only green pass permits write; reader errors shown verbatim as correction prompts; collision = reader's own refusal. Write = APPEND-ONLY self-contained block (never reserialize user file); post-write re-validation with in-memory restore on failure. Edit/remove NOT offered (lossy rewrite of prose-bearing user TOML, destructive posture; file named for hand-editing). REJECTED: schema-driven form generation (second contract statement that drifts, or one-error-at-a-time UX).

## 2. Data/authority map
- compose/domains.json: repo/installer; launcher only via `agent-bios domains --json` (new).
- corpus-status.json + last_apply: installer-only writer (unchanged direction).
- launch/i18n/*.toml: deploy-managed payload; en = reference.
- launcher.local.toml [ui].language: NEW user-owned; the only durable file the launcher writes.
- AGENT_BIOS_LANG: NEW env; ephemeral; what gates pin.
- review-methods.local.toml: user + wizard append-only; reader stays sole validator.

## 3. Gate strategy
- pty harness pins AGENT_BIOS_LANG=en → all English markers survive verbatim.
- Contract golden: add ko-env scenario requiring BYTE-IDENTICAL output to EN (chrome never leaks into contracts). NC: plant t() into contract template → ko-run diverges.
- Catalog completeness gate (set comparisons, non-empty subject). NC: delete key / plant orphan.
- Language render legs (pty, ko then ja): first-screen bytes derived from catalog at gate runtime. NC: wrong value in temp catalog → fails.
- Missing-key tripwire unit. NC: complete catalog → banner absent.
- F1 handoff leg: argv-recording installer stub; exact `install --domains <sel>` argv; disabled-row toggle inert. NCs both.
- F1 status-panel fixtures: canary_failed → loud marker; missing → unknown. NC: applied → marker absent.
- Installer canary-outcome install-scenario + NC.
- F3 round-trip leg (sandbox HOME): append → real reader validates → method listed + contract carries entered fields. NCs: shipped-name collision → file byte-identical; invalid field → no write.

## 4. Stages
1. i18n substrate EN-only: t() + en.toml extraction + completeness gate + harness lang pin. Done-when: existing pty markers byte-identical; gate fails by name on planted key.
2. KO/JA + menu + persistence + env: render legs, tripwire, ko contract-invariance. Done-when: legs green; ko golden byte-identical; preference survives relaunch.
3. Installer F1 half: domains --json + last_apply + canary-failure scenario. Shippable alone. Done-when: scenario shows canary_failed recorded + NC fires.
4. Launcher F1 half: checklist both paths, suspend-handoff, panel states. Done-when: stub+fixture legs green + one real E2E domain flip reflected.
5. F3 wizard: flow both paths, in-process trial validation, append-only write + post-write re-validate. Done-when: round-trip green; both refusals leave file byte-identical.

## 5. Risks/open questions
1. Packaged-mode domain enumeration inside npm payload boundary (verify before Stage 3).
2. CJK wide-glyph layout/pty assertions — probe minimal ko screen first.
3. TUI-suspend terminal handover; installer non-interactive under --domains (stdin detached at top).
4. Reader error message quality → improve reader messages, never wizard-side interpretation.
5. `ja` internal / "JP" display; status panel line "corpus: EN/KO (chrome language does not affect corpus)".
