# TUI surface: corpus checklist, chrome language (EN/KO/JA), reviewer-registration wizard

Synthesis of two blind dual-provider drafts (same packet: `2026-08-10T1240--4d855c3--design-packet.md`;
drafts: `--draft-anthropic.md`, `--draft-openai.md`). User request 2026-08-10: TUI corpus-selection
checklist + TUI language selection (EN/KO/JP) + a registration feature so they can register personal
reviewers themselves. Corpus languages stay EN/KO; JP is chrome only.

## Where the drafts agree (adopted as-is)

- **F1**: the launcher is a pure front-end; **no durable pending state** (both drafts independently
  rejected a pending-selection file as a second authority). Selection is in-memory diff against the
  applied set; on confirm the launcher suspends the TUI and runs the installer synchronously; effect
  is immediate; core+infra render checked-and-disabled; the installer alone writes status.
- **F2**: symbolic-key catalogs with **`en` as the reference key-set**, completeness enforced by a
  deterministic gate (set equality both directions vs source `t()` calls); language preference in a
  **new user-owned `launcher.local.toml`** (`[ui] language`, the only durable file the launcher
  writes); an ephemeral override for gates; TOML data descriptions (presets/methods) render
  **verbatim** in every chrome language; chrome language must **never** reach a rendered launch
  contract. Internal code `ja`, display "JP"/日本語.
- **F3**: **add-only wizard with zero wizard-side validation** — the real reader is the only oracle;
  candidate proven through the genuine merge-before-validation pipeline; append-only write (never
  reserialize the user's file); refusal leaves the file byte-identical; edit/remove deliberately out
  (hand-editing the documented file covers it). Both drafts rejected schema-driven form generation.

## Divergences, adjudicated

1. **Missing-key runtime policy** — anthropic: English fallback + one persistent loud banner;
   openai: recovery screen + per-string `⟦missing:key⟧`. **Taken: anthropic**, because per-string
   markers break layout and pty assertions for a state the completeness gate already makes
   unshippable. openai's recovery screen survives narrowly: a catalog that fails to LOAD (corrupt
   file) fails loud with an explicit fall-to-English notice, never silently.
2. **Override mechanism** — anthropic: env; openai: `--ui-language` flag. **Taken: env only**,
   named in the launcher's own namespace: **`AGENT_LAUNCH_LANG`** (consistent with
   `AGENT_LAUNCH_CONFIG`/`AGENT_LAUNCH_VENV`, which the drafts could not know). A flag is a later
   addition if demand appears.
3. **F1 invocation** — anthropic: `install --domains`; openai: `onboard --domains`. **Taken:
   openai** — `cmd_onboard` is the existing full loop (install → activation canary → prune
   migration) and already accepts a non-interactive `--domains`; reusing it is concept economy.
4. **Failure/status model** — openai: full transaction state machine (schema_version, applying/
   degraded states, attempt ids, snapshot dirs); anthropic: minimal `last_apply
   {requested_domains, outcome, at, error_tail}` record. **Taken: anthropic** — the installer
   already backs up replaced files and the canary already fails loudly; a transaction system is
   scope the pre-launch reality does not demand. "applying" needs no persisted state because the
   launcher runs the installer synchronously in the foreground.
5. **Domain-list source** — anthropic: new `agent-bios domains --json` subcommand; openai: launcher
   reads `compose/domains.json` directly. **Taken: neither** — the installer **projects the
   available domain list and the applied selection into `corpus-status.json`**, which it already
   owns and the launcher already reads. No new subcommand, no launcher knowledge of repo paths, no
   packaged-mode path problem; a stale list is impossible because every install run rewrites the
   projection. When status is missing, the checklist is unavailable and says to run
   `agent-bios install` — honest, not fail-open.
6. **F3 trial mechanics** — openai proposed refactoring the loader to accept a candidate path
   (its Stage 4). **Not needed**: `load_config(path)` derives sibling paths from the profile path,
   so the trial is a temp dir holding a copy of the live `profiles.toml` plus the candidate
   `review-methods.local.toml` — the REAL pipeline end-to-end with zero seam changes. openai's
   write mechanics survive: 0600 temp, pre-write digest check against concurrent edits, atomic
   replace, post-write re-read through the same loader.

## Data/authority map (net new or changed)

| Artifact | Owner | Note |
| --- | --- | --- |
| `launch/i18n/{en,ko,ja}.toml` | deploy-managed payload | `en` = reference key-set; must enter `files[]` (check-package will demand it) |
| `launcher.local.toml` `[ui] language` | user | new sibling of the two existing `.local.toml`; launcher writes it atomically on explicit selection only |
| `AGENT_LAUNCH_LANG` | caller/gates | ephemeral override; pty harness pins `en` |
| `corpus-status.json` `+ domains {available[], applied[]}` `+ last_apply {requested, outcome, at, error_tail}` | installer only | projection refreshed on every install run; launcher read-only |
| `review-methods.local.toml` | user + wizard (append-only) | reader stays sole validator |

## Gate strategy

- pty harness exports `AGENT_LAUNCH_LANG=en` → every existing English marker survives verbatim.
- New: catalog completeness gate (+NC: planted missing key / orphan key fail by name).
- New: ko/ja render legs — first-screen bytes derived from the catalog at gate runtime (+NC:
  wrong value in a temp catalog copy fails).
- Contract-language invariance: golden re-run under `AGENT_LAUNCH_LANG=ko` must be byte-identical
  (+NC: a `t()` planted into contract text diverges).
- F1 handoff leg: argv-recording `agent-bios` stub — confirm invokes exactly
  `onboard --domains <selection>`; disabled-row toggles inert (+NCs).
- F1 panel fixtures: applied / canary_failed-loud / missing-unknown (+NC: applied shows no
  failure marker).
- Install-scenario: forced canary failure records `last_apply.outcome=canary_failed` (+NC).
- F3 round-trip leg in a sandbox HOME: wizard → append → real reader loads → method reaches a
  rendered contract; refusals (shipped-name collision, invalid field) leave the file
  byte-identical (+NCs).

## Stages (each independently shippable)

1. **i18n substrate, EN only**: `t()` + `en.toml` extraction + completeness gate + harness env pin.
   Done-when: existing pty markers byte-identical; gate fails by name on a planted key.
2. **KO/JA + selection + persistence**: catalogs, language menu (both paths), `launcher.local.toml`,
   env override, render legs, contract-invariance. Done-when: legs green; ko-env golden
   byte-identical; preference survives relaunch.
3. **Installer F1 half**: domains/applied/last_apply projection into corpus-status.json +
   canary-failure scenario. Done-when: scenario records `canary_failed`; NC fires.
4. **Launcher F1 half**: checklist (both paths), synchronous `onboard --domains` handoff, panel
   states. Done-when: stub/fixture legs green; one real E2E domain flip reflected after re-read.
5. **F3 wizard**: question flow (both paths), temp-dir real-loader trial, append-only write +
   post-write re-validate. Done-when: round-trip green; both refusal cases leave the file
   byte-identical.

## Pre-coding checks (from both drafts' risk lists)

1. What `compose/corpus-state.py` writes today, and packaged-mode reachability of the domain list.
2. CJK wide-glyph behavior through the Textual pty harness — probe a minimal ko screen first.
3. `onboard --domains` non-interactive behavior when invoked from the launcher (stdin detached at
   installer top; terminal handover on the TUI-suspend path).
4. Reader validation-message quality as re-prompt UX — fixes go into the reader, never the wizard.
5. KO/JA terminology owner is the user; catalog text passes their review before release.

## Corrections (dated)

- **2026-08-10 (user decision, same day):** the packet and this record said "corpus
  languages stay EN/KO". Sharper boundary from the user: i18n applies to the
  INTERFACE only — **the corpus the AI consumes is English-unified** (the `ko/`
  tree is repo-side human reference; `assemble.py` builds from `claude/` and npm
  excludes `ko/`, so this was already structurally true). Catalog descriptions and
  prose corrected accordingly. Programming languages are a separate, permitted matter.
- **2026-08-10 (terminology):** this record's word "chrome" (browser/GUI chrome —
  NN/g, MDN) is insider jargon; the industry-standard i18n term is **"UI strings" /
  "UI text"** (Lingoport, Adobe, Crowdin). Code and gate vocabulary renamed to
  `ui_language`/`ui_catalogs_*`/"UI text"; this record keeps its original wording
  above as written.
