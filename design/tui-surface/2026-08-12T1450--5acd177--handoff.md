## The previous handoff was wrong about its own prerequisite

It asked for an 80-column CJK width probe on the theory that wide glyphs would
shift the column positions the pty assertions depend on. Both halves were false and
the probe is what said so: the fixture sets **24x100**, and no assertion reads a
screen column — `transcript.find()` offsets order sections, which glyph width
cannot disturb. The real failure is soft wrapping breaking contiguous matching, and
it bit **English** first (6/7 strings at 80 columns while ko and ja kept 7/7,
because CJK says the same thing in fewer characters). Recorded as D-0058.

### Boundaries already settled — do not re-litigate

- `REVIEW_SETUPS[*]["label"]` and `["description"]` are UI text; `["contract"]` is
  **not** — it is the instruction sent to the agent, `review_description`'s docstring
  says so, and `_cross_review_route` feeds it into the launch contract. Move label
  and description out into a render-time function; leave contract where it is.
- `registry[*].label` / `.description` come from `agent-launch.toml` **and the
  user-owned `review-methods.local.toml`**. They are config data, not catalog text.
  Translating them would mean translating a user's own file.
- `row.detail` / `why` is resolver output. Also not catalog text.
- `method_availability` is the hard one: it *assembles* advisory sentences from
  conditions (support, reachability, install state). Slot-per-sentence will fight
  ko/ja word order. Design that before touching it, not during.

## Traps this branch paid for

- **The key scanner is single-line.** `ui_catalogs_hold_the_reference_key_set` finds
  keys with a one-line `t("...")` regex. A wrapped call reads as uncalled and fails
  as an orphan. A computed key — `t(f"tier.{tier}.description")` — is invisible to it.
- **Import time freezes the catalog.** A module-level constant or a **default
  argument** evaluated before `load_catalogs()` runs serves English forever.
  `_corpus_info`'s `back_hint=` default was exactly this.
- **Slots must come from `string.Formatter().parse()`, never a regex.** `{}` and
  `{0}` parse cleanly, no named-slot regex sees them, and both raise `IndexError` at
  render. The gate reads `field_name` and rejects positional fields.
- **A `.format()` call site cannot be found by regex.** It stops at the first `)`,
  so `v.get("closed", "?")` reports kwargs the site does pass as missing. The gate
  uses an AST walk.
- **Product names stay English** — `Software Engineer`, `Builder`, `Session distill`.
  Transliterating `Session distill` into `세션 디스틸` shipped two names for one
  concept across a single navigation step. No gate can catch this; it took reading
  the Korean.
- **A checker must not borrow its subject's ruler.** The panel-alignment leg first
  measured with the launcher's own `display_width`; when its control swapped that for
  `len()`, product and checker counted characters together and a ragged panel measured
  level. The leg now carries its own width function on purpose.

## The layer that had no tests, and still bounds what a green run means

Every render check drove the **clone** launcher, which has `launch/i18n` beside it.
Deployed, the launcher lands in `$BIN_DIR` while catalogs land under `$LAUNCH_DIR`,
so it keeps none beside itself and the deployed catalogs *are* the UI text. That
layer had no coverage at all — `test-install-guides.sh` performs four real installs
and contained no reference to `agent-launch`.

It is not a coincidence that all three defects the review found lived there: deploy
ordering, a missing-key tripwire with no reader, and catalogs excluded from verify.
**I10** in `gates/test-install-guides.sh` now launches the deployed launcher, asserts
Korean from the deployed catalog with expectations read at run time, and controls it
by stripping a key from both deployed catalogs.

Design the verification for the review editor **with** the implementation, not after.
For this item that means deciding up front which screens I10 should walk, since the
review path is five levels deep from the Custom hub.

### Driving the TUI, for whoever writes those checks

Navigation that works today, verified at this HEAD (arrow keys, menus **wrap** —
overshooting cycles, which silently selected the wrong row twice during this work):

- Custom hub → Compose review: `down, enter`
- → Add review method: `down, enter`
- → the registration wizard: `down, down, enter`
- Root → Session distill → packages → back → versions: `down, enter, down, enter, esc, down, down, enter`

`AGENT_LAUNCH_TUI=0` or `TERM=dumb` gives numbered prompts; a real `TERM` gives
Textual. **The root mode menu needs a TTY** — stdin from `/dev/null` short-circuits
straight to launch and renders no menu, which produced one worthless comparison
before it was caught. Drive a pty.
