## Thread 1 — UI-string extraction (mechanical, gate-guarded)

Extracted so far: the root/mode screen, the corpus checklist, the language menu, and
the registration wizard. Measured at this HEAD: **58 catalog keys**, **16 `choose()`
sites still carrying a literal title**, **50 `MenuOption(...)` sites with literal
label/description**. Re-derive:

```bash
python3 - <<'PY'
import re, pathlib
src = pathlib.Path('launch/agent-launch.py').read_text()
print('keys:', len(set(re.findall(r'\bt\(\s*"([^"]+)"\s*\)', src))))
PY
```

The screens still holding English literals, in the order they are worth doing (each is
independently shippable, and each must keep `ui_catalogs_hold_the_reference_key_set`
green, which means en/ko/ja move together in the same commit):

1. **Custom settings hub** (`"Custom settings"`, `"Main tier"`, `"Review setup"`,
   per-tier model/effort screens) — the screen a Builder user sees most.
2. **Review editor** (`"Compose review"`, `"Add review method"`, the seat screens'
   `f"{title} — provider|seat|effort"`).
3. **Session-distill hub** (`"Versions & rollback"`, `"Corpus packages"`, the rollback
   confirmation).

Two traps this thread will hit:

- **f-string titles.** `f"{title} — provider"` cannot become one catalog key; the
  pattern is a key holding the suffix (`"seat.provider.suffix"`) composed in code, or
  a key with a `{}` slot formatted at call time. Pick one and use it everywhere —
  mixing them is how a catalog acquires two conventions.
- **The scanner is single-line.** `ui_catalogs_hold_the_reference_key_set` finds keys
  by a one-line `t("...")` regex, so a wrapped call reads as *uncalled* and fails as
  an orphan. That is the convention enforcing itself; keep `t()` calls on one line.

## Thread 2 — automated ko/ja render legs (the disclosed gap)

Today's ko/ja proof is **manual**: a pty run that shows the Korean mode menu and the
checklist. That is evidence, not a gate — nothing re-checks it. The design's intent
(synthesis §Gate strategy) is a pty leg per language whose expected bytes are
**derived from the catalog at gate runtime**, never hand-maintained, plus a negative
control that plants a wrong value in a temp catalog copy.

What must be true first, and is not yet verified:

- **CJK width through the harness.** Probed only that Textual mounts and navigates a
  CJK screen (`app.export_screenshot()` contains 코퍼스 / 日本語, arrow keys move the
  highlight). NOT probed: whether wide glyphs shift the column positions the existing
  pty assertions depend on, at 80 columns. Do that probe before writing the leg — if
  widths shift, the leg must assert on *substrings*, not positions.
- **Where the language comes from in the harness.** The fixture pins
  `AGENT_LAUNCH_LANG=en`; a ko/ja leg overrides it per-scenario. Do not reach for the
  user preference file in a gate — the env override exists precisely so a gate never
  depends on ambient user state.
