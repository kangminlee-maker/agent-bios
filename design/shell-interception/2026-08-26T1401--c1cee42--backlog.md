# Backlog — reassert the launcher's shell entrypoints at preexec

User-approved backlog item (2026-08-26). Not scheduled; the implementation handoff beside
this record is the authority for what to build and what was measured:
`design/shell-interception/2026-08-26T1135--f8add13--preexec-reassert.md`, authored by a
session working from `~/Documents/operator_platform` and addressed to this checkout, with
the candidate `launch/agent-launch.zsh` in `agent-launch.zsh.candidate` beside it.

## Why it is open

A bare `claude` inside a cmux terminal does not go through the agent-launch preflight. Cmux's
zsh integration reinstalls its own `claude` shell function on the first `precmd`, after every
rc file has run, so whichever definition the launcher installed at rc time is replaced — and
`codex` is untouched, which is why the failure looks host-specific rather than structural.

The defect is not that one terminal wins a race. It is that **the launcher's entrypoint is
installed once and never checked again**, so any environment that reinstalls a wrapper after
rc time silently removes the preflight while leaving the command working. The handoff's
answer is to stop competing for definition order: verify at `preexec` that the function about
to run is ours and redefine it if not.

## What this record deliberately does not do

It is registered rather than started because the deployed copy on this machine comes from the
npm package, not this checkout (`agent-bios status`), so a fix here does not reach the failing
terminal until a release — and that sequencing is a decision for the session that picks it up,
not one to bury in a backlog note. This entry is a task with a decided path, which is why it
is not in `FINDINGS.md`: that file's own rule is that an item with one path is a task, not a
finding.

## Before building it

Re-derive rather than trust: the handoff's claims are dated 2026-08-26 against cmux's
installed shell-integration file and codex-cli 0.149.1, and every one of them decays with the
next release of either. The handoff carries the exact commands that re-establish each.
