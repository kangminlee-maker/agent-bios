## The pre-commit contract — ENFORCED once per clone, nothing until then

```bash
git config core.hooksPath .githooks   # once, per clone
```

`.githooks/pre-commit` runs `gates/check-package.sh` then `gates/check-parity.sh` and aborts the commit on failure. There is no CI, so this hook is the only automatic enforcement in the repo. Run the umbrella any time with `./gates/check-parity.sh`.

**Budget minutes, not seconds.** The slowest leg runs real end-to-end installs against a throwaway `$HOME` (`gates/test-install-guides.sh`, invoked at `gates/check-parity.sh:152`) and its own comments describe re-runs in the eleven-minute range. Three different costs are stated in three files; re-measure before quoting one. A commit that appears to hang is this leg.

**Never `pkill -f 'check-parity'`.** The hook's own child matches that pattern and the commit dies. Kill by PID.

**The gates judge the index, not your working tree.** The hook materialises the staged tree through its tree object into a temp directory and points `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` at it. If gate output disagrees with what you see on disk, the difference is unstaged. Nothing is stashed, so an interrupted hook cannot leave the repo mid-surgery.

**A new file is invisible to the index-reading gates.** `gates/check-lexicon.py` builds its subject set from `git ls-files`. Run `git add -N <file>` before believing a lexicon or concept-home result.

**A gate that runs `git` in a scratch directory re-initialises this repository.** The gates inherit `GIT_DIR`, so a `git init` in a fixture rewrites this repo's `core.worktree` and breaks `git status` in the primary worktree. It happened once. The hook compares the value before and after, restores it, and fails the commit by name — detection, not prevention. A new gate must clear the variables itself: copy the `cleangit()` form in `gates/check-publish.sh:229-232`.

**Stage explicit paths, never `git add -A`.** Multiple sessions share this worktree; a sweep once pulled another session's files into a commit and the extraction cost a history rewrite. Read `git diff --cached --stat` before committing.

## What a green gate is worth

A green gate means "it ran", not "it checked your change". The repo is built around this and you are expected to preserve it.

- **Every leg asserts a non-empty subject before claiming clean.** `gates/check-package.sh:350` registers each leg through `leg(name, subjects)` and refuses to report clean when a leg judged nothing; it reports per leg and never aggregates, because an aggregate is how a zero hides.
- **`check-parity.sh` reads its own leg subjects out of its own file** (`:38-50`) and fails when a leg's subject is missing — otherwise deleting a file deletes its check while the umbrella still says OK.
- **Add a check, add its negative control.** Prove a new rule fires by planting a violation and watching it fail *by name*; then revert the fix and watch the control fail. A control written against a bug it does not test survives a faithful revert.
- **`gates/control-audit.py`** removes one failure statement at a time and reports whether that gate's own `--self-test` notices. It discloses and exits 0, deliberately. Shell gates are reported as ungraded, not clean.
- **Some legs silently skip.** `install.sh:1058` runs the parity gate only under `[ -d "$REPO/ko" ]`, and `ko/` is `.npmignore`d — so `agent-bios verify` from an npm install never checks mirrors. Only a clone does.
- **Blocking is for deterministically decidable violations only.** Gate a judgment call and people route around the gate. `gates/check-surfaces.py` states this about itself and leaves the judgment half ungated on purpose.

## Co-change duties

- **Add a deploy target → claim it in `SURFACES.md`.** `gates/check-surfaces.py` fails *unclaimed* when the installer deploys something no surface claims, and *stale* when a surface names a path that no longer exists. A deploy that is genuinely not a consumption surface is justified by name in `NOT_A_SURFACE`, never silently skipped.
- **Add a runtime path → add it to `package.json` `files[]`.** `gates/check-package.sh` derives the real `$REPO/...` references out of `install.sh` and `compose/assemble.py`, so a path added later is covered automatically. Three directions: unshipped runtime paths fail; author-side paths appearing in the payload fail; and shipped prose may not name a path the user will not have. A file may name author-side paths only by declaring `audience: author`, which makes `compose/assemble.py` withhold it from delivery. Note that a directory entry in `files[]` expands to its whole subtree, so an entry can pack a file no entry names.
- **Edit `install.sh` → re-derive the ontology.** `ontology/extract.py` parses named function bodies out of `install.sh` and derives line-anchored evidence literals, so an unrelated edit makes every install scenario fail with a message about the ontology. Run `python3 ontology/extract.py && python3 ontology/emit-map.py`. It is line drift — **never hand-edit the number to match.**
- **Close a finding → delete its entry from `FINDINGS.md`.** Only open items live there; the reasoning goes in that round's dated record. `gates/check-lexicon.py:349` fails if a resolution marker appears in the file — a status field is the thing that goes stale.
- **A rule restated across two files carries an anchor phrase.** `gates/check-parity.sh:99-104` pins declared global↔guide restatement pairs; a one-sided reword fails there. `README.md` is bound by this, so rewording it can fail parity.

## Terminology and concepts — ENFORCED

`gates/check-lexicon.py` scans every tracked text file outside its archive allowlist for deprecated tokens, and asserts both the file set and the denylist non-empty so a green run cannot pass over nothing. It also enforces **concept homes**: a machinery file whose path carries a concept's slug must live under that concept's declared home, and a home matching no file fails as a stale declaration. The corpus trees, `design/`, `benchmarks/`, and `research/` are exempt — a slug there is a mention, not a home.

Adding a concept: find the nearest existing term first, then reuse / extend / rename / split explicitly, in the same change. Because `LEXICON.md` is generated, the edit goes in `ontology/instances/graph.json`.

## The deployed global is a per-session token budget — CONVENTION

`claude/CLAUDE.md` is re-sent every session and to every subagent, so each added bullet dilutes every other rule. A new global bullet must name the bullet it displaces, or why none does. Procedures, tables, numbers, and worked examples belong in a guide. A rule earns global placement only if it must work **even when the agent fails to recognise the situation**; a rule whose failure mode is recognition failure belongs behind a pointer.

Rule bodies use role slots and tiers, not model names — concrete bindings live in each guide's `Environment Binding`. The gated exception is the prompting guides, whose advice inverts between model generations: they list concrete ids in `targets:` frontmatter, and `launch/check-prompting-targets.sh` fails when `launch/agent-launch.toml` binds a model no prompting guide covers.

## Dated records are written once — CONVENTION

New records under `design/` are new files, not edits to prior ones:

```
design/<initiative>/<YYYY-MM-DD>T<HHMM>--<short-sha>--<slug>.md
```

with `created_at`, `head` (the commit the content was true at), `kind`, and `supersedes` in frontmatter. A continuously overwritten "current state" file claims to be now and is no particular time; a file whose name carries its timestamp cannot rot. Existing `HANDOFF.md` / `DESIGN.md` files are themselves history — re-derive their numbers from the artifact before acting on them.

## Record a decision when it closes an alternative — CONVENTION

```bash
python3 decisions/record-decision.py --kind design|direction|stop|steering \
  --summary "..." --closed "the alternative this ruled out" --why "..."
python3 decisions/record-decision.py --render | --timeline | --graph | --check
```

The tool refuses a record that closes nothing, and owns id, timestamp, branch, HEAD, dirty state and session — you supply meaning only. Ids are derived from the record's content, so ledgers written on two branches merge by concatenation and `--check` fails any row whose id is not what its content derives to. `--check` runs in the parity umbrella. This ledger never ships: `decisions/` is declared author-side in `gates/check-package.sh`, so adding it to `files[]` fails the gate.

## Deploying and publishing

**`agent-bios install` deploys the published npm package, not this tree** — `install.sh:36-45` resolves `REPO` to the script's own resolved location. To deploy what you are editing:

```bash
bash install.sh install     # from the clone
```

Confirm what landed with `agent-bios status` (version marker, no DRIFT), not the command's exit code. Reading the registry cannot see this, which is why it went unnoticed three times.

`npm pack` runs `gates/check-publish.sh --stamp` and `npm publish` runs `--guard` (`package.json` scripts). The stamp writes `provenance.json` binding the tarball to its commit; it refuses a dirty tree, and the guard refuses a HEAD no remote ref holds. `provenance.json` is gitignored and shipped — never commit it.

`npm i -g agent-bios@latest` right after publish installs the **previous** version (stale packument, exit 0). Pin exact — `npm i -g agent-bios@X.Y.Z` — then verify the *deployed* `version.json`, never the registry.

`install.sh` runs `exec </dev/null` at the top, so the stdin-payload subcommands (`learn`, `cost`) park the caller's fd on 3 and bypass the flag parser. Never publish a corpus that calls a new subcommand before the CLI carrying it ships.

## Traps that cost a real attempt

- **The launcher without `--config` reads the deployed profile**, not this tree's (`launch/agent-launch.py`, `default_config_path`). Always pass `--config launch/agent-launch.toml`, or every probe of your change tests the last install.
- **`agent-launch.py` options must precede the positional host.** Everything after the host is forwarded verbatim, so `agent-launch.py claude --no-tui` launches Claude with `--no-tui` and the launcher never sees it.
- **`AGENT_BIOS_STATE_DIR` is not read by `install.sh`** — `STATE_DIR` comes from `$HOME` with no override. A probe that sets it takes the no-manifest branch and passes for the wrong reason. The real overrides are `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `AGENT_LAUNCH_VENV`, `ZDOTDIR`.
- **The Bash tool here is zsh**: unquoted parameter expansions do not word-split, and `$x:y` is a history modifier. A probe loop where *every* case returns the same status is a signal to check the instrument, not the subject.
- **Driving the launcher needs a real TTY.** stdin from `/dev/null` skips the menu entirely and renders nothing; arrow menus wrap, so overshooting selects a different row silently. Use `AGENT_LAUNCH_TUI=0` or `TERM=dumb` for numbered prompts, or drive a pty.
- **A checker must not borrow its subject's instrument.** A panel gate that measured with the launcher's own width function agreed with the product about a ragged panel.

Declarative-sentence titles stating the insight, not the mechanics — "Review independence is the axis; the enum was the blocker". Releases: `Release vX.Y.Z`.

General engineering discipline — tool traps, verification menus, spawn policy, review contracts — is already loaded from the deployed global corpus in every session. Restating it here dilutes both. Only what is specific to developing *this* repo belongs.
