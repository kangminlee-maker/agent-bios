# agent-bios 0.20.0

Release changes relative to 0.19.4.

## The purpose statement describes the shipped product

The product purpose described team work environments built from Instructions,
Domain knowledge and Decision memory, with the team as the unit of sharing. What
ships is a personal library of Instructions, chosen per Claude Code or Codex
session, with packages others publish. The purpose text in the README and its
Korean reference now says that. The team work-environment initiative is stopped;
its design records remain as history.

## The session-distill driver is in the package

`session-distill/distill.py` and its modules, schemas, tables and packets ship for
the first time. The driver runs a session-distill run as declared stages: a census
of the window's sessions, their immutable copies and inventories, the readings and
the formation of candidates, the evidence checks, two judges per candidate, the
proposals and their review, the owner's review file in Korean with a faithfulness
check, the owner's decisions and their confirmation, and the close.

What this release's run produces is evidence about the window, the owner's review of
it, and a record of what the owner decided. **It changes no library file.** A
proposal that would place, correct, re-deliver or reduce instruction text is refused
by name (`RELEASE_1_NO_LIBRARY_CHANGE`), and where the evidence supports such a
change the proposal names it in its reason for the owner to read; the change itself
is the author's work by hand. The run writes the ledger it is given and, for a
periodic run, the coverage state it names, and refuses to write either, or its own
run directory, inside the instructions: under a checkout's `claude/`, `codex/` or
`ko/` trees, or in a host's home as `CLAUDE_CONFIG_DIR` and `CODEX_HOME` configure
it. Testing whether an applied change helps (stage S8) is not part of this release.

Running it still requires an agent-bios checkout. Its runbook,
`session-distill-workflow`, is an author guide and is not delivered by a packaged
install, and the launcher now withholds the Session distill preset on a packaged
install, where it was still offered.

The driver declares its dependencies in `DEPENDENCIES.md`: Python 3.12, `jsonschema`
at the version it was measured with (a missing or different one is refused by name),
`git`, `zstd` for a compressed session capture, and the Claude Code and Codex CLIs for
the calls it makes.

## Isolated review runs

- `claude-run --profile hermetic` runs a call in a cell: a fresh `HOME`,
  `CLAUDE_CONFIG_DIR` and working directory under a cell root you name, so the call
  carries none of your instructions. The run records the request as sent and the
  context the host loaded, and a call counts as isolated only on that record.
- `codex-run --profile hermetic` gave Codex only a temporary `CODEX_HOME`, while Codex
  also reads the repository's `AGENTS.md` and your skills from `HOME`: a review run
  inside a repository saw that repository's working rules and your skills. Codex now
  runs with an empty temporary `HOME` and no project documents.
- `codex-run --capture DIR` records what one call showed about itself. It reads a
  version-bound trace channel of the Codex CLI, so it refuses a Codex whose version is
  not the one it was verified against, and every exit before Codex starts names its
  code.

Installation deploys and verifies the helpers these routes load beside themselves
(`claude_hermetic_evidence.py`, `jsonl_lines.py`, `codex_frame_filter.py`,
`codex_protocol.py`, `claude_subcommands.py`, `host_platform.py`).

## Model bindings

The Claude FRONTIER seat moves from Fable 5.1 to `claude-fable-5-2`, and Fable 5.1
leaves the launch profile's model list rather than staying beside it. The Claude
prompting guide was re-derived for Fable 5.2 before the binding moved.

## Reliability

- Every lock the package takes waits a bounded time: it says after two seconds what it
  waits for, and after thirty refuses, naming the lock.
- A child process's group is ended before the child is reaped, on every path, and no
  wait on a child's output is unbounded.
- Every reader of a JSONL log, the hosts' and the package's own, reads through one
  splitter from the file's bytes, so a record ends at LF or CRLF and nowhere else.
- A Codex session's activation records the rollout file the host wrote, so a session's
  selection and delivery can be read from its transcript, and an installation receipt
  names the installer that executed.
- Shell scripts no longer pipe a long output into `grep -q`, which under `pipefail` read
  a match as a miss.

## Upgrading

```bash
npm i -g agent-bios@0.20.0
agent-bios install
```

Install the exact version: right after a release, `@latest` can still resolve to the
previous one.

## Not established by this release

No packaged install has run a session-distill run; the driver's evidence is its own
suites, run from a checkout, and a check that the packed tarball starts the driver and
imports every module it ships. A file the driver reads only once a command runs is held
by the payload check's classification of every driver file, not by a run. The driver's
refusal to write inside the instructions reads a destination as it resolves when the
command starts; a parent directory another process replaces afterwards is not held. The
Windows script route and the Claude Desktop route are not re-established by this
release.
