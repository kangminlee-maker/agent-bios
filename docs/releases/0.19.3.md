# agent-bios 0.19.3

Release changes relative to 0.19.2.

## Windows without npm or WSL

Windows installs as scripts and data bound to an approved CPython 3.13, with no
custom executable and no EXE installer. It targets machines whose application
control permits PowerShell and Python but blocks unrecognized executables. The
bootstrap reuses an approved CPython already on the machine, or provisions the
pinned official embeddable runtime into an application-private folder; neither an
existing Python nor its packages are modified.

The installed commands are `agent-bios` and `agent-launch`. Each is a static
wrapper plus a generated `.cmd` shim, because Windows does not treat `.ps1` as
executable: without the shim a PATH directory holding only wrappers is reachable
from PowerShell alone, and the Command Prompt, the Run box and any program that
spawns a command find nothing while PATH is correct. The shim is generated at
installation rather than shipped, since Authenticode cannot sign a `.cmd`; its
bytes are fixed and recorded in the deployment's ownership inventory, so a
modified shim is refused exactly like a modified command.

`agent-bios uninstall` removes owned commands, shims, shortcuts and the owned
PATH entry. Private instructions, session records and any preexisting Python are
retained.

## A fixed installation address

The project's installation page serves one explicitly promoted release at a fixed
URL, so publishing another release does not silently change what the address
installs. It carries a one-line command per platform.

Each command relaxes the PowerShell execution policy for the single process it
starts, because the default policy on an unconfigured Windows client is
Restricted and refuses a downloaded script. The machine's saved policy is not
edited, and a domain-imposed policy still refuses through the invocation's own
error. The Windows command names the interpreter, so it can be pasted into the
Command Prompt or the Run box rather than only into an open PowerShell.

The macOS and Linux command installs the published npm release and stops, naming
the command that deploys the work environment: `curl | bash` gives the shell a
pipe, and the interactive chooser needs a terminal. It also reports the case npm
leaves behind — a successful global install whose command the caller's PATH does
not carry.

Windows releases come in two channels. Stable is Authenticode-signed and
timestamped. Preview is published without a signing identity and refuses to run
unless the caller adds `-AcceptUnsignedPreview`; the hashes pinned inside the
bootstrap still guard the manifest, the application archive and the runtime
archive.

## Claude Desktop

Claude Desktop opens conversations without a launcher and exposes no skill folder an
installer can reach ahead of time, so agent-bios reaches it as a local extension the
user installs once. `agent-bios app desktop` writes a `.mcpb` file under the private
state root; opening it with Desktop installs a standard-library stdio MCP server with
four tools: status, preview, use and off. agent-bios writes nothing into Desktop's own
folders or configuration.

`use` returns the saved installation selection, or a selection named in the request,
as context for that conversation only. Nothing reaches a conversation that did not
ask, including one already in progress. Desktop sends no conversation identity with a
tool call, so the first preview or use returns a `session_id` that later calls pass
back; a repeated use with it returns the same text without recording a second
delivery. The returned text ends with an `agent-bios end` line, and reporting that
line through status records that the text was read to its end. It does not record
whether Desktop kept the text in the message or saved it to a file, which Desktop
does not reveal to the extension.

The file names the absolute Python that generated it, because Desktop resolves a bare
`python3` through the login shell's PATH, which on stock macOS reaches 3.9. The server
finds the current installation on every call, so an agent-bios update needs no new
file; changing that Python does. Desktop delivery has no project scope, so
project-scoped imported instructions are not included, in chat or in the Code tab.

## Installation reports an unreachable launcher

Installation now says when the `agent-launch` it deposits cannot be typed: when
`~/.local/bin` is not on the shell's PATH, and when the optional zsh connection that
routes a bare `claude` or `codex` through the launcher is off. Both used to end in a
success message followed by `command not found`. A reachable installation reports
nothing new. The terminal interface, the conversation client and the non-interactive
path share the message.

## Instruction guides

The multi-model workflow, staged coding workflow, LLM capability boundary,
tooling gotchas, verification discipline and UI design guides were revised, and
lessons paid for on a separate deployment line were carried across where this
line had not already removed them. The tooling-gotchas hook was updated with
them.

## Not established by this release

No signing identity exists yet, so the published Windows channel is the unsigned
preview. Approval by an organization policy or endpoint-protection product is not
established: a green workflow proves the route on a hosted runner where
PowerShell and Python are permitted. Migration of an existing EXE installation
into the script route is refused rather than attempted.

The Claude Desktop route was measured on Desktop 2.16120.0 for macOS, in chat and in
the Code tab. It is not available on Windows, and a later Desktop version is not
established to load the file until someone checks it.

Domain knowledge, Decision memory and shared environment editions remain design
directions rather than features of this release.
