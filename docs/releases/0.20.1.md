# agent-bios 0.20.1

Release changes relative to 0.20.0.

## Codex seats on GPT-6.2

The Codex catalogue now lists GPT-6.2 Astra and GPT-6.2 Sol as its current models
and calls GPT-6 Astra and GPT-6.1 Sol the previous generation. The shipped launch
profile's Codex column now binds:

| Seat | Codex |
| --- | --- |
| FRONTIER | `gpt-6.2-astra` · max |
| HELM | `gpt-6.2-sol` · xhigh |
| WORKHORSE | `gpt-6.2-sol` · high |
| SWEEP | `gpt-6-luna` · max (unchanged) |

The Claude column is unchanged. WORKHORSE keeps HELM's model and differs by effort
alone: the catalogue's other current model, `gpt-6.1-terra`, is described for visual
understanding and computer use rather than for that seat's coding work. The deep
reviewer that the Deep review and Session distill presets dispatch from a Claude
session is now `gpt-6.2-sol` at `ultra`. The Codex agent files and the `codex-helm`
defaults follow the same bindings.

## The GPT prompting guide covers GPT-6.2

The guide was re-derived from the vendor's documents before the bindings moved, and
its Korean reference follows. A GPT-6.2 section states what the vendor observes on
6.2 Astra and Sol: more concise output by default, final answers that must stand on
their own, and how to state completion and coding expectations. It also states what
changes in the API from 6.2:

- editing earlier history drops the reasoning carried after it;
- top-level `instructions` are placed after `input`, past the cache, and billed as
  uncached input, so reusable instructions belong in the first `developer` message;
- `prompt_cache_options.ttl` replaces `prompt_cache_retention`.

The 6.2 models' instructions in the Codex client skip new tests unless a test is
requested, required by the repository, or needed for a specific regression, so a 6.2
run that must add tests has to say so.

The guide also drops claims its sources no longer make and corrects one they
contradict: a conversation that changed its reasoning effort mid-way can still use
automatic compaction through `context_management`.

## Session distill

The driver's Codex pin moves to codex-cli 0.171.0, because the versioned 0.167.0 binary
it named is no longer installed after the Codex CLI's update. Its Codex seats (S6's second judge, S7b and S9b)
move to `gpt-6.2-sol`, and each seat's context window is read from the catalogue the
0.171.0 binary carries. Two things a Codex call shows about itself have not been
observed on 0.171.0: the trace shape its capture reads, and the built-in skills the
host loads. The first Codex call of a run is that observation, and a capture that
differs is refused by name. The Codex host allowance is not measured on 0.171.0
either; only the stage that reads session windows (S3, a Claude seat) needs one, so
it holds no Codex stage back. The checkout's re-pin runbook lists these measurements
and the others a model change requires. Running the driver still requires an
agent-bios checkout.

## Upgrading

```bash
npm i -g agent-bios@0.20.1
agent-bios install
```

Install the exact version: right after a release, `@latest` can still resolve to the
previous one.

## Not established by this release

No call was made to a GPT-6.2 model for this release. The instruction-behavior
benchmark has not been re-run on the new bindings. The driver has made no Codex call on
codex-cli 0.171.0, so neither the capture's trace shape nor the host's built-in skills
are confirmed there, and its Codex host allowance is unmeasured. OpenAI's Codex documentation lists the GPT-6.2 models for
the Codex app and CLI and not for the IDE extension.
