# Choosing a visual direction for an operational interface

Use when a new visual direction or a material arrangement decision remains
unresolved in the requested work. For an established direction or a bounded copy
correction, use the existing system and verify the affected result proportionately.

## Start from the task and supported system

Identify the content people must read, compare, select, edit or act on. Preserve
the working scope, authority and state distinctions that matter to that task.
Inspect the project's existing components and tokens before introducing a new
visual vocabulary. An external reference does not itself justify replacing the
project's framework or component library.

Consult a reference when it helps resolve the remaining visual decision; reuse
sufficient existing evidence. Research more when the decision needs it or the
user requests research. Prefer task-relevant product views or official pattern
documentation. Distinguish live observations, release screenshots, historical
images and explanatory artwork. Record the source and date, what it informs,
and its applicability limits in the ordinary design note. Do not infer token
values or usability from an image alone.

## Choose only the patterns the task needs

| Task | Useful arrangement | Meaning to preserve |
| --- | --- | --- |
| Reading and review | Give the artifact sufficient space; keep necessary evidence nearby when switching would obstruct comparison | The artifact, source, applicable conditions and review target |
| Repeated record comparison | Align comparable values; distinguish whole-list, selected-set and individual-record actions | Units, comparison basis, exceptions and each action's scope |
| Selection-driven editing | Keep relevant properties bound to the selected object | Selection, draft and resulting changes remain attached to the same target |
| Input and result confirmation | Keep input, consequential effects and results close enough to follow | Entered, saved, approved and actually executed states stay distinct |

These are conditional patterns, not a required navigation structure or panel
count. Choose persistent supporting panels or transient overlays according to
their role. Give prose a readable measure and comparisons sufficient width.
Adapt the arrangement to the supported viewport while preserving the current
selection, return context, reading order and keyboard focus order. Compact
navigation when needed to keep the main task reachable on a narrow screen.

## Define roles before values

Explain the proposed reading order, emphasis, density and grouping briefly.
Map foregrounds, surfaces, action states, spacing relationships and any required
depth to the existing semantic tokens. Keep focus, selection, feedback and
disabled states distinct even when values initially coincide. Add a pattern
token only when it represents an independent decision. The role of a token
must survive theme changes; check its actual foreground/background pairing.

For information-dense operational work, start with typography, alignment and
spacing to organize content; add containers, color or elevation when they
communicate a needed relationship or interaction. Large introductory areas,
repeated summary cards, badges and icon backgrounds need a task or brand purpose.
Ordinary content need not look raised. Use depth when it clarifies a floating,
movable or otherwise distinct object. Preserve useful brand and user preferences.

Do not impose a reference palette, fixed pixel scale, permanently dim navigation,
universal card ban or identical layout across tasks. When no system exists, mark
initial values as project proposals. Define consistent text roles and spacing
within and between groups, then check the resulting density. Resolve crowded
content through grouping, widths and wrapping before shrinking text. Keep words
and meaningful phrases together where the language permits, with a fallback for
unbroken strings. Check representative Korean text when the product uses Korean.

## Compare only enough to resolve the decision

Use representative content, long labels, important exceptions and relevant
states at the target sizes. Keep task, content and capability constant while
comparing visual alternatives; use a credible baseline. Distinguish token
changes from changes to regions, information order and grouping. Typography
and spacing can still alter wrapping and geometry. Where narrow layouts
converge, do not claim a difference the user cannot see.

Inspect the actual rendered result when appearance is being judged. Check
contrast, clipping, wrapping, state distinctions, action targets and focus
visibility under the applicable accessibility requirements. Verify that
rearrangement preserves semantic reading and keyboard order. For interactive
changes, exercise selection, draft retention and the relevant failure/recovery
paths; styling does not establish permission or execution.

Record visual preference separately from observed task performance. Rendered
samples support visual inspection; interaction and user-performance claims need
their own evidence. Preserve the result and remaining uncertainty in ordinary
team artifacts. No prescribed number of variants or new research report is
needed for every task.
