# 업무용 화면의 시각적 방향을 정하는 방법

요청받은 작업에서 새로운 시각적 방향이나 중요한 배치 결정을 내려야 할 때 사용한다.
방향이 이미 정해졌거나 범위가 좁은 문구 수정이라면 기존 체계를 사용하고,
영향을 받는 결과를 그에 맞는 수준으로 확인한다.

## 업무와 기존 체계에서 출발한다

사용자가 읽고, 비교하고, 선택하고, 편집하거나 처리할 내용을 확인한다.
그 업무에서 중요한 범위, 권한, 상태의 구별을 보존한다.
새 시각 체계를 도입하기 전에 프로젝트의 기존 컴포넌트와 토큰을 살펴본다.
외부 레퍼런스가 있다는 사실만으로 프레임워크나 컴포넌트 라이브러리를 교체하지 않는다.

남은 시각적 결정을 내리는 데 도움이 될 때 레퍼런스를 참고한다.
이미 충분한 근거가 있다면 재사용하고, 결정에 더 필요하거나 사용자가 조사를 요청할 때
추가로 조사한다. 업무가 비슷한 제품 화면이나 공식 패턴 문서를 우선한다.
실제 관찰, 출시 당시의 화면, 과거 이미지, 설명용 그림을 구별한다.
출처와 시점, 무엇을 참고했는지, 적용에 어떤 한계가 있는지를 평소 쓰는 설계 기록에 남긴다.
이미지만 보고 토큰값이나 사용성을 추정하지 않는다.

## 업무에 필요한 배치만 선택한다

| 업무 | 활용할 수 있는 배치 | 보존할 의미 |
| --- | --- | --- |
| 읽기와 검토 | 대상 내용에 충분한 공간을 주고, 화면을 오가면 비교가 어려운 근거는 가까이 둔다 | 내용, 출처, 적용 조건과 검토 대상 |
| 여러 기록의 반복 비교 | 비교할 값을 정렬하고 전체 목록·선택 항목·개별 기록의 행동을 구별한다 | 단위, 비교 기준, 예외와 행동의 적용 범위 |
| 선택한 대상의 편집 | 필요한 속성을 현재 선택한 대상에 연결한다 | 선택, 초안과 변경 결과가 같은 대상에 속함 |
| 입력과 결과 확인 | 입력, 중요한 영향과 결과를 이어서 이해할 수 있게 배치한다 | 입력됨, 저장됨, 승인됨, 실제 실행됨의 차이 |

이 표는 조건에 따라 선택할 수 있는 패턴이다. 메뉴 구성이나 패널 수를 정하는 규칙은 아니다.
계속 참조할 보조 패널과 잠시 여는 겹침 영역을 역할에 따라 고른다.
긴 글에는 읽기 편한 폭을, 비교할 정보에는 대조에 필요한 폭을 준다.
지원하는 화면 크기에 맞게 배치를 바꾸면서 현재 선택, 돌아갈 맥락, 읽기 순서와
키보드 포커스 순서를 보존한다. 좁은 화면에서 주요 작업에 도달하기 어려워지면
탐색 영역을 더 작게 구성한다.

## 값보다 역할을 먼저 정한다

제안하는 읽기 순서, 강조, 정보 밀도와 묶음을 짧게 설명한다.
글자·아이콘 등 전경 요소, 표면, 행동 상태, 간격 관계와 필요한 깊이를 기존 의미 기반 토큰에 대응시킨다.
포커스, 선택, 피드백과 비활성 상태는 처음에 같은 값을 쓰더라도 뜻을 구별한다.
패턴별 토큰은 독립적으로 결정할 필요가 있을 때 추가한다.
테마가 바뀌어도 토큰의 역할이 유지돼야 하며, 전경 요소와 배경의 실제 조합을 확인한다.

정보가 많은 업무용 화면은 글자, 정렬과 간격으로 내용을 구성하는 것부터 시작한다.
필요한 관계나 상호작용을 설명할 때 상자, 색이나 깊이를 추가한다.
큰 소개 영역, 반복되는 요약 카드, 배지와 아이콘 배경에는 업무나 브랜드상의 목적이 있어야 한다.
일반 콘텐츠가 모두 떠 있는 것처럼 보일 필요는 없다.
부유하거나 이동할 수 있는 객체 등 별도의 대상을 분명하게 표현할 때 깊이를 사용한다.
업무에 도움이 되는 브랜드 표현과 사용자 선호를 존중한다.

참고 제품의 팔레트, 고정된 픽셀 척도, 탐색 영역을 언제나 약하게 강조하는 방식, 모든 카드의 금지나
모든 업무에 같은 배치를 강제하지 않는다. 기존 체계가 없으면 초기값을 프로젝트의
제안값으로 표시한다. 일관된 글자 역할과 묶음 안팎의 간격을 정한 뒤 실제 밀도를 확인한다.
내용이 빽빽하면 글자를 줄이기 전에 묶음, 폭과 줄바꿈을 조정한다.
언어가 허용하는 범위에서 단어와 의미 있는 구절을 함께 배치하고,
공백 없는 긴 문자열도 처리할 수 있게 한다. 한글을 사용하는 제품은 실제 한글로 확인한다.

## 결정을 내리는 데 필요한 만큼 비교한다

대표 내용, 긴 이름, 중요한 예외와 관련 상태를 넣어 실제 사용할 크기에서 확인한다.
여러 시안을 비교할 때는 업무, 내용과 기능을 동일하게 유지하고 타당한 기준안을 사용한다.
토큰 변경과 영역 구성·정보 순서·묶음 구조의 변경을 구별한다.
글자와 간격을 바꾸면 줄바꿈과 기하학적 배치도 달라질 수 있다.
좁은 화면에서 배치가 같아진다면 사용자가 볼 수 없는 차이를 주장하지 않는다.

모습을 판단하는 작업이라면 실제 렌더링한 결과를 살펴본다.
해당 접근성 요구사항에 맞춰 대비, 잘림, 줄바꿈, 상태 구별, 조작 대상의 크기와
포커스가 보이는지를 확인한다. 재배치 후에도 의미에 맞는 읽기 순서와 키보드 순서가
유지되는지 확인한다. 상호작용을 바꿨다면 선택, 초안 유지와 관련된 실패·복구 경로를
실행해 확인한다. 시각적 표현만으로 권한이나 실행이 성립하지는 않는다.

시각적 선호는 관찰한 작업 성과와 따로 기록한다. 렌더링한 시안은 모습을 살펴볼 근거가 된다.
상호작용이나 사용자 성과에 관한 주장은 그에 맞는 별도 근거가 필요하다.
결과와 남은 불확실성은 팀이 평소 사용하는 문서나 작업 파일에 남긴다.
모든 작업에 정해진 개수의 시안이나 새 조사 보고서가 필요한 것은 아니다.
